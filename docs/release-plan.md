## 首版交付边界

首版交付共享记忆、通用 MCP／Skill 接入和任务交接，并形成“安装 NAS Docker 服务 → 网页配置模型与项目 → 一次性链接安装 Agent 连接 → 跨设备使用 → 备份与升级”的完整流程。默认接入不要求另装 App；新远程接入仍须单独完成目标系统和宿主验收，已有 NAS Linux amd64 与 Mac 客户端证据保留其原路径边界。其他架构或宿主在单独验证前不列为已支持。

管理页面面向没有技术基础的新用户：明确解释项目用途、模型密钥来源、一次性链接的
使用与连接步骤，并给出第一次共享的实际核对方法；旧配对文件入口保留在高级选项。技术编号和协议细节按需展开；
已登记、已接纳与已整理不能混为“连接成功”。不能只凭组件存在宣称容易上手，
须按完整用户路径操作并核对结果，见[首次网页使用](reviews/2026-11-10-browser-first-use.md)。

继续复用固定 Hy-Memory／MemHub 的数据平面、队列、模型管理、网页组件和备份原语。新增代码只补当前证据明确指出的产品缺口；涉及协议、权限、迁移或恢复语义时，先记录设计与兼容性，不通过隐式迁移或放宽保护制造成功。

四个阶段依次收口，每阶段附对应提交、自动测试、真实操作证据及已知限制。自动备份是第三阶段的明确交付项。六入口全部自动化、离线读取缓存及复杂全域恢复单列后续，不反复加入当前阶段的退出条件。

## 执行纪律

- 用户确认的最终收尾顺序：先完成产品成熟度和生产验收，再盘点并清理 MacBook、Mac mini、NAS 上属于本项目的测试数据、测试环境与测试包，保留生产环境、应用及必要的生产恢复保障。清理前以实际资源名称、用途和生产依赖核对清单；未知归属不凭名称删除。完成后才制作本地参赛包，参赛分支不推送 GitHub。
- 每个修复关联上述门槛和需求编号，先复用后补齐，保持小步可审查提交。
- 先在合成数据、独立卷和独立 Agent 配置中验证；日常配置、真实数据和外部发布按已有授权范围处理。
- 数据格式、鉴权、协议或恢复变化先记录 ADR 与兼容说明；不得自动降低旧保护或重建用户身份。
- 每步运行 `make check` 及变更所需的相关测试；不将工作流定义、组件测试或服务健康冒充完整产品验收。
- 本计划的四阶段是有限发布门槛。发现其他问题先记录是否影响当前公开承诺，不能把所有后续需求追加为本阶段前置。
