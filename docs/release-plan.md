# Cloud Memory Hub 首版发布计划

状态：2026-11-10 用户已要求按上线发布标准逐一完善，最终让其他人通过 GitHub 自行部署 NAS 并在网页配置；既有产品主页 `Memory-Hub-Website` 一并完善并重新发布 Vercel。基线为 `1279f1b`；以下均为待实现或待验收门槛，不是完成声明。当前问题和证据见[发布准备度审计](reviews/2026-11-10-release-readiness.md)。

最新进度：项目控制台、作用域问答、Anthropic 问答、普通忘记入口和召回修复已构建为 `preview-f0f3740` 并备份升级到日常 NAS；独立空卷安装、重启、真实模型问答／引用、普通忘记与两机读取通过，见[项目控制台记录](reviews/2026-11-10-project-console.md)。独立官网已重新发布并核对线上文件；页面视觉与真实点击验收仍未完成。下表保留初始差距，不以局部结果提前关闭退出门槛。

产品公开发布与自行部署是主目标。参赛准备在独立 `codex/ugreen-contest` 分支开展，不改变本计划、通用接口或主体架构，也不成为产品发布的前置门槛；成熟产品的固定版本可供参赛分支适配与打包。

## 首版交付边界

首版交付共享记忆、通用 MCP／Skill 接入和任务交接，并形成“安装 NAS 服务 → 网页配置模型与项目 → 配对客户端 → 跨设备使用 → 备份与升级”的完整流程。首版以经过实测的 NAS Linux amd64 和 Mac 客户端为支持范围；其他架构或宿主在单独验证前不列为已支持。

继续复用固定 Hy-Memory／MemHub 的数据平面、队列、模型管理、网页组件和备份原语。新增代码只补当前证据明确指出的产品缺口；涉及协议、权限、迁移或恢复语义时，先记录设计与兼容性，不通过隐式迁移或放宽保护制造成功。

四个阶段依次收口，每阶段附对应提交、自动测试、真实操作证据及已知限制。自动备份是第三阶段的明确交付项。六入口全部自动化、离线读取缓存及复杂全域恢复单列后续，不反复加入当前阶段的退出条件。

关联 FR-01、FR-03、FR-10、FR-11、FR-12；解决 RR-01、RR-02、RR-03、RR-05。前置复用调查关注现有远程读取、治理接口和上游网页，不另建第二套记忆存储。

| 门槛 | 当前状态 | 可观察的完成条件 |
| --- | --- | --- |
| R1-01 忘记停止自动召回 | 已合成复现缺陷 | 普通记忆忘记后，实际搜索和下一轮 hook 输出都不含目标内容；主动按 ID 查看原文仍可读。分页、重开进程、无关记忆保留和同长句整事件拒绝回归通过。保留旧实现失败与修复后通过的证据。 |
| R1-02 网页使用真实项目 | 后端已有，网页未接通 | 两个已授权项目有不同合成数据；网页选择项目后计数、列表、搜索、原文与来源均对应当前项目，刷新和重启保持一致。Agent 写入可见于网页，网页不能显示另一项目内容；网络／权限错误不能伪装为 0 条。 |
| R1-03 问记忆接入 Hub | 未接通 | 在已选项目询问唯一合成事实，回答依据来自该项目实际 Hub 记录，并能打开来源；空项目和无权限场景明确反馈。真实模型样例单独验收，不能只测返回文本的替身。 |
| R1-04 网页治理语义一致 | 机制已有，旧按钮路径被保护性拒绝 | 复用已有预览／确认，对当前支持的普通记录完成忘记及其结果核对；彻底删除只对已有完整证明的范围开放。不可执行类型在确认前说明原因；旧 DELETE 保护保留，不出现虚假成功。复杂旧日志执行不作为本阶段门槛。 |
| R1-05 产品身份与状态准确 | 页面仍有上游桌面占位 | 标题、服务位置、版本／构建来源使用真实 Cloud Memory Hub 信息；适当保留上游署名。不适用的桌面启动／本地存储文案得到替换或解释，已连接却展示“尚未开启”的情况消除。 |

退出条件：上述行为在隔离非空数据上通过自动回归，再在安装后的 NAS 网页和实际客户端联合核对；记录使用的镜像摘要和客户端版本。不得通过把演示数据搬入 `local` 空间绕过项目权限。

## 第二阶段：自行安装、配对、状态和后台运行

关联 FR-01、FR-02、FR-04、FR-05、FR-06、FR-07、FR-12、ENG-01；解决 RR-04、RR-06、RR-07、RR-11。复用设备身份、来源注册、授权、现有连接组件、MCP 和 Skill。

| 门槛 | 当前状态 | 可观察的完成条件 |
| --- | --- | --- |
| R2-01 NAS 首次启动与网页配置 | 容器与模型设置已有，整体流程未验证 | 使用空数据目录和文档指定部署配置启动，取得管理员入口，创建项目、填写模型、获取候选、测试并启用。错误有明确定位，密钥不回显、不进入日志；NAS 重启后数据与配置仍在。候选拉取失败时保留手填能力。 |
| R2-02 网页配对独立客户端 | 身份接口已有，网页未接通 | 用户在网页新增两台设备并按指引安装，无需维护者预先生成私有连接文件；两端身份与队列独立，同项目双向读写及交接成功。撤销一端后立即拒绝该端，另一端继续可用。已有 Agent 配置先备份并保留其他条目。 |
| R2-03 可安装 MCP／Skill 及能力说明 | 现有手工安装已验证部分宿主 | 一份版本化客户端配合明确的 MCP／Skill 指引可在干净 Mac 安装和卸载；声明宿主限制、重连要求及自动采集范围。实际 Claude CLI 与 Codex 桌面 Skill／CLI 路径分别验收，不能宣称未经验证的桌面原生 MCP 自动能力。 |
| R2-04 可理解的同步与失败状态 | 状态和队列原语已有，网页未接通 | 网页或客户端能区分待上传、已接纳、正在处理、可读取、永久拒绝和可重试失败；展示最近成功时间及安全原因。断网排队、恢复补传、重复接纳和永久拒绝后的合法后项都能观察，不能用“已上传”代替“已提炼”。 |
| R2-05 日常自动运行与升级 | 容器常驻已有，本机安装流程不完整 | 明确首版后台运行方式，退出终端／机器重启后自动补传按承诺恢复；可查看状态、停止和卸载。升级保留身份、原队列及既有配置；故意失败后可按说明恢复，不把旧数据覆盖新增事件，也不假设 Agent 热重载。 |

退出条件：不使用现有预配客户端，以文档和候选安装产物完成两端接入；记录一轮结束到另一端可用的实际时间，按 60 秒目标逐项报告。已有对话下一轮读取使用实际支持宿主验证；其他宿主维持部分支持标记。

## 第三阶段：备份恢复、发行制品与 CI

关联 FR-11、FR-13、ENG-01；解决 RR-08、RR-09、RR-10、RR-12。该阶段包含用户确认的自动定期备份，不以一段手工归档命令替代。优先复用 Core 备份与维护恢复能力，补齐 Hub 多卷和治理协调。

| 门槛 | 当前状态 | 可观察的完成条件 |
| --- | --- | --- |
| R3-01 自动定期历史备份 | 未形成产品流程 | 用户可设置备份位置、周期和保留版本；非空实例实际产生至少两个可区分版本，可查看时间、状态、大小及失败原因。服务重启后计划恢复；备份目的地与运行数据分离，不将同一故障域的副本描述成独立保障。磁盘满或中断不产生可选的假成功版本。 |
| R3-02 手动完整导出与导入 | 单库原语及手工三卷备份已有，整体流程未实现 | 完整导出覆盖当前支持的 Hub 记忆、原文、来源、项目、设备权限、配置／密钥和治理所需数据，并验证清单与格式版本；在独立空环境导入后逐项核对，配置凭证可按既定设计恢复或明确要求重新配置。含凭证的备份有明确私有保存要求，不提交 Git。 |
| R3-03 选择历史版本恢复与升级回滚 | 部分恢复／迁移机制已有，整体演练未验证 | 在隔离非空实例选择旧版本恢复，比较记录、引用、权限和必要配置；较新的忘记／删除约束仍有效。故障中断、损坏归档和不兼容版本明确拒绝且保留现场；执行前保存当前一致状态。治理依据不足时暂停自动召回，不宣称恢复成功。 |
| R3-04 可获取的版本化制品 | 未发布 | 确定项目许可证、仓库归属和可见性；一个版本 tag 对应固定 NAS 镜像与 Mac 组件／适配包，提供摘要、来源提交、第三方许可证／SBOM、发行说明和升级兼容表。新用户无需开发树或维护者私人脚本。 |
| R3-05 可复现构建与发行检查 | 质量工作流已有，远程执行未验证，发布流水线未实现 | 干净环境从固定源码、补丁及锁文件构建；新增网页、召回、安装和恢复回归进入门禁。目标提交实际通过 GitHub CI，依赖／镜像检查结果可审阅，发布产物与候选验收制品摘要对应。配置远程必需检查及最小发布权限。 |
| R3-06 安装、升级和恢复文档一致 | 已有指南包含过时描述 | 单一首版入口串联部署、网页配置、Agent 接入、状态排障、备份恢复和卸载；标明架构及入口支持矩阵，去除私人路径和配置。历史验证保留原时点，不用旧状态覆盖新指南。 |
| R3-07 产品主页与发行内容一致 | 已有独立主页，尚未完成本轮核验 | 在 `Memory-Hub-Website` 复用现有站点完善文案和入口，逐条对照已验证能力、支持客户端与已知限制；安装、GitHub、下载和说明按钮指向实际发行资源。完成构建和 Vercel 预览核对，不能提前宣称六入口完整自动化或全域恢复。 |

退出条件：完成自动版本生成、手动导出导入、选择历史版本恢复、一次升级失败恢复的实际演练，再发布可供最终验收的候选制品。备份／恢复设计需说明维护互斥、三卷一致性、治理记录优先级及新实例导入身份策略。

本阶段只验收支持范围内的受控 Hub 备份与恢复。无来源旧日志、Docker 宿主日志、任意外部副本的物理治理，以及所有派生写者的全域恢复仍是独立后续项目。遇到不能证明安全的恢复范围应拒绝并说明；这种拒绝不计为该范围恢复成功，也不以全域未完成否定已验证的有限流程。

## 第四阶段：真实全新安装与发布验收

关联 FR-01、FR-02、FR-04、FR-05、FR-10、FR-11、FR-12、FR-13、ENG-01。只使用第三阶段产生的候选发行制品，不在验收中临时补私有脚本或直改数据库。

| 门槛 | 可观察的完成条件 |
| --- | --- |
| R4-01 全新 NAS 与浏览器 | 在独立 NAS 目录／卷安装候选版本；从未登录浏览器完成首次配置、项目创建和模型测试。重启后网页显示正确版本和实际数据；安装步骤无需原开发环境。 |
| R4-02 两台干净客户端 | 在独立配置中完成配对、MCP／Skill 安装、双向写读及完整 handoff；使用承诺支持的实际宿主完成下一轮读取。记录原有配置保持、真实时效和限制。 |
| R4-03 用户可见闭环 | 网页与 Agent 对同一项目数据一致；来源能打开；忘记后自动召回不含目标原文；主动查看仍遵循规则；故障与永久拒绝可解释且不阻塞合法后项。 |
| R4-04 可恢复运行 | 观察自动备份版本，手动导出并在另一隔离实例导入；选择旧版本恢复后验证较新治理规则有效；按公开说明完成升级与失败恢复，不丢已确认数据。 |
| R4-05 发行证据与公开入口 | 记录源码 tag、镜像／包摘要、平台、模型、支持入口、步骤、失败和复测结果；远程 CI 与候选验收对应。准备好的 GitHub 发布页、安装文档和已知限制可供审阅；按用户授权范围完成最终发布。 |
| R4-06 产品主页线上验收 | 按已授权范围重新发布 Vercel，在实际线上 URL 核验首屏、窄屏布局及主要按钮；从主页进入真实 GitHub／安装／下载文档并走通首版入口。记录部署版本、URL、点击后的实际页面和失败复测，保留原部署回退途径。 |

首版通过要求：R1 至 R4 的限定门槛逐项有证据，未执行项不能算通过；对公开承诺的能力不能只靠模拟代替真机。若验收发现缺陷，修改后只重跑受影响检查及必要集成，不重新扩大整个项目范围。

## 执行纪律

- 每个修复关联上述门槛和需求编号，先复用后补齐，保持小步可审查提交。
- 先在合成数据、独立卷和独立 Agent 配置中验证；日常配置、真实数据和外部发布按已有授权范围处理。
- 数据格式、鉴权、协议或恢复变化先记录 ADR 与兼容说明；不得自动降低旧保护或重建用户身份。
- 每步运行 `make check` 及变更所需的相关测试；不将工作流定义、组件测试或服务健康冒充完整产品验收。
- 本计划的四阶段是有限发布门槛。发现其他问题先记录是否影响当前公开承诺，不能把所有后续需求追加为本阶段前置。
