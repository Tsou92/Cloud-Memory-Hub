# 架构草案

状态：依据需求和上游阅读形成的首选方案，尚未完成技术验证或最终架构评审。复用原则已确认，具体扩展方式仍须通过 G1 验证。

2026-10-22：已采用 [ADR-0003](../adr/0003-sdk-authority-baseline.md) 的 SDK 权威存储基线。当前记忆及原文归 SDK，Core 保留管理配置、授权与队列；旧治理／session 镜像表已移除。以下目标中的历史、忘记、删除与同步仍由 Hub 扩展补齐，不假定旧表仍存在。

## 1. 方案选择

| 方案 | 价值 | 代价／结论 |
| --- | --- | --- |
| 扩展 MemHub，分离 NAS 中心与 Mac 连接组件 | 可复用记忆、证据、队列、治理、界面、安装器及测试 | 首选；需要梳理本地运行时耦合和远程信任边界 |
| 只依赖 Hy-Memory SDK，自建服务与客户端 | 自由度较高 | 会重写大量已有能力；仅在 G1 证明相关模块无法复用时局部采用 |
| 从零实现整套记忆系统 | 不受上游结构限制 | 与用户复用要求不符，排除 |

当前不新增微服务集群、独立消息中间件或数据库替换。大型项目的开发规范不意味着扩大部署复杂度。优先保持 MemHub Core 的模块边界和单写入者模型，再以测量决定是否需要拆分。

Core 的 SQLite 和派生存储位于 NAS 本机挂载的数据卷，跨设备只通过接口操作。禁止把活动数据库放在两台 Mac 共用的 SMB/NFS 路径：[SQLite WAL 官方限制](https://www.sqlite.org/wal.html)要求相关进程在同一主机，网络文件系统不是同步协议。

## 3. 复用与新增边界

- **Core／SDK**：复用原文、记忆、检索、模型适配和持久任务流程。远程接入层调用受控服务入口，不绕过权限直接写数据库；Hub 历史及抑制记录引用 SDK 稳定 ID。
- **Mac 连接组件**：复用来源读取器、宿主安装器和召回协议；补足设备身份、本地过滤、离线缓存与重放。优先验证能否在现有 Host Bridge 内扩展。
- **通用接口**：围绕现有合同提供版本化写入、检索、来源追溯、变更读取和治理操作。HTTP 作为传输基础，MCP 用于 Agent 工具接入，宿主插件／hooks 用于自动化。具体端点和字段经合同评审后固定，不在草案中假定已经实现。
- **能力声明**：每个适配器报告历史读取、增量采集、按需检索、下一轮自动注入、多模态、删除传播等能力及验证版本。新增 Agent 不改核心业务模型。
- **网页与恢复**：优先复用已有页面、组件及 managed_restore；增加设备状态、同步问题、备份调度和防复活检查。

## 4. 同步、一致性与项目身份

候选事件身份由设备、来源、稳定源记录 ID 和修订组成；不只按正文哈希去重，避免把不同出处误合并。重试采用至少一次投递和服务器幂等处理；事务提交后才确认游标。设备时间只是来源信息，不作为全局排序或纠错的唯一依据。

中心负责共享发布顺序，客户端保存已确认游标和缓存版本。崩溃、确认包丢失和重复投递均应可重放。历史导入和实时任务的调度需要实验，不能让首次导入屏障无限阻挡新内容。

同一项目在两台 Mac 上使用稳定项目 ID，并显式映射本地路径。路径、仓库名或远程地址只能作为匹配候选，不能未经验证就合并。未确定来源先进入待归属状态，避免跨项目污染。

## 5. 隐私、授权与外部模型

本地过滤必须先于出站队列和所有 Hub 外部请求；缓存、日志、重试、附件和解析器同样纳入覆盖。图片／PDF 的隐私检查先在本地完成，不能先上传外部 OCR 后再去除凭证。无法判断安全性的文件保留本地隔离状态并说明原因。

具体过滤实现仍需评估，不用仓库源码凭证扫描器替代运行时文本及多模态保护。模型连接凭证是系统配置，不进入内容记忆、日志或模型提示词。

设备凭证可撤销、具备最小权限；所有来源和项目授权由服务端校验，不能相信客户端自报的 scope。NAS 回环信任假设不能沿用到远程网络。HTTPS／私网连接、会话和令牌方案在网络验证后确定。

历史对话、附件和检索结果都作为不可信资料。记忆不得授予工具权限、变更系统规则或自行触发删除。Agent 的治理操作仍需验证调用者身份与用户意图。

## 6. 忘记、删除与恢复

复用 SDK 修改／物理删除入口，增加 Hub 历史、跨设备的抑制／删除记录和传播确认：

- 忘记保留受控原始证据供用户主动查看，阻止自动召回与重新提炼。
- 彻底删除清理 Hub 的相关证据、提炼结果、索引、缓存及受控备份中的可恢复副本；删除记录只保留必要标识，不保留被删正文。
- 离线客户端重连后先协调删除状态再发布旧队列；撤销或长期离线设备的状态在管理界面可见。物理断网设备不能被宣称已即时清除。
- 恢复旧快照前保存最新删除状态并重新应用，重建派生索引后才开放召回；导入也要服从同一规则。

尚需解决的关键问题是删除记录本身的灾难恢复：如果只剩旧备份且所有后续删除记录均丢失，系统无法推断后来发生的删除。候选策略是在恢复后保持召回关闭，直到从存活设备或受保护记录完成核对。不能默默使用旧快照恢复服务并宣称已满足防复活要求；G1/G2 必须证明策略可执行。

受控备份的清理方式、删除完成时机、备份周期及数量需在恢复设计中具体化。用户自行导出的副本和原 Agent 文件不自动修改。

## 7. 失败行为与可观测性

| 情况 | 预期行为 | 验证重点 |
| --- | --- | --- |
| NAS／网络不可用 | 使用缓存，新增内容本地排队，显示待同步 | 恢复后重放、无丢失、无重复 |
| 模型超时、限流或无效响应 | 可重试任务与错误状态，保留证据，不发布半成品 | 重试预算、来源核验、费用重复 |
| 进程在提交与确认之间崩溃 | 重投同一事件、返回一致结果 | 事务与幂等键 |
| 存储满／备份失败 | 明确失败，不提前确认或覆盖唯一有效副本 | 空间预检、临时文件及原子切换 |
| 过滤或附件解析失败 | 本地隔离、不给外部模型或 NAS 原文 | 错误日志也不泄露正文 |
| 宿主更新导致 hooks 失效 | 能力降级可见、可修复／撤销 | 不静默覆盖用户配置 |
| 删除后重放或恢复 | 拒绝旧内容重新生效 | 游标、删除记录和索引一致 |

观测量至少包括队列积压／年龄、同步水位、过滤隔离、模型用量、采集到发布耗时、召回注入版本和设备状态；使用关联 ID，不在诊断日志中复制原始内容。

## 8. 性能与交付

1 分钟目标从源会话本轮完成计时，衡量到他端可检索及其下一轮能注入；分别记录过滤、传输、排队、模型提炼和发布耗时。对大附件、历史导入并发、NAS 资源和跨城网络单独测量，不能把“原文已上传”当作达标。

目标制品为 NAS Docker 镜像和 Mac 连接组件。复用上游运行时构建链，增加镜像与客户端包的版本兼容检查、健康检查、迁移前备份及回滚演练。发布管线、SBOM、制品校验和安装文档都属于交付范围；当前尚无产品制品。
