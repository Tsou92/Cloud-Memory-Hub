# 模型列表与连接测试修复

关联 FR-01、FR-02、FR-07、FR-14、ENG-01。设计见 [ADR-0053](../adr/0053-model-catalog-and-probe-budget.md)。

## 真实故障与修复

用户保存密钥后，配置页面提示测试失败，同时把未通过的能力标识显示成地址不可达、模型不存在。NAS 合成请求确认生成接口 HTTP 200，但旧探针 64 token 用完后返回空正文和 `max_tokens`；同一服务、同一模型改用 512 token 及明确的纯 JSON 提示后返回完整 `memory_probe=true`。这证明该次失败属于探针预算及提示问题，不能归因为用户配置错误。

另一次只读请求确认模型列表使用标准 Anthropic 认证返回 401，同一 URL 使用 Bearer 返回 45 个候选，包含用户选定模型。名单仅供选择，不表示所有候选都兼容当前生成协议。未发送历史对话，未把任何真实密钥或服务私有配置写入源码。

修复继续复用上游表单和模型管理流程，增加有界的独立模型列表接口，保留手填并根据实际测试阶段显示错误。列表不保存配置、不激活、不调用生成、不导入历史；生成始终遵循所选协议。

- 新增预算回归在旧实现下失败，修复后整组模型探测测试 50 项通过；仍拒绝截断、不完整或无效响应。
- 模型列表新增 57 项用例，与既有模型配置 API、探针操作回归共 87 项通过。
- 独立审查通过三种非法请求的实际 ASGI 调用确认 422 不回显合成密钥，也不派发外部请求。
- 后端格式、静态检查、差异及测试索引检查通过。
- 网页 4 个相关测试文件共 71 项通过；Node 24 下 TypeScript 与 Vite 生产构建通过。覆盖候选选择、手填保留、失焦自动获取、输入变化丢弃迟到响应，以及错误阶段映射。
- 独立审查未发现阻断问题。主仓库 `make check` 通过，含 20 项工程测试；公开合成凭证及错误码字面量使用逐行扫描注释，未扩大扫描器排除规则。

## NAS 更新与真实验证

提交 `31737ba` 构建 Linux amd64 镜像 `cloud-memory-hub:mvp-31737ba`，NAS 安装摘要 `sha256:c953be880a681b22bd1dd155df53002202cac0c5b320b3274eec1ab59b8541e7`。固定上游与全部 25 个补丁在构建中重新应用，生产网页构建及资产验证通过。安装镜像禁网探针通过真实本地向量编码、合成 Messages 调用和加密凭证重新打开。

NAS 升级前停止 MVP 容器，备份 data/config/governance 三份归档及部署配置，摘要记录位于 NAS 私有备份目录；旧镜像 `mvp-424a6e0` 保留。更新后健康；旧验证实例未修改。使用用户最新保存的配置，通过实际管理 API 获取 45 个模型候选，包含其已选模型；实际 Messages 探测完成，生成阶段约 1.8 秒，本地向量阶段通过。随后按既有设置流程激活该配置，回读确认只有一个活动模型。

HTTP 获取实际页面和其 JavaScript 资产确认新列表入口已部署。网页交互由上述本地组件测试覆盖，本轮没有把真实 NAS 浏览器截图或完整手工交互宣称为已验证。

本步证明模型列表、真实连接和配置启用；尚不单凭这些结果宣称记忆提炼、两机较早记忆命中已通过。模型激活可恢复之前已授权采集的等待任务，未另行导入 Agent 历史。
