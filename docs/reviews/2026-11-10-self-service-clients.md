# 自助配对与 Mac 客户端发布验证

关联 FR-01、FR-02、FR-03、FR-06、FR-07、FR-12、ENG-01，以及 R2-01 至 R2-05、R3-04。设计见 [ADR-0060](../adr/0060-self-service-pairing.md)，用户入口见 [Mac 自助接入](../client-installation.md)。本轮属于产品发布主线；参赛工作仍在独立分支。

## 已实现的边界

- 网页使用现有项目、设备、授权、来源、轮换和撤销 API；不增加身份数据库或新的凭证协议。下载文件仅绑定一个设备、项目及来源。
- `cloud-memory-setup` 校验下载文件，实际检查会话与来源权限后创建私有配置和队列。相同绑定重复导入保留队列，其他绑定显式拒绝；不修改用户正在使用的 Agent 配置。
- MCP 配置可输出通用 JSON 或 Codex TOML，只含已安装命令与私有配置路径。
- Mac 后台服务复用 connector watch，提供安装、启动、状态、停止及卸载；负责已入队事件补传，不代表历史自动采集或离线读取。暂时失败由现有退避处理，永久错误停止；没有无限重启策略。
- 安装包从固定源码生成三个非 editable 业务 wheel，携带公共 Skill、哈希锁与来源声明。源码发行依赖在构建阶段预构建，安装端只下载锁定 wheel；需要本机 Python 3.12 和网络。上游完整 Python 依赖暂保留，不另写过滤、解析或队列。

## 首轮新安装客户端与 NAS 实际联调

最终包的本机安装客户端通过 9 项实际检查：MCP 初始化与七工具、记忆立即读取、同请求幂等、同连接读取后续更新、8,219 字节完整交接、合成断网持久入队、真实 LaunchAgent 补传、已安装 MCP 读回、停止／卸载后保留配置及队列。最终真实远程检查仍为 authorized。单 Mac 写入到 recent 约 209 毫秒，完整交接读取 2.924 秒；不将这两个数字当作两台 Mac 或模型自主调用的时效证明。

首次后台验收未通过：自定义运行时位于 Desktop，macOS 内核 System Policy 明确拒绝后台 bash 读取该 launcher，服务退出码为 126。远程权限正常，队列保持 3 accepted／1 queued；只停止本次合成服务并保留现场。随后重新校验同一最终压缩包，在正式默认的 Application Support 目录全新安装，先卸载旧合成服务注册，再用新运行时绑定原配置及原队列，未调整系统保护。

重试使同一个既存事件在 7.734 秒内由 queued 转为 accepted，总数变为 4 accepted／0 queued；已安装 MCP 在约 119.7 毫秒内读回该事件。服务停止并卸载后，配对配置和凭证文件摘要不变，outbox 保留。本轮断网入队由 MockTransport 模拟 ConnectError，后续投递与读取使用真实 HTTPS NAS；没有声称真实物理断网或两个宿主模型自主调用。后台新登录／整机重启尚未执行。

验收脚本首次另有两项前置假设错误：误要求默认配置也位于测试目录、误把 ConnectError 固定码当作 HTTP 503 固定码。修正脚本后复用原配置和已入队事件，没有重建身份或重写一条新事件掩盖失败。

## preview.4 原 Python 入口与真实双机验收

早先 Mac mini 在传入独立合成配对文件后离线，按约定等待北京时间 14:00 后才连接。恢复连接后，preview.3 首次安装实际失败：Python 3.12.9 的 shim／符号链接入口使新虚拟环境记录了错误的基础解释器目录，随后出现 `ModuleNotFoundError: No module named encodings`。同一 Python 的真实路径在另一个新目录可建立并运行虚拟环境；该绕行只作为根因诊断，不计为默认安装通过。失败日志、原配对和队列均保留。

安装器现先保留 Python 3.12 与架构检查，再严格解析当前进程的基础解释器，确认其为已存在且可执行的文件后创建虚拟环境；不从 PATH 回退到其他 Python。对应安装器 14 项回归通过，修复时 `make check` 的 62 项工程测试及格式、lint、仓库与凭证检查通过。

重新构建的 `0.1.0-preview.4-arm64` 包来自干净源码 `c8720372ae3d8deb8ac674216494500da3720239`，清单中 `hub_worktree_dirty=false`。归档为 22,718,659 字节，SHA-256 为 `c02d2363a87de38de6a8a3caeafd5dfd2d98d7e4f3668ab6c4c7e7cd9c55fda5`；清单 SHA-256 为 `f901fbc37441fc15a50a937375aaada9b04c23fcc34c3c1772b4c08bfaae25bc`。两台 Apple Silicon Mac 均在新的默认运行目录实际安装；Mini 使用原 shim 调用包内安装器，成功建立基础目录正确的新虚拟环境并导入原合成配对，没有复用 preview.3 的失败目录或复制旧虚拟环境。

## 仍待验证的边界

上述双机结果验证已安装客户端经 MCP 调用的原文与交接能力，不代表 Agent 模型自主调用、模型提炼、历史自动采集、真实物理断网或用户注销／整机重启。当前实际安装架构为 macOS arm64，不据此宣称 Intel Mac 或其他操作系统通过。新的客户端配对复用了本任务既有合成文件；首次网页登录与下载配对的完整用户流程仍需另验。

固定上游第 29 项补丁 `0031-hub-self-service-pairing.patch` 已通过摘要与重放核验；Hub 管理网页登录后的视觉与真实点击验收仍未由本记录完成。自动版本备份及 NAS 正常／中断恢复已有独立证据，见[备份与恢复](../backup-and-recovery.md#nas-恢复演练记录)。正式 GitHub 发行和其余门槛继续按[发布计划](../release-plan.md)核对，不以本轮客户端结果宣称整体发布完成。
