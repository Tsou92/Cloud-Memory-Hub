# 治理身份绑定与运行时隔离验证

日期：2026-10-25。需求：FR-06、FR-09、FR-10、FR-11、FR-13、ENG-01。状态：运行时接线已完成本地回归，镜像和 NAS 验证待执行；不是产品治理或完整同步验收。

## 复用与实现

复用固定 MemHub Core、来源授权回调、持久队列和已有独立治理记录。新增权威绑定只保存 ledger_id 与签名水位；正文和原始记录仍属于 SDK。设计、迁移及回滚边界见 [ADR-0011](../adr/0011-governance-authority-and-offline-sync.md)。

身份库版本 1 显式升级至 2，保留设备及授权；普通启动不创建缺失身份／治理库。独立治理卷不能嵌入业务或配置目录。Core 构造、lifespan、所有 HTTP 请求与响应输出均检查治理状态，来源授权回调在故障时拒绝后台新提炼。直接 SDK 删除入口返回明确 409，不能绕过新的治理合同。

- 真实子进程在意图提交后、外部水位提交前 `os._exit(23)`：重开时原意图保留，水位恢复为 1，实例保持待执行隔离。不是主机断电或物理删除测试。
- 真实 Core 处理过程中产生意图：准备好的旧响应不发布，返回 503。单独 ASGI 流式边界测试证明已发送片段保留，后续片段停止；不声称所有上游 SSE 都有同样的缓冲行为。
- 上游隔离执行器运行来源授权／开关和写入租约三个原始测试文件：22 项通过。首次直接 pytest 被隔离门禁拒绝，改用原版 `run-tests-isolated.sh` 后通过，没有移除隔离要求。
- 实际 Claude CLI 2.1.308，隔离配置、同进程四轮、真实 SDK 和 HTTP：更新记忆、撤销、断网、合成来源自动采集投递继续通过。模型仍为本地替身，记忆由 SDK 夹具导入；不能算真实模型提炼、两机网络或一分钟 SLA。

镜像探针 `scripts/probe_governance_runtime.py` 已编写：只使用随机命名的临时 Docker 卷／容器，目标是验证旧镜像启动、显式迁移、设备身份保留、旧镜像拒绝新库、缺失记录及恢复可信副本、待执行意图隔离。未执行前不计入通过。
