[ADR-0064](../adr/0064-source-root-generation.md)。继续复用固定 Core 授权与来源连接流程。

## 已复现的问题

提交 `ad8d661` 的[真实 GitHub CI](https://github.com/Tsou92/Cloud-Memory-Hub/actions/runs/42768563998)
中，两项 quality 成功，Hub 2,162 项通过、6 项跳过；Core 为 5,189 通过、2 失败、
18 跳过、12 未选、2 预期失败。失败均来自授权后删除并重建目录：Linux 复用 inode，
`root:v2` 未区分新目录，状态错误为 OK，实际 `authorized_root` 也未拒绝。
原两个失败用例保持原样。

在 NAS Linux 6.18.15／x86_64 的全新 ext4 实验卷，用已安装 ad8d661 Core 和原测试
重现相同两个失败。另在本机 Linux／arm64 与 NAS 各连续创建目录 10,000 次，inode
分别复用 9,999／9,998 次，创建时间均不同；不据此宣称所有文件系统时间戳唯一。

## 修复与兼容

补丁 0034 为根目录身份加入创建时间，Linux 从已打开描述符读取并检查 statx 返回字段；
缺字段拒绝。正常子文件活动不改变根身份；macOS 仍不依赖重启可能变化的设备号。
旧 v2 授权不自动转换；自选目录需通过现有确认入口明确批准当前 v3 身份。
本地历史采集的旧绑定保持拒绝和原状态，不自动删库、重绑或扫描真实历史。

独立审查另外复现了授权对象与路径检查之间的目录切换：实际可读到替换目录正文。
三个授权入口已绑定对象与保存／确认的身份，保留路径复核；不能只比较两次路径。
补充四个真实目录切换回归，检查拒绝和原授权、候选、游标及任务不变。
