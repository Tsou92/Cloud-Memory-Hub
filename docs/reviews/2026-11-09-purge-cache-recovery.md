# 彻底删除缓存恢复验证

日期：2026-11-09。关联 FR-10、FR-11；设计和兼容约束见 [ADR-0035](../adr/0035-purge-cache-recovery.md)。在用户新增 ADR-0034 及测试（至 d3d3125）之后继续开发，保留其 8 个预期失败，不把未实现项算作通过。

## 故障与变更

原中断续做测试只扫描被删事实文本；增加真实 SDK get_write_outcome 断言后失败：Hub 回执已清除，续做已显示完成，但结果缓存仍存在。清理现在从 Core 持久 job_id/idempotency_key 恢复请求身份，校验项目、设备、来源与尚存原文；依据缺失或矛盾时拒绝清理。未新增存储，也未修改上游补丁和锁文件。

删除输入快照时，其所属请求的结果缓存也清除；范围外原文和原始轮次仍保留，依赖该历史的事实按确认范围删除。清理缓存先于移除回执。启动重放检查缓存、修订历史和 Chroma 写前队列，因此只恢复旧缓存也会重新清理。

额外实测并修复：已完成任务的正文尚未后台清理时仍在 Core 队列库，现于 VACUUM 前复用上游终态正文清理；Core 后台维护和 Hub 启动可能同时调用 resume，现通过异步锁串行，避免争抢独占区导致启动失败。两项都没有取消或判定非终态任务，ADR-0034 的在途缺口仍待实现。

## 验证

- 治理与缓存恢复专项：37 通过、8 个 ADR-0034 已知缺口预期失败。新文件 test_purge_recovery.py 覆盖旧清理顺序中断、清除回执后中断、仅恢复旧缓存、后续输入副本清理、无关原文/原始轮次保留、缺失/跨域请求依据拒绝、并发 resume 单次重放。
- Hub 全量：672 通过、5 项可选后端跳过、8 预期失败、269 条上游弃用警告。预期失败与跳过均不计通过。
- 上游真实隔离运行器：来源授权/持久队列 199 通过；原生 SDK 写入结果与预处理缓存 8 通过（测试工具 pytest-asyncio 1.4.0，未改生产依赖）。
- 跨进程治理探针通过：忘记、彻底删除、重启、完整业务数据恢复、仅结果缓存恢复、来源重导入拒绝；同时查询 SDK 结果确认目标行清除、忘记结果保留。真实 Core/SDK/数据库/HTTP，只有提炼输出是合成替身。
- make check 通过：格式、静态检查、19 项工程门禁、文档链接、敏感内容扫描和差异检查。
- Linux amd64 安装制品在本地和 NAS 均通过跨进程治理探针与完整容器检查；探针含仅恢复旧结果缓存及来源重导入拒绝。真实数据库/SDK/HTTP，提炼器为合成替身，无真实历史或收费模型。

## 审查与限制

顺序自审及独立代码审查均已完成。检查 SQL 参数、队列与来源身份交叉校验、锁顺序、回执移除前后的幂等、恢复后的副表查询和正文清理范围，未发现本次新增阻断问题。仅保留 Core 既有终态正文清理语义。独立审查建议补充仅恢复 history、仅恢复 Chroma 队列的独立回归；这些分支目前主要依据代码核查，不能等同于仅缓存恢复的集成实测。

Core job_id/idempotency_key 是恢复依据，尚未设计可删除这组身份的队列归档；不能擅自清理这些行。只恢复旧队列（尤其非终态请求）的协调仍属 ADR-0034；本轮未证明任意混搭快照可安全恢复。HNSW 已接受限制、生产力记录物理删除、操作 UUID 请求冲突、离线规则传播和产品全量交付仍未完成。
