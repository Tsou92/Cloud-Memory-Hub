# SDK 共享准入验证

关联 FR-10、FR-11、FR-13、ENG-01；方案、复用证据和测试路径见 [ADR-0014](../adr/0014-shared-sdk-admission.md)。本步是内部 SDK 操作屏障，不开放用户维护或删除入口，不表示已排空整个队列。

## 实现与自审

固定上游的 patch 0006 为 Core 和 bridge 注入可选异步上下文工厂，覆盖管理读取与 supervisor 的读写工厂；prepare 初始化也进入已有 exclusive_access。保留上游单 bridge 重入、局部锁和取消后等待实际线程的实现。Hub 按实例建立一个 SdkAdmission，无新增数据库或 HTTP schema。

自审覆盖锁顺序、同 Task 重入、子 Task 不继承独占权、等待局部锁的计数、重复取消、跨循环错误、异常释放及无注入兼容性。正常不同 bridge 操作仍可并发，独占等待不主动取消 SDK；取消独占等待后恢复普通准入。所有诊断为固定错误码，不保存正文或凭证。本次是开发者自审，没有独立同行审查。

## 已执行证据

- 新增 15 项测试全部通过。包括普通并发、在途重入、自身升级和并发独占拒绝、独占取消／异常恢复、跨循环拒绝、实际 bridge 读取线程与初始化线程被重复取消后的等待，以及等待局部锁的任务取消。
- 实际 Core lifespan 验证管理 bridge、处理 bridge 和 supervisor 读取 bridge 共用同一实例准入；使用真实 SDK 写入合成记忆，在独占前后读取成功。独占期间外来 HTTP 请求返回固定 503，响应没有记忆正文；独占主体可通过同 Task 检查记录。
- 保留原上游 runner，执行 `test_hy_memory_bridge.py`、`test_memory_processing.py`、`test_sdk_memory_qa.py`：162 项通过，1 项上游已标记预期失败，分类完整。该预期失败涉及 D-16「被替代证据不会撤回其记忆」，不计作通过，也不能据此宣称治理已完成。
- `make check-runtime`：255 项通过；`make check` 的格式、静态检查、19 项工程门禁、文档路径、源码凭证扫描及差异检查通过。新增上游补丁的两份 Python 源码也通过上游配置的静态检查。
- 安装镜像及 NAS 新补丁验证另行记录。此前 NAS 常驻的 `963d276` 不包含本补丁。

所有测试使用合成内容，没有启用外部生成模型或改动日常客户端配置。

## 尚需接通

在 SDK 操作准入之外，还需暂停接纳和队列领取、等待整项处理、核对未知写入结果、重新规划范围、持久执行计划、选择性抑制与物理清理。当前屏障是可组合的底层组件，不是安全删除的充分条件；直接底层 SDK 调用和内部构造器不识别进程租约的限制仍按 ADR 处理。
