# 工作／编程记忆统一读取验证

关联 FR-02、FR-03、FR-07、FR-12、ENG-01；设计见 [ADR-0016](../adr/0016-productivity-read-adapter.md)。此记录为实现者自审，不是独立同行审查。

## 实现与复用

新增薄适配器，复用固定 SDK 的路径／集合命名、SQLite 解码、经验向量去重及事实词面重排。普通读取继续使用 Core bridge，两变体的经验和事实进入同一个设备授权合同，不新增索引、数据库或运行依赖，不改上游源码与原生回执 ID。

SQLite 以只读连接访问；Chroma 仅获取已有集合。项目授权前后复核、全文脱敏后分块、共享 SDK 准入及取消后等待实际 worker 结束继续生效。事实与原文的引用类型保持区分；没有可验证的原文关系时不伪造引用。

## 本地证据

- 原有读取测试 14 项通过；新增适配测试 14 项通过。真实 Core、SQLite、Chroma 和本地 embedding，全部为合成记录，无生成模型调用。
- 覆盖普通／两变体／两类记录相同原生 ID、分页跨段及越界、全局和项目隔离、superseded／删除后索引残留、错误命名空间索引、正文分块脱敏、查询期间权限版本变化、保留前缀冲突、缺库不创建、坏库／坏 schema／坏 JSON／缺集合、重启、取消与维护准入。
- 2026-10-28 最终完整运行时回归 307 项通过；39 条提示来自固定上游的 utcnow 弃用，不是跳过项。`make check` 的格式、静态检查、19 项工程门禁测试、路径／链接、源码凭证扫描及 Git 空白检查通过。
- 上游 `tests/coding/test_store.py`、`test_search_scope_filter.py`、`test_fact_lexical.py`、`test_scene_coding_variant.py` 共 139 项通过。使用原有合成 embedding fixture；不是模型质量验证。仅临时加入 pytest-asyncio 1.4.0，未改产品依赖；限制 conftest 范围，未加载上游根目录的 .env 读取钩子。
- 独立进程 seed → read 探针通过，读取进程实际调用设备 list/search/get，验证五类记录及分页；禁止 productivity writer 初始化。探针为 `make probe-productivity-read`，不以同进程缓存代替重启证据。

首次新增测试发现适配错误：误把 `embed_with_meta` 的 tuple 当成对象；已按固定 SDK 返回合同修复。另修正测试中遗漏集合维度后缀的问题。自审修正生产时间字段为上游一致的 Unix 秒，并让聚合普通候选展开后再与 productivity 交替，防止首个聚合占满结果。
