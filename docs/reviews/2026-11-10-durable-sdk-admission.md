# 持久 SDK 准入与出生身份验证

日期：2026-11-09 至 2026-11-10。关联 FR-10、FR-11、ENG-01；设计见 [ADR-0038](../adr/0038-durable-sdk-admission.md)。本项是治理在途清扫的基础，不能据此关闭 ADR-0034 的 G-A/G-C。

## 本轮实现

新 HTTP 事件经原权限、过滤和抑制检查后，获得服务器分配的稳定 `cmh2` 执行身份。独立准入日志保存 ENROLLED → MAY_INVOKE 两步签名链，配置卷保存外部见证，主治理卷绑定日志身份。实际 SDK 调用必须在原互斥锁内先提交一次性许可，再进入 `add` 或 `add_extracted`。相同事件重试复用出生身份；输入或身份不一致、重复许可、已签名删除规则命中均拒绝。

复用 Core 的输入转换、队列、SDK bridge 和状态机；补丁 0019 增加可选调用前门，0020 增加受信协调器可用的精确比较取消及单任务终态清理。后者尚未接入 Hub execute/resume；候选清单也仍是观察接口。旧任务不能补造出生证明，已有治理操作的项目保守拒绝旧格式 SDK 生成，其他项目不因此一并封锁。

主治理日志显式升级到版本 2，身份库到版本 3；沿用停服迁移命令。部分提交可按完整签名证据向前恢复；缺失绑定或文件不可被初始化为空。保留历史目标和 Checkpoint，不重签旧删除意图。准入日志不保存正文或来源／会话／记录 ID 明文，来源由事件、实际调用和来源规则的 HMAC 绑定。

## 发现与修复

- 全量回归发现 `input_context` 与 `reconcile_graph` 重建请求仍使用旧身份，分别造成自引用漏拒绝和画像产出来源不符。改为验证权威回执并保留完整出生身份；旧／新混合历史、另一个 birth 和画像重启关系均有回归。
- 同一事件不同 birth 的冻结输入不能仅凭自洽回建就充当另一份回执。原文恢复及候选观察增加队列／回执／正文请求 ID 完全一致检查。
- 独立审查发现明文 `source_id` 没有读取方且违反原隐私合同，已移除。换来源仍发生事件冲突；登记和许可两个阶段的落盘检查都不含来源、会话和记录 UUID。
- 删除主日志能力绑定并恢复旧配置时，原迁移路径可能重新建空准入日志。新增主 v2 绑定必存在要求；实际隔离负例固定拒绝且不创建替代文件。
- 许可日志领先见证时可修复见证，但重复请求仍拒绝；不把幂等追加返回当作第二次许可。

## 实际验证范围

新存储测试使用真实 SQLite 和合成输入，覆盖稳定登记、两种操作、输入与事件冲突、并发恰好一次、登记／许可提交中断、见证倒退／分叉、缺失文件、能力绑定删除、非法流转和逐 birth 点查。原治理日志回归继续保留。

Hub 接线测试从真实 HTTP 接纳进入真实 bridge 许可；SDK `add` 使用计数后抛出合成异常的边界，不调用模型。覆盖并发、篡改、伪造 birth、取消时等待持久线程、删除后首次许可拒绝、回执失败后稳定重试、重启、旧格式项目隔离和损坏描述。另保留真实 Supervisor 输入转换、准备、调用标记与 Drain 处理，只替换模型就绪和桥获取；第一次进入 SDK 后恢复旧队列，第二次仍无 SDK 调用，状态保持 unknown。不能把这视为真实外部模型质量或完整输出覆盖证书。

固定上游组合专项 **423 passed、1 个既有 xfail**。采用临时 HOME/data、显式隔离端口及实际 Core conftest／分类门禁，以 Hub 锁定环境执行 bridge、processing、generation permit、durable queue、job state 五文件；不是官方全部 Core 套件。0019 两入口／两构造点及 contents 顺序、重复、等待期间外部修改有专项；0020 新增 46 例，不改变普通 unknown/settle 合同。

本地多进程治理探针通过：forget/purge、重启、旧业务卷与缓存恢复、相同／冲突请求重试、修订保留、来源／内容重导入及恢复后的历史排除。其提炼和 Supervisor 仍使用合成缝，未验证在途取消。实际加载基线 edf3e67 的旧日志读取器后，已拒绝新 v2 日志且未改变文件字节；未进行旧容器启动试验。

Hub 全量运行 **984 passed、5 skipped、6 strict xfailed**，289 条警告为既有上游弃用警告。全量收集后新增的候选跨 birth 回归，与原身份专项一起 **10 passed**（其中 9 例也在全量内，不能相加计数）；旧源身份／并发等失败已修复后复跑通过。跳过项与预期失败没有算作通过。

独立分工为存储、上游生成门和受信队列接口，主任务负责接线、完整回归与最终审查；审查中发现的问题均按上文处理。最终复审未发现新的阻断项，不能替代下文的未完成验收。

工程检查 `make check` 通过。秘密扫描首次命中补丁中两个公开测试文件清单 SHA-256；已重新计算 340/341 个文件名列表核实，只精确排除这两个校验值，没有放宽所有摘要或文件扫描。
