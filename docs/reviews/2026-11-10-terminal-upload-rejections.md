# 永久拒绝项与后续补传修复

关联 FR-01、FR-06、FR-10、FR-11、ENG-01。设计、升级与回退约束见 [ADR-0055](../adr/0055-terminal-upload-rejections.md)。当前状态：本地回归、NAS 隔离安装、两台 Mac 备份升级及新版客户端读写、项目钩子验收通过。已有日常宿主会话的 MCP 热重载不在已验证范围内。

## 原因与改动

前轮 NAS 隔离实测已证明普通记忆忘记后，同长句混合事件整条拒绝；客户端却将该 409 显示为通用身份冲突并停在队首，连后一条合法事件也不能上传。

本次在已有本地网络队列增加终态拒绝索引。只有实际上传返回格式正确、有界且精确的 `governance_content_suppressed` 才标记该事件 rejected；保留过滤后的正文、身份及原因，无接纳回执。后续合法项继续，重复提交被拒事件仍返回拒绝，不重复计数。其他冲突、权限错误、身份不符与无效响应保持停止行为。服务端模型队列、记忆存储与治理语义没有更改。

本地 schema 2 仅增加索引表，保留原事件表及 capture 状态。两个本机 CLI 提供显式 `upgrade-outbox --backup-file`，排除并发写者后通过独立读取连接取得 SQLite 一致备份，再事务性增加表和版本。普通打开 schema 1 要求升级，旧客户端不能读取 schema 2；不会自动删库、重建或覆盖已有备份。Agent、hook、MCP 与 Skill 明确区分 rejected、queued、accepted。

## 回归证据

新增回归先在旧实现得到 2 项失败、9 项通过。修复后专用测试 32 项通过，覆盖终态幂等、ack 冲突、错误响应保留、持久化故障、两个 CLI、一致备份、WAL、失败回滚与 capture 状态保留；既有本地投递、传输、读取、Agent、hook、MCP、来源采集回归 174 项通过。

组合探针复用真实本地 HTTP、SDK 存储和合成提炼替身，11 项检查通过：恢复上传先收到 409，后一条收到 202；本地 queued 为 0、accepted 为 1、拒绝原因计数为 1；只增加后一条的唯一服务端回执及写入任务；新进程同步零上传；同 payload 重提仍为 rejected，正文保留；搜索排除已忘记记忆，原文仍可显式读取。

首次组合运行的队列关联断言误硬编码旧请求 ID 格式，虽已观察到正确的 `[409,202]` 与队列结果，仍记为探针失败。改为通过权威回执的 request_id 精确关联任务后重跑通过，保持唯一性断言，失败日志保留。该组合使用临时实例与合成提炼，不能称为日常两机或真实模型验证。

独立审查发现损坏旧库缺少必需表或列时，迁移可能误报成功；新增四类红例复现后修复，迁移先校验结构，失败保持原库字节与版本。独立复核 32 项通过且无剩余阻断。

## NAS 安装验证

提交 `60fb82b` 构建 Linux amd64 镜像，安装到 NAS 后实际镜像 ID 为 `sha256:425fb71af882c00af5c56ce95b0e8800909401f5b27527413e8e6ef824b1fdb7`。本地 containerd 与 NAS 的镜像标识形式不同，逐项核对 RootFS 层一致。独立禁网临时容器以只读方式挂载四份探针，不挂载日常卷；11 项检查全部通过，退出 0，用时 13.371 秒。原先 `[409]` 后阻塞已变为 `[409,202]`，最终 queued 0、accepted 1、rejected 1，重新打开零重发。使用真实 HTTP 和 SDK 存储、合成提炼替身，不计为真实外部模型或两物理设备的拒绝测试。

临时容器已清理。此变更属于客户端，日常 NAS 保持 `mvp-6801367` 且健康；不为客户端升级替换日常服务或迁移 NAS 数据库。

## 两台 Mac 备份升级

两机分别准备独立 `60fb82b` 运行目录并校验固定源码归档、依赖和上游补丁。先验证新运行时及独立 schema 2 队列，再备份七份配置，精确更新 Claude／Codex MCP、两份 Skill 的本机 CLI 绑定及拒绝状态说明、项目 UserPromptSubmit／Stop 钩子。其他配置内容、文件权限、设备配置与全局 Claude 设置均保持；没有重建身份或导入历史。

只终止精确匹配的旧 CMH MCP 子进程，未结束 Claude／Codex 宿主。随后通过产品命令显式备份并升级日常队列，原格式备份为 schema 1、当前为 schema 2；MacBook 24 条、Mac mini 13 条原事件的完整行（含 payload、摘要、顺序与回执）与备份逐条相同，原绑定保持。两机旧客户端均实际拒绝打开新格式，新 CLI 状态正常，旧 MCP 进程已消失。原运行目录及私有备份保留；不能只降级程序后继续读 schema 2，更不能以旧备份覆盖升级后的新增记录。

第一次向 Mini 传输时，macOS 附加的归档元数据被严格文件白名单拒绝，尚未解出文件；关闭附加元数据后，三份制品摘要校验和 stage 均通过。失败现场保留，未放宽文件校验。

配置切换本身不证明已有 Agent 会话已经重新加载 MCP。升级脚本明确返回 `applied_host_reload_pending`；新会话或重连后才使用新配置。两机私有使用说明已经各自备份并更新，旧回滚命令标为历史，不再指引直接降级新格式队列。
