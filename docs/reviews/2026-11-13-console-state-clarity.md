# 管理后台状态清晰度修复

日期：2026-11-13。关联 FR-07、FR-12。补丁 `0048-hub-console-state-clarity.patch`。

## 来源

普通用户视角评审（8 个维度、约 90 条带 `file:line` 的发现，另经独立批评阶段纠错）中，以下四项属于「同一屏反复出现、改动小、误解成本高」，先做：

1. 每次刷新都回到「请选择一个项目」，只有一个项目也不自动选中。
2. 顶栏「服务已连接」与侧栏「管理服务已连接」是写死的常量，NAS 不可达时仍然全绿。
3. 会话失效后页内错误横幅只有文字，没有「重新登录」出口；重试必然再失败。
4. 记忆库空态只有「本页 0 条」，与总览、历史原文的数字对照时容易被读成「数据丢了」。

## 实现

只改网页展示与本地状态，不新增协议、存储、鉴权或迁移。

- **项目持久化**：`HubContext` 把所选 scope 存入 `localStorage`，键按 `instance_id` 隔离；刷新后恢复。仅当实例只有一个项目时自动选中。存量 id 已不存在时当作未选择。`refresh()` 不再清空 scope——刷新是「重连」，不是「忘记我在哪」。存储被禁用（隐私窗口）时退化为仅本页有效。
- **真实连接状态**：顶栏与侧栏改用 `HubContext` 已有的 `error` / `loading`，三态显示「正在连接… / 服务已连接 / 无法连接 NAS」。新增 `.is-offline` 样式。没有引入额外轮询，避免为状态展示增加请求。
- **重新登录**：错误文本等于登录失效类文案时，横幅追加「重新登录」链接到 `/hub/login`。其他错误不显示该链接，避免误导。
- **记忆库空态**：`SdkMemoryLibrary` 新增可选 `renderEmpty`；控制台提供三态说明（未配模型 / 刚发送待整理 / 用历史原文确认已收到）与两个下一步按钮。只在首屏为空、非加载中、无错误时渲染。
