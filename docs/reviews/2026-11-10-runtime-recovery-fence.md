# 治理恢复失败的运行时隔离验证

日期：2026-11-10。关联 FR-10、FR-11、ENG-01、[ADR-0044](../adr/0044-governance-runtime-recovery-fence.md)。本轮修复已有普通服务的实际恢复故障，不提前开放 ADR-0043 的实验执行格式。

## 反例与修复

1. 真实 HTTP purge 已完成后，同 operation_id 重试在 Purger 的真实 I/O 位置失败，返回 503，但旧 `ready=true`、completed 和写入检查仍可放行。现增加同进程恢复故障状态，复用 Authority、Core claim/source 与 SDK generation 的原许可入口；完整恢复成功才解除，局部操作成功不解除。
2. 恢复此前捕获的原生 Chroma 记录后，purge 重试在删除前失败。原 Core GET 返回目标正文，Hub RemoteRead 已正确返回 404。现对原生 Core 业务转发及输出增加故障屏障；认证、静态页面和 Hub 治理维护不依赖未完成的 Core 业务恢复。
3. 独立复审发现已完成操作的实体覆盖预检处于故障边界之外：恢复真实原生实体后，重试虽拒绝但运行状态仍开放。现将已确认请求的真实恢复预检纳入故障边界，保留新请求不支持选择的正常拒绝语义。
4. 新隔离逻辑的独立审查复现正常运行回归：后台例行恢复采用缓存快路径时尚有活跃 worker，最终校验的临时维护计数会误拒绝其源许可。第一版修正复用纯 worker/admission 排空，实际任务恢复正常，但完整回归又发现它使正常读取和显式维护与例行检查争抢独占锁。最终区分健康与故障：健康检查只核验且不清标记、不抢独占；只有启动未验证或真实恢复故障才进入可以解除故障的完整屏障。模型提炼和 profile 为合成边界，不算外部模型测试。

不改主日志、准入证书、执行库格式、operation_id 或已签意图，不复制上游队列或新建持久状态。实际维护先等待原 worker 完成，之后才暂停新 SDK 许可；临时维护计数保持到资源全部退出，防止“先解锁、后异步失败”的窗口。能够解除故障的最终校验也保持临时屏障，在线程清除故障后但取消尚未返回的窗口仍不能发放许可；健康例行检查不做清除，也不暂停普通读写许可。

HTTP 继续复用既有延迟响应头和逐块复核。新增每请求的受控 Core 转发状态，使最外层数据库检查后再次检查进程故障；真实响应头发送等待后也再次检查。两个窗口均有修前失败、修后通过的实际回归。已发出的响应字节不声称可以撤回。

## 已有验证与工程评审

- Executor/Authority 新增 18 个参数化场景通过：启动未验证、真实已完成重试 I/O、原生覆盖预检、反复失败、完整恢复、局部成功仍隔离、过期/冲突/不支持请求、资源进入/退出、SDK 锁提前释放、取消等待、最终线程清除窗口及健康后台恢复。最终分支与原五个失败节点独立复验共 23 项通过；真实健康 worker 产出 1 条且任务 completed，空恢复禁止 SDK 构造且未创建 Chroma。使用真实 Core/SQLite/HTTP/SDK 调用前许可与合成模型边界。
- HTTP 故障边界新增 9 例与既有 boundary/authority 合计 33 项通过：真实原生记录恢复、首个正文与流式截断、最后一跳竞态、认证/静态/维护可达。既有无恢复初始化的空流式 fixture 改为先执行真实空状态恢复验证，原 200 首块及拒绝过期内容的断言保留。
- 只读维护及 Store2 兼容性中间态 197 项通过；唯一旧 fixture 初始化失败已修复，未放宽只读或删除断言。Store2 的既有真实多进程探针仍通过，不以运行时故障状态替代签名或原授权。
- 既有治理安装探针增加一次完整的故障隔离阶段：精确恢复原生记录、真实 I/O 失败、Core 503/RemoteRead 404、claim/source/SDK 许可拒绝、未消耗准入证明、反复失败、局部成功保持隔离、完整恢复重新放行。源码组合探针已通过；最终安装制品证据待记录。
- 第一遍完整 Hub 为 1419 通过、4 失败、5 跳过。4 个失败均为旧实体恢复测试仍要求故障后保留重放缓存；现要求缓存失效、`ready=False` 和故障标记，原计划、回执保留及恢复拒绝断言全部保留，整文件 31 项通过。最终完整结果将在正常 worker 回归修复后重新记录，不把中间失败抹去。
- 第二遍完整 Hub 为 1419 通过、5 失败、5 跳过。5 项分别涉及原文重启读取、生产力读取与取消、普通 SDK 读取和 SDK factory 共享准入，均为健康例行恢复占独占锁造成的真实可用性回归。原测试保持不变，不以停止后台任务或接受 503 掩盖问题。
- 最终完整 Hub：**1424 passed、5 skipped、289 warnings，227.06 秒**。跳过项为未安装的可选向量后端，不算通过；使用现有固定的 22 补丁上游环境，本轮未修改上游源码或清单。`make check` 通过，代码及测试身份在完整运行期间冻结。

架构评审保留单一 Authority、Executor 和原 ASGI 检查算法。持久协议无变化；新增进程 Event、锁和临时计数不持正文。性能检查为常数状态读取，HTTP 内层不重复扫描主链；原结构检查仍按既有合同执行。独立代理复核真实失败证据、恢复时序与输出窗口；未使用外部模型或真实历史。

健康核验取消另经独立反例检查：真实只读核验完成后延迟返回，此时没有 SDK 独占或临时许可计数，连续取消仍等待实际线程结束；返回后故障标记成立、重放缓存失效且写许可拒绝，再次完整恢复后才开放。不能把“健康检查不抢独占”解释为取消后仍可继续写入。

## 尚未完成的范围

同一镜像本地/NAS 验收正在执行，不把上述交叉重叠子集相加作为全量结果。常驻 NAS 尚未升级。本修复不是完整文件治理接线、全部副作用证书或 G1 退出。

后续产品接线仍需：原 purge 与 repair 的签名恢复工作图、可达的完整记录审阅/确认流程、SDK 文件批处理、Core 与容器输出域，以及恢复完成门槛。跨项目混合旧记录是否允许逐条确认整条删除仍待用户答复；重导入整事件拒绝不构成此项授权。新正式实例可评估禁用 Docker 持久日志并由宿主 create/inspect/start 核验，现有容器不能仅修改 YAML 就被认定已清除历史日志；本轮没有修改部署日志驱动。
