# 在途任务取消与恢复验证

日期：2026-11-10。关联 FR-10、FR-11、ENG-01；设计见 [ADR-0038](../adr/0038-durable-sdk-admission.md)，承接[持久准入验证](2026-11-10-durable-sdk-admission.md)。本记录只覆盖确认范围内的在途任务，不代表全部删除恢复或 G1 已完成。

## 执行与兼容

已把出生证明、候选观察和 Core 受信取消接入治理执行／恢复。计划提交前完成归属、完整输入、独立准入日志和范围检查；签名目标绑定每个 job、request、原队列正文摘要及取消／终态清理用途。只有完整 ENROLLED 证明可取消非终态任务；unknown 的状态或 hy_invoked 值不充当负证明，MAY_INVOKE／旧任务不确定时保留状态和正文。

forget 取消任务并保留完整原文的显式读取；purge 仅清理本操作已确认任务的终态正文。completed 重放仅重查签名任务，不因后来无关任务获准调用而扩大范围或阻断启动。仅恢复旧 Core 队列时，启动恢复在开放 claim 前重复同一取消／清理，不追加删除意图。终态清理证书不能被恢复出的非终态任务用于取消。

旧操作不补签出生证明。其已确认原文的终态正文沿原 Core 清理语义处理，快照所属任务不自动升级成整条原文删除范围。计划从未提交到主日志时，在 SDK 观察前丢弃；执行库与主日志的意图即使分别签名有效，也必须完全一致。

## 审查与修复

独立审查复现旧请求定位先取完整回执、后核算预算，以及两次快照之间 job/request 交换可能逃过集合核对。修复复用候选模块的元数据、正文和总预算工具，在同一次配置／Core 只读快照内保留逐 job 映射；全部所需正文的累计大小通过后才开始取正文，不读取非终态队列正文。测试保留拒绝前零正文读取、跨两库累计预算和交换映射负例。

安装验证发现旧治理探针复用归档初始化时额外接纳一条无关 pending，正确触发 native 范围不完整拒绝。探针改为复用仅创建身份／来源的初始化，不接纳无关事件；没有放宽产品保护或把该任务强行标完成。同作用域未提炼修订继续由真实治理取消。重启后 Core 原有保留策略允许队列正文变成严格清理标记，探针核原摘要和完整 Hub 原文读取，不错误要求队列副本永不回收。

原请求预算测试改为将真实在途凭证计入总量，仍验证 10,000 个目标可接受、10,001 个拒绝。并发恢复测试现在阻塞实际清理调用，验证启动与后台恢复只执行一次。

## 验证范围

原 G-A/G-C 六个严格预期失败已转为真正成功的回归：单条／同来源多修订取消，以及恢复旧队列后自动取消和清理。两个同项目非空 SDK 对照保留已有无关原文／记忆和队列行。另覆盖 unknown 负证明、MAY 拒绝、中途取消失败后重启续做、相同请求重试重新检查、无关后续 MAY 任务及孤立计划处理。

`make probe-inflight-governance` 使用四个独立进程执行接纳、治理、仅恢复旧 Core、启动恢复与读回。实际 HTTP、生产 lifespan、SQLite 队列与主治理／准入日志参与；断言签名文件不变、SDK 生成入口零调用、forget 原文可完整读取、purge 原文不可读及 Core/WAL 物理正文清除。模型就绪和 embedding 为合成边界；它不是外部模型质量或六客户端验收。`--installed` 额外要求三个关键模块来自安装包。

覆盖审计补充 `test_reaped_queue_vacuum_recovery.py`：仅恢复已经严格清理、但 SQLite 旧页仍含正文的 Core；逻辑记录和 `present` 均为空，生产启动仍进入清理／压缩，停服后字节残留消失，签名意图和队列行不变。专项通过；仅内存换回旧 present 快径的负对照失败，产品源码未改变。

Hub 最终全量 **1063 passed、5 skipped**，无预期失败；五个跳过为可选向量后端，289 条警告为既有上游弃用警告。`make check` 在纳入新文件后通过。旧请求与终态清理专项 62 项、恢复／请求／清理专项 37 项及旧页恢复专项 1 项均在全量内，不能相加；独立复审的 48 项也为重叠验证。源码四进程探针再次通过。上游补丁本轮未变，保留前轮 423 passed／1 个既有 xfail 的证据，不描述为本轮重新执行。

独立分工覆盖候选证明、旧清理预算、安装探针和只读审查；主任务负责执行接线、恢复、全量回归及最终集成。独立复审无剩余阻断项。

## 安装与 NAS

产品接线提交 `e6e3538`，安装夹具和恢复覆盖补充提交 `c0467f5`。最终 Linux amd64 镜像 `cloud-memory-hub:dev-c0467f5` 从明确 Git 提交、固定上游、18 个受审补丁和摘要核验的模型缓存构建；运行时来自已安装 wheel。首次构建发现私有缓存权限过严，修正公开模型文件权限后，以普通运行账户再次验证成功；模型字节及摘要不变。

本地与真实 NAS 均通过六套安装探针：治理执行、完整 Drain 等待、实体范围、生产力忘记保护、Chroma 删除重放，以及新增在途取消／仅队列恢复。两端完整 Compose smoke 通过离线模型编码、初始化、认证、设备／来源撤销、HTTP 接纳、安装 CLI 与读取／采集，以及重启持久性。合成模型和 Supervisor 的边界仍如各探针说明，不能据此宣称外部模型或六客户端通过。

两端另用实际旧 `cde427c` 和新镜像、独立临时卷验证：新镜像未迁移时拒绝；显式迁移及再次迁移保持身份、凭证、日志和绑定；新镜像第二进程可完整读取同一事件。仅恢复旧 config 2、保留新 Core 与治理卷时，实际旧镜像的 `serve` 以 `governance_version_unsupported` 拒绝，Core／治理文件逐字节摘要不变。生成入口禁止调用；实际 CLI／HTTP 均以运行账户执行，仅新建卷的所有权准备使用 root。这是实际容器兼容性验证，不是旧读取器模拟，也不是允许降级。

常驻空实验实例先停服，备份 config/data/governance 三卷及 Compose／环境配置，逐归档验证内容和摘要；再显式迁移并重复核验，升级到 `c0467f5`。身份库为 3、主日志为 2、独立准入日志和双向绑定有效；实例身份、凭证、挂载、3 GiB／2 CPU 限制、只读根、能力限制和回环端口不变。启动和重启均通过，最终独立 SSH 检查为 running/healthy。没有自动回滚、丢弃治理卷或修改 SSH。

## 仍未完成

- 旧／已许可任务的完整 SDK 副作用覆盖证书、生产力治理、备份与离线端删除传播仍待完成。无关在途任务存在时，无法证明的 native／snapshot 范围继续明确拒绝。
- completed purge 即使正文已被替换为清理标记，仍会重新执行压缩和核验，以覆盖恢复到清理后、压缩前的旧库。历史操作较多时会重复全库压缩；本轮优先保证恢复正确性，行／字节预算不等于恢复耗时上限。
- 保留已确认的 HNSW 未使用预分配空间限制；没有扩展为全磁盘零字节承诺。
- 未修改日常 Agent 配置、导入真实历史或调用外部付费模型。正式网络入口和 GitHub 发行仍按 roadmap 推进。
