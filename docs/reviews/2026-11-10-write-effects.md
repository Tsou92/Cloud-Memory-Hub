# 2026-11-10 原生写入观察及诊断副本恢复

关联 FR-10、FR-11、ENG-01。设计为 [ADR-0039](../adr/0039-sdk-write-effect-observation.md)；缓存清理补充见 [ADR-0035](../adr/0035-purge-cache-recovery.md)。本项不改变用户选择：同项目命中已忘记/删除的规范化长句时拒绝整个事件，包括混合新内容。

## 变更与实际发现

`80ffd17` 统一清理 SDK 的三张请求缓存表：write_outcomes、pipeline_logs_v2 和 memory_operations_v2。修前实际原生缓存写入、HTTP purge 返回 completed 后，两张诊断表仍有目标行；仅恢复诊断缓存也未清理。诊断文字可以不同于原文，所以正文片段扫描不是副本完整性证明。修后首次执行、同意图重试及仅诊断缓存恢复均按原请求精确清理，无关请求行保留。

新增仅 history 恢复的独立回归：实际 HTTP 接纳、SDK 写入及成功 purge 后，只恢复旧 history.sqlite3；其他持久文件的摘要不变。生产启动按原签名范围重放，清除目标历史行及 SQLite/WAL 正文，同项目和另一项目历史保留，operation/head 不变且无 SDK 再生成。仅内存跳过历史删除的负对照确实失败。

`c7a8d27` 的补丁 0021 在原生存储边界记录尝试目标，复用 Chroma 五个变更入口、HistoryStore 共同 insert、SQLite 请求日志/episode、SDK 生命周期和结果缓存。26 项新增测试覆盖非空 add/add_extracted、结果 ID 之外的画像/旧节点、批量部分写、落盘后异常和取消、unknown 结果留存、重开重放、上下文隔离、旧结果、超限及未观察域。

字段永远是 `observation_only=true`、`all_effects_proven=false`，不改变任何治理执行许可。`returned` 仅代表函数正常返回，不证明落盘成功；冻结副本不证明之后不会有后台写入。原子/持久覆盖证书、实际版本核验和旧任务恢复仍待实现。

## 审查及修正

独立代理分别检查副作用清单、Hub 证明边界、反例和最终差异；根代理复核并集成。

- 观察器提前遍历 batch 会消费调用者迭代器：改用原生有效节点列表。
- seal 异常时上下文可能未恢复：改为统一 finally。
- 固定预留头部空间漏算 JSON 转义：反例修前 265562 字节超过 262144 上界，修后 260690 字节且明确 byte_limit；增加 NUL、反斜线、中文及 emoji 回归。
- entity collection 独立于 graph 开关：元数据明确标识未观察，开启时不声称已覆盖。
- 新探针误将 semantic ID 当原生 ADD 历史 ID、误计自身基线文件、误要求 add_extracted 写 history：按固定实现修正，未改产品算法制造通过。
- 探针增加硬模型拦截及受控提炼，避免继承环境后意外访问外部模型。
