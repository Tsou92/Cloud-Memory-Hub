# 普通记忆生产版本验证

日期：2026-11-02。关联 FR-08、FR-09、FR-10、FR-11；设计见 [ADR-0026](../adr/0026-chat-memory-origins.md)。

## 实现与复用

补丁 0014 扩展已有 record_origin 为普通记忆生成独立域的语义版本摘要，沿用 MemoryNode、通用 payload 与原生 writer 的持久化位置。生产请求与语义状态一起写入，单条/批量 ADD、原地 UPDATE、SUPERSEDE 和直接写入均覆盖。UPDATE 使用已有旧节点读取，不增加数据库访问。旧节点读取失败则清空来源。三个原生后端对未带完整来源对的语义更新清空旧标记，辅助状态更新保留生产者。

摘要保持 experience/fact 兼容，普通记忆覆盖实际模型内容与身份/时间；旧数据缺失字段不回填。该一致性标记不是签名，也不能单独证明完整来源链。Hub 原文、唯一生产请求、作用域与阶段/产出关系仍需接线验证；画像、摘要、后台任务、删除执行与恢复防复活继续待完成。

本轮对架构、数据流、代码、错误路径、测试和性能作顺序自审，没有独立同行审查。新增开销是语义字段摘要；保留原模型调用、检索和存储后端。

## 本地测试

项目安装环境的 make check-runtime：536 项通过、5 项可选后端测试跳过，269 条既有上游弃用警告。另以固定可选依赖运行 make check-memory-origins：28 项全部通过，包含上述 5 项；跳过项没有计为原环境通过。make check 的格式、静态检查、19 项工程门禁、文档路径/链接与凭证扫描通过。

新增用例覆盖语义篡改、旧数据、节点/通用 payload 往返、非法请求和结构、完整/不完整来源对，以及三种真实本地存储 Chroma、FAISS、Qdrant 的持久化和重开。原生 writer 的合并结果使用合成操作，覆盖批量 ADD、单条/批量 UPDATE、SUPERSEDE、直接写入，以及旧节点读取异常。现有真实 SDK add/add_extracted 回归补充生产版本断言：原地更新后的当前节点归属新请求，冻结输入和重放仍归属旧请求。

make probe-memory-origins 在三个独立进程中验证两种 SDK 写入入口、原地更新、版本标记、冻结输入和重放；模型响应为合成结果。该证据不代表模型质量或六入口真实接入完成。

相关上游 payload-only、L1 边界、写入缓存/结果/延迟、链合并/回退、提示、带向量更新及克隆回归：80 项通过；1 项 Qdrant BM25 稀疏克隆因 fastembed 支持不可用跳过，未计通过。可选测试环境沿用 faiss-cpu 1.15.1、qdrant-client 1.19.1、pytest-asyncio 1.4.1，产品依赖未修改。

验证过程中修正了两个测试环境问题：Chroma 的正文更新样例补齐同维度合成向量，避免调用默认 embedding；可选依赖环境用 python -m pytest 确保后端真正加载。曾把全量测试放入临时依赖环境，2 项已安装 CLI 测试因缺少入口文件失败；这两项随后在原项目安装环境实测通过，保留其真实命令验证。CI 分别运行正式安装环境、全部可选后端和跨进程探针，尚无远程 CI 结果。

## 安装与 NAS

首次网络构建在下载 embedding 模型时因 HTTPS 连接中断失败。改用逐文件摘要与上游清单一致的五个公开模型缓存，保留原下载脚本、固定上游与补丁校验。不过缓存复制保留了仅文件所有者可读的权限；构建阶段的 root 校验通过，安装后的普通账户无法加载 tokenizer，真实 SDK 写入探针失败。该镜像未用于升级已有实例。

针对需求中的 NAS Docker 部署场景，Dockerfile 在切换普通账户后再次执行现有上游 verify_assets，让不可读的模型在构建阶段就失败；不提高运行用户权限。私有缓存构建输入的公开模型文件改为 0644、目录改为 0755。相关业务代码与模型摘要不变。

普通账户执行 verify_assets 在失败镜像上实测返回 PermissionError；修正缓存权限后，同一检查在新镜像构建阶段通过。make check 再次通过。这是安装权限检查的失败/通过证据；业务代码未在此次构建修正中改变。

交付镜像为 cloud-memory-hub:dev-19efdf3，源码修订 19efdf3348e2869846fe1d6470c54c19d508d101，linux/amd64。镜像 config 摘要为 sha256:4c1059ae8ce8caf01abc3586bdd39709e2fa814ddcde3d1093b70c1ab80d8b3f；导出包 261274112 字节，SHA-256 为 28f151727a2fa6b4760131a5c0f329434ef4808f35602b3f20ec70c91cd75398。NAS 接收后重新校验包摘要、加载后的 config、架构和修订，11 个探针文件摘要一致。

该构建使用已核验的固定上游源码与公开模型缓存，不是一次干净的在线下载构建。私有构建配方只比仓库 Dockerfile 增加两个缓存 COPY，其余内容逐字相同；配方 SHA-256 为 049dab902050f654a03c011c01206fb0df22feb4ec58af537bdec70a183c89f6。原上游准备/补丁校验、模型清单校验，以及新增普通账户校验均执行；运行时环境没有携带构建代理变量。

本地 Docker 与 NAS Docker 的独立临时卷均实测通过：安装后的 SDK 先写入、原地更新，再由独立进程读取和重放；新版写入的结果缓存经旧镜像 a677bac 读取后，新版仍能核验当前节点来源；旧版生成的记录由新版读取仍保持来源未知。使用断网、只读根文件系统与普通账户，模型响应为合成结果；不把这些兼容性探针称为生产回滚或真实模型验证。

两端完整容器检查均通过，覆盖初始化、认证、真实 SDK 检索、来源管理预览、已安装连接命令/读取钩子、过滤后的 HTTP 接纳与持久重放、原生格式合成采集、授权撤销及重启后的拒绝访问。

NAS 原空测试实例在停服后备份配置、数据、治理卷及部署文件，分别得到 168960、698880、31232 字节的卷归档，校验归档与摘要后由 a677bac 升级为 19efdf3。升级及再次重启后，健康检查、实例身份/凭证指纹、空数据基线和既有 schema 均一致。仍使用原数据卷、只读根、全部能力移除、3GiB 内存/2CPU 限额，以及回环地址 8800 端口。

没有执行生产回滚、完整备份恢复或 Hub 显式迁移命令；没有导入真实历史、改动日常 Agent/SSH 配置或激活外部模型。Hub 普通记忆来源接线、其他模型输入来源、删除与恢复防复活仍待完成，不能据此宣布整个产品或 G1 验收完成。
