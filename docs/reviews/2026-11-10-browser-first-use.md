# 自行部署后的首次网页使用验收

关联 FR-01、FR-02、FR-04、FR-05、FR-11、FR-12、FR-13、ENG-01，
以及发布计划 R1-02、R2-01、R3-01。复用现有管理控制台、模型设置、SDK 原文组件
和备份接口；补丁 0035 只修改展示，不新增协议、存储或鉴权。

## 环境与实际流程

在 MacBook 的 Docker 中以已构建的 `preview-ad8d661` 和官方 init／supervise
创建全新四卷实例，服务只监听本机回环地址。使用真实 Chrome 浏览器操作，
管理员凭证由该空白实例初始化生成；没有访问日常 NAS 管理员凭证或真实历史。
项目、设备、记忆、交接及模型响应全部为明确标注的合成内容。

- 登录、创建项目与设备成功，真实浏览器下载配对 JSON。用户确认下载后，核对两份
  文件一致；用实际已安装 preview.4 客户端在新状态目录导入其中一份，并直接使用
  导出的 MCP 配置连接。
- 两次写入获 Hub 持久接纳，记忆原文和完整任务交接读回通过；队列为 accepted 2、
  queued 0、无 rejected。沿用网页创建的同一设备和来源，未另建身份或重复写入。
  初始探针误把 NFKC 标点与事件 ID 当作原样回执，修正只读断言后检查原记录；
  不把第一次断言失败隐藏为成功。处理记忆搜索为 0，不计作提炼或语义召回通过。
- 模型空表单给出必填错误。填写 Anthropic 测试接口与合成 Key 后，不点击刷新也会
  自动获取候选列表；选择候选并测试，页面显示已配置的当前模型。隔离替身计数为
  两次目录成功请求（含一次预检）及一次探测成功，证明网页触发了真实 HTTP 调用。
- 替身只接受内置连接测试提示；两条后续提炼请求被拒绝，随后在网页关闭提炼。
  此项不证明外部服务可用或模型提炼成功。最初替身使用普通 HTTP 容器域名被既有
  HTTPS 规则拒绝，改为测试容器内回环地址后通过；未关闭证书校验或改认证逻辑。
- 开启定期备份、设置保留 3 个版本并保存后，页面显示下次执行时间。提交一次备份
  请求后服务按设计短暂停止，浏览器会话失效；重新登录可见成功时间及实际历史版本，
  清单声明 17 个文件、约 1.1 MiB。页面未把“排队”算作完成，也未把清单当作恢复校验。
  CLI 恢复和中断恢复的 NAS 证据见[备份指南](../backup-and-recovery.md)。

## 发现的问题与修正

1. 控制台通用 form 样式覆盖了模型表单的 grid，造成标签与输入框挤成不正确布局。
   补丁 0035 让通用规则排除原有 `.model-form`，保留已有双列与窄屏单列断点。
2. 已接纳原文直接展示整个协议 JSON，交接又被转义为嵌套字符串。继续使用 SDK
   历史组件，仅对完整的 Hub v1 原文显示记忆正文、交接栏目和消息角色；完整原文及
   来源留在折叠区，未知、损坏、截断或普通 SDK 内容保持原样，所有正文使用 React 文本。
3. 备份页没有指向已实现的导出、导入及回滚方法。增加现有 NAS CLI 指南链接，
   并明确网页不执行恢复；版本清单说明改为普通用语，不扩大完整性保证。

Node 24.22.1／pnpm 11.24.0 隔离执行 Dockerfile 所列 15 个测试文件，290 项通过；
Web、contracts、operations 类型检查与生产构建通过，源码前后摘要一致。
主 JS 约 514.15 kB，触发默认 500 kB 体积提示；构建未失败。
独立静态审查未发现阻断问题。将构建资产装入该独立实例的派生测试镜像后，核对 20 个
资产摘要及页面实际获取的 HTML／JS／CSS；保留原四卷、身份、项目、配置和备份。
真实 Chrome 复验：模型表单恢复双列，390 像素窄屏为单列且无横向溢出；历史默认显示
交接栏目和记忆正文，展开可见完整协议原文与来源；备份指南链接可见且路径正确。
浏览器记录没有控制台错误，临时视口已恢复。此为网页资产派生测试镜像，后端仍为
`ad8d661`，不计作包含 0034 的最终发行镜像验证。

## 两个项目与普通忘记

后续在同一独立实例，通过现有官方 SDK 精确导入两个项目的不同合成记忆及来源。
仅取消合成模型配置的活动状态，保留配置与密钥，使用现有无模型摘录模式。
真实浏览器选择两个项目询问同一问题，分别得到各自的青绿色与紫色内容；切换项目后
旧回答与引用详情清空。点击引用可打开相应记忆；对第二项目预览、确认普通忘记后，
再次提问没有相关回答或引用。原文不再自动列出，按精确编号仍可读取；这符合忘记规则，
不是删除原文。随后另导入不同的日历合成内容用于来源入口复验，没有重导入已忘内容
或取消规则。本段不计作模型生成或模型提炼成功。

## 新手上手流程

用户随后明确要求面向完全不懂技术的新手。只改已存在的界面流程，复用当前项目、
模型、配对、历史读取及忘记接口，不新增账号、协议或另一套安装器：

- 首页解释项目的用途并给出顺序入口；已有项目优先选择，不用“已登记”冒充在线。
- 模型表单按服务、地址、服务商密钥、候选模型、测试排列；说明密钥来源与用途，
  保留手填和已有密钥，接口类型不自动猜测。
- 配对文件生成后给出安装、导入和 Agent 连接指引。安装器不修改 PATH，因此移除
  裸命令误导，明确使用安装器显示的完整路径。清除页面凭据后保留无秘密的后续指引。
- 首条共享示例引导用户先在历史中确认收到内容，再在另一端读取；不把收到原文等同
  于完成长期记忆整理，不把读取错误当成空项目。
- 记忆类型使用中文；修正“已有忘记按钮却仍提示不能操作”的矛盾。
  引用复用当前项目的精确历史读取和续页；忘记成功后可主动查看已知保留原文，
  不重新加入自动列表。帮助页提供实际安装与验证文档链接。

这些改动属于补丁 0036。Node 24.22.1 下 15 个文件、306 项网页测试通过，
完整 Web 类型检查和生产构建通过；283 个源码文件摘要在验证前后相同。
另在固定 Node 24.10.0 的 Linux amd64 Docker web-tests 阶段执行同 15 文件，
306 项通过。该构建复用已核验公共固定上游缓存，再由原 prepare 检查全部补丁；
没有改业务源码、测试选择或隔离 runner。主 JS 约 524.73 kB，仅有默认体积提示。
独立静态审查未发现阻断问题。将最终资产替换到同一独立实例后，真实 Chrome 验证：

- 未选项目时可看到四步指引，已有项目提示选择而非重建，并可直接进入模型设置。
- 重排后的表单仍自动获取合成候选；选择后模型名及配置名称正确填入。该轮没有重新
  保存或启用模型。390 像素下表单单列、配对指引正常换行，均无横向溢出。
- 使用此前真实下载的配对文件对应状态，清除页面凭据后仍显示设备名称及完整后续
  指引，没有重复建设备、重新签发凭证或变更已有授权。三个帮助链接及章节路径正确。
- 日历合成记忆能直接打开实际来源；预览并完成普通忘记后，列表变空，显式点击
  “查看保留的来源原文”仍能按编号打开原文。切换项目清空旧来源及操作结果。
- 控制台无错误，临时视口已恢复。四卷与业务／治理内容保持；底层 Chroma 启动仅
  按固定实现追加一行内部锁记录，该差异单列留证，未宣称数据库逐字节完全不变。

本次是实际浏览器任务复验，不声称已完成外部新手用户研究。Mac 客户端仍需按文档
安装并配置 AI 应用，不能把分步指引描述成已实现一键、免命令安装。
