# 登录文案与离线重置管理员密码

日期：2026-11-13。关联 FR-07、FR-12。

## 问题

- 用户设的是「密码」，但登录页标签写「管理员凭证」，不知道这里该填什么。
- 忘记密码等于永久进不去后台：凭证是不可逆 PBKDF2 记录，全库文档没有任何重置说明。
- 手动部署后首次初始化页只说「请打开安装器提供的初始化链接」，页面没有任何获取方式，只能自己去 NAS 终端找命令。
- 改密成功后直接跳回登录页，没有「已更新」提示。

## 实现

- **文案**：登录页「管理员凭证」改为「管理员密码」，并补一句「首次登录时由安装器设置；忘记密码可在 NAS 执行环境重置，不影响已连接 Agent 与已有数据」。超长请求的错误文案同步改为「管理员密码」。初始化链接已失效页与首次初始化页同样改为「密码」。
- **首次初始化页**：改为三步可执行说明——在 NAS 上执行 `docker compose exec hub /opt/cmh/venv/bin/python -m cloud_memory_hub setup-link`、在本机浏览器打开打印出的链接、说明该链接只对当前实例有效。不打印也不会重置密码。
- **离线重置**：新增 `reset-admin-password --writers-stopped` 子命令与 `admin_credentials.reset_admin_password`。复用与页内改密相同的原子发布路径（临时文件 + `fsync` + `os.replace` + 目录 `fsync`），只替换 `admin-token`；设备凭证、项目授权、记忆、加密密钥均不改变。新密码从标准输入读取，不进入命令参数或 shell 历史。目录权限不安全、文件不可读、写入失败时返回非零并保持原文件。
- **文档**：`docs/development-runtime.md` 新增「忘记管理员密码」一节，给出停服、重置、重启三步命令，并说明它不是密钥轮换。

## 验证

- `test_admin_credentials.py` 新增两项：
  - 重置后写入的是可验证的密码记录而非明文；新密码可通过验证、旧密码不再通过；设备权威库字节与加密密钥不变。
  - 空密码与不安全的配置目录权限被拒绝。
- `test_admin_credentials.py`、`test_initial_admin_web.py`、`test_initial_admin_state.py`、`test_boundary.py`、`test_login_recovery.py` 合计 **30 通过**。

## 未覆盖

- 页面内改密成功后的「已更新」确认条：当前流程保存后立即跳登录，改动涉及会话生命周期，单独处理。
- 重置后的旧后台会话失效依赖重启；命令不会主动撤销正在运行的进程内的会话，因此必须停服执行（`--writers-stopped` 强制声明）。
