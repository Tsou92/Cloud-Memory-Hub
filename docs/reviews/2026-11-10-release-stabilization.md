## 两项修复

### 首次打开空记忆库

旧测试将“没有加载提示”当作加载完成，但组件刚挂载、请求尚未启动时也满足这个条件。
受控延迟响应下，旧条件三次提前结束并失败；等待明确空库结果的条件三次通过。
只修测试等待并增加空列表断言，组件和样式不变。正式 `make check-web` 在固定
Node 24.10.0 / Linux amd64 容器中通过 17 个文件、339 项测试。
完整复现范围见[空库测试记录](2026-11-10-sdk-empty-library-readiness.md)。

### Docker 镜像身份

另外对已保存的 `346938a` 原始归档进行复核，发现 `image_receipt` 将 Docker 原生 ID
直接等同于归档配置 SHA-256。真实本机 containerd image store 返回 OCI index 摘要；
同一归档在真实 NAS 经典存储后端导入后，ID 为配置摘要，且 Descriptor 字段不存在。
原实现会拒绝本机的有效镜像。这是独立确认的打包兼容问题，并非上述发行运行的报错步骤。

继续使用既有发行脚本、归档格式和 smoke：`image_id` 保留已测 Docker 原生 ID，
新增 `config_digest` 表示配置字节摘要。OCI 路径核对 Descriptor 与原生 ID，逐层验证
归档 blob 的大小、摘要、唯一 Linux amd64 manifest 及其配置绑定；经典路径保留原校验。
不能仅以 revision 标签或文件名代替内容绑定。兼容说明见[发行制品](../release-artifacts.md)。

发行脚本专项 30 项通过，包含修复前失败的 OCI 正例，以及摘要篡改、配置替换、
错误大小、未知类型和重复目标平台等拒绝路径。修复后使用未改动的真实 `346938a`
归档和实际本机 inspection 通过绑定核验，配置中的 14 层与已测镜像对应；没有重建镜像、
改写 inspection 的 ID 或修改归档来制造通过。

合并两项修复后，`make check` 通过：113 项中 110 项通过、3 项条件跳过。
本机携带隔离的 PowerShell 运行原安装命令测试；两项固定运行时下载与 Windows DACL
检查留给相应 OS 工作流，不把本机跳过项计为通过。锁文件检查通过，依赖版本未改动。
