## 已观察的源码与兼容性证据

首轮 Hub 全量 1388 通过、5 个可选后端跳过；原生新增及相关回归 192 项通过，Core 39 项通过。只读相关 157 项、执行与清单 70 项、独立执行/gate/store 81 项是交叉重叠子集，不相加当作独立测试数。后续错误归类修复与完整安装探针完成后须记录最终回归。

独立复核发现：正常日志轮转后，无 stage 的旧 verified 进度仍要求旧路径保留旧前缀，造成错误拒绝。已限定此前缀保护只适用于实际尚存 stage，真实原生反例修复后通过。旧 verified 进度、旧正文与新 strict 尾行共同恢复时，重新扫描并清理授权正文、保留新增尾行，原签名操作未新增或改写。

完整探针还发现，目录扫描 contextmanager 曾把 yield 内的实际替换失败误译成扫描不可用。现只转换扫描自身错误，执行错误由引擎固定归类；77 项执行/清单回归验证准确错误、文件描述符关闭与现场保留。真实子进程探针和对应测试通过：HTTP 接纳两个合成请求、旧 purge 完成、三种原生格式 6 条记录、两次只读 CLI（含迁移 capability 间隙）、独立 repair 意图、第二次 replace 故障、全新进程恢复、只恢复日志再清理、安全尾行保留与变字节拒绝。探针只返回两域执行证据，明确 `whole_purge_completed=false`。`--installed` 校验 Hub、SDK、Core 三包及每个恢复子进程，禁止把工作树源码混入安装验证。

实际旧安装镜像 `cloud-memory-hub:dev-8588581` 的治理日志读取器接受原 admissions capability，拒绝新增 execution capability，错误为 `governance_capability_invalid`；主链头不变。这是实际旧读取器验收，不等于完整旧 Compose/启动迁移验收。

验证期间新私有上游克隆缺少已有模型缓存，首轮相关测试 21 项失败；按官方摘要校验并复用前序已验证的 5 个模型资源后完整回归通过，无外部模型调用、无网络下载或产品断言放宽。旧镜像读取器探针的入口/解释器两次启动错误也保留为失败记录，修正验证命令后才计通过。
