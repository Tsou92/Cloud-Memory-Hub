# 记忆库搜索

日期：2026-11-13。关联 FR-07、FR-12。补丁 `0051-hub-memory-search.patch`。

## 问题

需求第 7 节要求「搜索与浏览记忆」。后端 `/hub/v1/memories/search`（控制台为 `POST /hub/v1/console/read/memory-search`）早已实现并可用，但控制台从未调用它：记忆库没有搜索框，历史原文页固定写「本页暂不提供历史全文搜索」，清单里 10 条一页，找一条只能盲翻。

## 实现

只接现有的、项目范围的语义搜索，不新增接口或索引。

- `MemoryLibraryReader` 增加可选 `search(query, signal)`；实现走 `readHub(instance, scope, "memory-search", {query, limit: 10})`。与 `list` 共用同一套 scope 校验、抑制过滤与错误映射。
- 记忆库在 `reader.search` 存在时渲染搜索表单（`type=search`，含 aria-label），可「清除搜索」回到完整列表。搜索期间清空旧结果并禁用提交，避免把上一轮结果当成新查询的结果。
- 没有 `search` 的 reader（例如只读引用详情）不渲染搜索框，保持现状。

## 边界

这是**当前项目的语义检索**，不是历史原文全文搜索：

- 依赖 NAS 上已生成的可搜索记忆；未配置模型或尚未提炼时可能返回空，空结果不代表没有相关原文。
- 历史原文页仍写「暂不提供历史全文搜索」——Hub 侧没有对应接口，原生 `searchSdkRaw` 只适用于本机 SDK 库，不能用于项目范围。

## 验证

- `SdkMemoryLibrary.test.tsx` 新增两项：有 `search` 时输入并提交会以该查询调用、命中结果替换列表、「清除搜索」回到列表并重新走 `list`；没有 `search` 时不出现在搜索框。
- 受影响的 5 个测试文件合计 **72 通过**；`tsc -b` 通过。
- 49 个补丁（含本补丁）从干净检出准备通过；叠加后在 4 个文件上与开发副本逐字节一致。
