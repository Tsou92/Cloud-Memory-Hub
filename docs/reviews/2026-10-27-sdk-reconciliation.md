# SDK 未知写入恢复

关联 FR-02、FR-04、FR-10、FR-11、ENG-01，设计和复用证据见 [ADR-0015](../adr/0015-sdk-unknown-write-reconciliation.md)。本项恢复已完成写入但丢失回执的任务，不重发 SDK add，不调用外部生成模型。

## 实现与自审

patch 0007 沿用 Core 定时核对、SDK 持久结果查询和原队列状态机，增加可选回调及比较冻结输入／更新时间后原子保存回执的参数。不新增表或协议版本；未注入回调的上游仍保留 unknown。正常 add_extracted 回执同步修正：单数 memory_id 是语义记忆，不是原始记录。

Hub 核对请求、用户／Agent／会话、操作、终态和所有声明引用。chat 原文／记忆复用 bridge 查询；productivity 复用上游路径派生，以只读 SQLite 连接核对两个变体的身份字段，未初始化 writer 也能在重启后查回。缺失引用、身份不符、同 ID 多变体冲突、损坏结果、失败及非终态均保留 unknown。上游禁止自动恢复的写后权限错误继续排除。每轮最多 32 项、单回执最多 512 个引用，稳定游标轮换，坏任务不阻止后续任务。

核对与提交受共享 SDK 准入覆盖，取消仍等待原生查询／提交线程真正退出。提交前再次检查治理状态，队列内比较 unknown、时间、完整冻结输入及禁止恢复错误，再一次提交状态和完整 IDs。自审覆盖权限、事务失败、迟到 worker、并发变化、取消、预算和不含正文的诊断；未做独立同行审查。

## 限制与兼容

队列 receipt 完成只证明这次 SDK 写入及所列存储引用得到核对，不证明检索质量、全部客户端可用或一分钟 SLA。成功结果仍在但引用已消失、没有冻结输入，或现成记忆去重没有留下可核实 ID 时继续 unknown；不猜测“未写入”并自动重试。

实际存储测试确认公共 SDK get 无法读取 productivity 的经验 ID；现有治理预览也未覆盖其库。当前加上项目范围检测，存在这种数据即明确拒绝不完整预览。完整读取、来源关联和删除执行仍待实现。上游 coding_trace 的最近 100 次保留策略也不能替代本项目长期历史，仍须另行补齐。没有导入真实历史，没有修改日常 Agent、模型或 NAS 权限设置。
