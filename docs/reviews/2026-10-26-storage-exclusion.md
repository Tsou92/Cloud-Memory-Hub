# 服务与维护入口的存储互斥

关联 FR-10、FR-11、FR-13、ENG-01。设计及兼容边界见 [ADR-0013](../adr/0013-runtime-storage-exclusion.md)。这是实际治理执行和恢复前的进程保护，不是在线任务已排空的证明。

## 变更与自审

复用原有 CLI、私有目录验证和治理迁移，只增加部署层 POSIX 文件锁。serve 在构造 Core 前取得三目录租约；init／migrate 参与同一协议。锁文件无正文、凭证或 PID，不删除锁文件来释放锁。异常路径释放本次已取得的全部描述符；不安全文件不会被改权限、覆盖或替换。

检查 Compose 时发现 setup 原先只挂 config/governance；迁移新增 data 独占后，必须同时挂载真实业务卷。已补齐挂载，并让容器探针在确认 hub exited 后通过同一 setup 服务执行迁移。运行中第二个服务、初始化和迁移均须拒绝。

没有数据库／HTTP 协议变更，没有修改固定上游源码。旧镜像和直接 SDK 调用者不识别此协议，升级仍需观察旧进程退出；锁不检测任意外部程序，也不替代统一操作准入、在途结果核对和持久治理计划。本次为开发者自审，未进行独立同行审查。

## 本地验证

- `make check` 通过，包括 19 项工程门禁、格式／静态检查、文档链接和源码凭证扫描。
- `make check-runtime`：240 项通过，其中新增 8 项存储租约测试。真实子进程覆盖三个目录的竞争、不同存储独立、SIGKILL 后 OS 释放、部分获取失败后回退，以及实际 serve 运行时阻止不同端口的第二个 serve 和带声明的迁移。进程退出后迁移成功，原身份凭证未替换。
- 安全形态用例覆盖软链接、硬链接、FIFO、非私有权限和意外非空锁文件，验证未覆盖或替换既有文件。
- 按上游隔离 runner 执行 `test_backup_restore_api.py` 与 `test_hy_runtime_config.py`：12 项通过、分类完整。它验证上游运行时拒绝旧恢复入口及配置合同，不表示当前 SDK 的完整备份恢复已实现。

均使用合成数据和临时目录，未启用真实模型、修改日常 Agent 配置或导入真实历史。安装镜像和 NAS 验证将在后续补充；NAS SSH 当前返回认证前的 Connection refused，新镜像尚未部署。
