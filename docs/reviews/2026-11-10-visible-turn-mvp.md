# 当前轮自动共享与真实模型接续

日期：2026-11-10。关联 FR-01、FR-02、FR-03、FR-05、ENG-01。接续[两台 Mac 接入](2026-11-10-two-host-mvp.md)，设计见 [ADR-0050](../adr/0050-mvp-visible-turn-hooks.md)，使用方式见[自动共享说明](../agent-turn-hooks.md)。本轮只补齐 G2 日常使用链路，不扩展旧治理范围。

## 实现与复用

新增显式工作目录绑定的 Claude hook，复用固定上游 `_messages` 提取当前用户文字和最终回复，过滤后写入现有 LocalOutbox，再尝试远程接纳。下一轮通过原有 history-list 取得最近原文并注入有限、不可信参考上下文。无 transcript 回退、历史扫描、新存储或新上游补丁；NAS 无需启用模型提炼。

同一原生 session／prompt／角色和已绑定来源形成稳定身份，重放复用事件；网络失败保留待传状态，读取失败独立报告。旧 MCP 和 CLI 合同不变，新的可见消息使用既有 conversation_turn 形式，不伪称已提炼事实。

## 真实模型按 Skill 约定使用 MCP

另一项独立探针沿用 Claude 已有认证和模型设置，以临时设置关闭普通 hooks、自动记忆和普通 CLAUDE.md，限制为本次 MCP 工具，不读取真实历史、不复制凭证。Skill 正文作为 system prompt 提供，故该项不证明原生 Skill 发现。

真实模型在同一 session 完成三轮成功结果、10 次 MCP 调用、零工具权限拒绝：保存合成决定后 Mac mini 读到；Mini 写入未出现在第二轮提示中的新标记，Claude 重新读取并在答案中使用；第三轮模型保存并读取交接，Mini 再读取同一交接。

首次驱动脚本把过滤后的交接与未规范化输入直接比较，断言失败并退出 1，随后收尾终止 Claude 进程（143）；原始失败报告保留，**不改写为整次探针通过**。对同一交接进行只读复核，五个字段全部符合生产过滤结果，差异仅为既有 NFKC 全半角规范化。另存复核证据后修正新探针比较规则；没有为这次复核重新请求三轮模型。由此可确认上述真实调用与过滤后完整交接行为，不能声称字节原样保存或原探针正常退出。

随后另做一次原生 Skill 的只读真实模型验证：不再向 system prompt 注入 Skill 正文，仅允许 `Skill(cloud-memory-hub)` 和四个读 MCP 工具，明确禁用写工具。真实输出依次包含 Skill 成功加载、status、recent、handoff_load 和 search；交接各字段与前次过滤后回读一致，答案采用最新决定及确认标记。**20.983 秒通过，Claude 退出 0，零权限拒绝、零写调用。**它证明已安装原生 Skill 可被明确调用，不代表无需提示必定触发或六种宿主的逐轮自动保证。

## Codex 桌面对话的 Skill 备用入口

通用 Skill 增加了按需读取本机 `references/local-connection.md` 的约定；两机四份已安装 Skill 均已备份并更新，私有绑定只含稳定 CLI 和 Agent 配置文件路径，不含凭证，不进入通用包或 Git。无需搜索其他 Agent 配置即可使用 CLI。

当前真实 Codex 桌面对话在未显示 CMH MCP 工具时，实际读取了已安装 Skill 与本机绑定，使用稳定客户端完成 status、recent、search 及 Claude 交接的完整读取，再按读回的最新决定保存一份新的接续交接，NAS 返回 accepted。该链路是当前桌面对话的工具执行通过 Skill／CLI 接入，并非另启动 Codex CLI 代理，也不是桌面原生 MCP 调用证明。搜索当时为空，与 NAS 未开启提炼的状态一致，完整交接仍可按 ID 读取。

随后在 Mac mini 使用其自身现有登录和真实 Claude 2.1.319，以原生 Skill／MCP 读取这份 Codex 交接。首轮在 180 秒期限内已成功加载 Skill、status、recent、handoff_load，五字段完整匹配且包含隐藏确认编号，但模型未给最终结果；保留其 181.073 秒超时、收尾退出 143 及 partial 审计记录。事件包含持续 thinking 和一次 API retry，没有工具错误，不能据此断言特定网络或模型故障。

由于首次工具读取全成功、模型仍有进度，仅放宽独立只读复验的总期限为 600 秒，保留原模型、思考强度、认证和工具权限，不复制凭证。复验 **12.153 秒通过**：实际调用原生 Skill 和 handoff_load，五字段完整一致，最终 result 成功且答案包含绿色决定及未出现在提示中的 Codex 确认编号；无权限拒绝或写操作，Claude 与 SSH 均退出 0。两次运行的证据分别保存，没有将首轮失败改写为成功。

因此本轮验证了实际的 **当前 Codex 桌面对话经 Skill／CLI → NAS → Mac mini 真实 Claude 原生 Skill／MCP** 接续。它不证明 Codex 原生 MCP 或每轮必定自动调用；通用 Skill／CLI 是本次已验证的 Codex 路径。
