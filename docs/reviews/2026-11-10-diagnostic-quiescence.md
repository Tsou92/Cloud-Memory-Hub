# 2026-11-10 诊断后台写入排空

关联 FR-10、FR-11、ENG-01；设计见 [ADR-0040](../adr/0040-diagnostic-write-quiescence.md)。本地实现和验证已完成，安装制品仍待单独验收。

## 实际缺陷与修前证据

在固定上游及原 19 补丁中，HTTP purge 可以在 pipeline JSONL 的原生线程或 SQLite trace 的实际写入仍被阻塞时返回 completed。释放写入后，文件首次出现目标正文，或被删除的 SQLite 诊断行重新出现。只检查 asyncio 任务集合、取消代理 future 或等待一次当前 loop 的任务快照，都不证明线程已停止。

新增四条 HTTP 回归覆盖 JSONL/trace 和正常执行/取消后重试。修前在隔离导出的 HEAD Hub 与 19 补丁 SDK 上四条均失败：原生 I/O 尚未放行，purge 已实际返回 HTTP 200。首次误将新 Hub 与旧 SDK 组合运行导致接口缺失，只作为测试环境错误记录，不作为上述缺陷的负对照。

另四条搜索准入回归在原 SDK/Core 上均失败：两个原生搜索入口可绕过维护等待；取消等待方之后，尚未完成的搜索线程也未被全局维护准入统计。这些测试同时要求普通搜索继续并发，不能靠全部串行化消除问题。

## 实现范围与审查要求

复用原 pipeline wrapper、JSONL writer、SQLite cache、executor 和共享准入，为诊断任务登记真实完成状态。维护期间暂停新日志、排空真实任务与线程，再运行既有治理。原生搜索加入共享准入；关闭服务先处理诊断任务，并保留关闭失败后的对象以供重试。

设计独立审阅发现并纳入四项边界：冷启动先初始化治理桥再快照；暂停租约分别归还；关闭成功才释放完整所有权链；成功关闭永久封闭工作组，且每桥关闭等待同桥搜索。

数据库、治理签名、删除范围、一次性写入许可和用户选择的整条事件防重导入规则不变。新增观察仍不授予完整副作用治理权限。

## 审查、回归与修正

- 取消等待线程结果后，异常可能在屏障之外才输出：诊断路径分别保留原生 future 和 asyncio 结果消费票据，并使用不取消 inner future 的等待方式。独立 Python 3.12/3.14 反例确认晚异常被消费、真实完成前票据不归零；普通非诊断 executor 路径保持原行为。
- owner loop 尚未开始派发也必须被统计；跨 loop 私有反例观察到派发前 pending=1、真实线程执行时 pending=3，实际结束后才为 0。此项是受控线程实验，不替代数据库集成测试。
- runtime 资源已关闭但线程稍晚退出时，重试不再向已停止的 loop 投递关闭协程；同桥读取重入和同步关闭依赖当前 loop 的错误也明确处理。四条最新边界测试由独立代理再次运行通过。
- 首次 Hub 全量为 1104 通过、5 跳过、2 失败。其一是冷初始化在旧 Chroma 序列检查前写了 acquire_write；提取复用原只读版本/序列预检并前移，保留实际配置路径的二次检查与原“逐行不变”断言。
- 另一失败是空恢复也初始化 Chroma，使后续进程锁测试的文件句柄超过 select 上限。连续 12 个空实例实测：原路径始终 7 个句柄，过早初始化为 16 至 82；修复后恢复为 7 且不创建 Chroma。空执行记录在原恢复锁内直接结束，非空记录仍经过完整屏障并重读；未放宽原进程锁测试。上述启动/搜索/HTTP/进程锁组合 25 项通过。
- 探针最初泄漏进程内日志 handlers/levels/初始化标志。修复后对冷日志环境和已有配置环境各连续运行两次真实场景，原处理器对象/状态与旧文件字节保持，新文件句柄关闭，调用者处理器未收到合成正文。安装探针另用独立子进程。
