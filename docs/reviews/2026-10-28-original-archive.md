## 实现和复用

继续复用固定 Core 的持久任务、冻结输入、重放和终态清理，不另建处理队列。SDK staging Evidence 会释放，productivity trace 只留近期记录，两者都无法证明长期完整保留；在已有配置库的回执事务新增规范 Event 正文，接纳扩展升为 schema 2，语义记忆仍以 SDK 为权威。

历史读取复用既有设备项目授权和全文过滤／分块合同，以 `cmhe:<receipt UUID>` 读取归档。拒绝损坏原文的成功重放、状态查询和读取；来源停止写入不会删除已有历史。完整 typed output 来源链接与选择性治理仍待实现，现有待处理治理意图继续隔离整个实例。

## 本地验证

- 新增 13 项原文测试通过，覆盖成功／失败终态清理、完整正文与元数据、重启、同事件重放、队列已接纳但回执事务失败、原文／摘要／身份损坏、权限与项目隔离、处理中撤销，以及正确和不可证明的旧格式迁移。
- 保留明确失败路径：旧队列已清理、缺失、被改或丢失可选空对象的原始表示时，整个迁移回滚。测试没有用空正文制造通过。
- 存储互斥实际 CLI 测试覆盖在线服务拒绝 `migrate-originals`，进程退出后才允许维护；独立进程探针通过实际 CLI 的拒绝旧格式启动、缺少停服声明、回填、幂等验证，并在清理输入和重启后通过设备 HTTP 合同读取完整合成 Event。
- 最终完整运行时回归 320 项通过，包含扩展后的实际 CLI 互斥测试；39 条上游 utcnow 弃用提示，不是跳过项。固定上游 `tests/test_memory_server_durable_queue.py` 187 项通过；`make check` 的格式、静态检查、19 项工程门禁、路径／链接、源码凭证扫描及 Git 空白检查通过。

终态由测试直接设定，清理使用真实 Core 实现；没有激活外部生成模型，不能将其称为真实提炼质量或一分钟可用性测试。第一次新增测试的失败来自夹具目录权限和 API 格式化 JSON 的空白差异；已让夹具符合实际 CLI 的私有目录要求，并按 JSON 内容相等验证输出、按规范字节相等验证存储。
