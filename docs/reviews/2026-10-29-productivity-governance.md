# 工作记忆与原文治理观察验证

关联 FR-02、FR-08、FR-09、FR-10、FR-11、FR-13；设计见 [ADR-0019](../adr/0019-productivity-governance-inventory.md)。这是实现者自审，不是独立同行审查。

## 复用与实现

复用固定 SDK 的 SQLite、四个 Chroma 集合、记录解码及访问线程；经验／事实／索引副本／共享 trace 加入已有方向性规划器。已接纳原文和输出关系由 OutputLineage 在同一配置事务合并，核验完整集合而非普通展示引用。没有新持久 schema、writer、队列或执行路由。

保留事实演化和两端任一明确记录的事实到经验关系；共享经验的其他来源不被反向扩张。向量副本作为独立对象纳入范围，避免 SQL 记忆已更新时漏掉索引中旧正文。缺失、跨项目和损坏关系明确失败。原文、逻辑记录、轨迹与副本在合并后统一受记录、关系及字节预算限制；SQLite 正文在读出前先核对总量。

仍缺少精确请求关系的编程改动链保持显式拒绝，不再把所有 productivity 数据一概拒绝，也不把该限制称为删除功能完成。所有预览仍为不可执行的观察。

## 本地证据

- 完整运行时回归 346 项通过，87 条上游 utcnow 弃用提示，没有跳过项；新增 12 项真实 SQLite／Chroma 集成测试。
- 覆盖两个变体、同原生 ID 的经验／事实隔离、仅有反向字段时仍恢复正确方向、共享经验不吞并独立来源、原文及 trace、索引副本、重启和无 writer 初始化、管理员权限、分页变化、整体缺失链接、错误类型／摘要、无效引用／状态、缺失集合、无法映射的链以及合并后的扫描预算。
- 固定上游 `tests/coding/test_store.py` 的 41 项回归通过。原有图／向量独立进程探针通过，保留来源指针、旧版本、归档派生、跨项目和底层失败拒绝验证；探针不宣称完整治理通过。
- 增强错误类型和仅反向字段断言后的 12 项集中测试再次通过。独立进程来源探针已增加管理员范围预览，在清理冻结输入并重启后仍能从五种输出查看归档及 productivity 索引副本。
- `make check` 的格式、静态检查、19 项工程门禁、文档链接、路径和凭证扫描通过。

第一轮全回归仅旧“有工作记忆就必须拒绝”断言失败，已改为检查实际类型化记录和关系；新增测试初次的集合删除夹具遗漏了 SDK 的维度后缀，已复用 ChromaVectorStore 的实际集合命名修正。没有放宽产品路径以制造通过。
