# 网页彻底删除入口

日期：2026-11-13。关联 FR-10、FR-11、FR-12。补丁 `0052-hub-console-purge.patch`。

## 问题

需求第 6、7 节要求明确区分「忘记」和「彻底删除」两种操作。后端 `/hub/v1/governance/preview` 与 `/execute` 的 `action` 字段本来就接受 `forget` 与 `purge`，执行器对 purge 有完整路径（SDK、原文副本、快照分段处理）并对不支持的类型显式抛 `governance_purge_kind_unsupported`。但网页只发 `forget`，并在末尾写「网页暂不提供此操作」——承诺的第二种操作只存在于 HTTP 接口。

## 实现

复用现有治理合同；不新增接口、协议或存储。

- **动作选择**：影响范围面板新增「处理方式」单选（忘记／彻底删除）。切换动作会清空已勾选的确认并重新预览，因为两者证明范围不同、`view_digest` 也不同。
- **执行门槛**：与忘记共用同一套 `eligible`（预览完整、无 unsupported 记录、无缺失来源）。绝不放宽：证明不完整时按钮保持禁用，服务端仍会二次校验并可能拒绝。
- **待核对操作**：`pendingKey` 与 `readPending` 按动作区分，避免把忘记的回执当成 purge 继续执行。旧版本写入的 `cmh-forget:` 键仍能被读取（否则升级前中断的操作会丢失），成功或重启时通过 `clearPending` 一并清除两个键。
- **文案**：按当前动作切换标题、确认声明与说明；彻底删除明确写「正文不可恢复」和「无法证明可清理的范围会被拒绝」。忘记页保留一句指向彻底删除的说明，不再声称网页不提供。

## 验证

- `HubGovernance.test.tsx` 新增两项：切换彻底删除后标题、预览动作、提交动作与 `record_ids` 正确，完成时清除 purge 键；默认动作仍是忘记，确认文案未被误改。
- `hub-governance`、`HubGovernance`、`HubConsole` 三处合计 33 通过；完整网页套件 **2163 通过、10 跳过、2 失败**——两项失败是 `workbench-tags.test.ts`（中文标签排序，未改动的基线上同样失败）。
- `tsc -b` 通过；50 个补丁从干净检出准备通过，叠加后 3 个文件逐字节一致。

## 边界与未覆盖

- 支持范围仍受服务端约束：生产力／编程记录（`cmhp:`／`cmht:`／`cmhc:`／`cmhv:`）的物理删除未实现，服务明确拒绝，网页显示拒绝原因而不假装完成。
- 旧诊断日志、Docker 宿主日志等域外副本不在本次范围。
- 批量选择与 purge 的执行进度可视化未做；仍是一条记忆一次确认。
