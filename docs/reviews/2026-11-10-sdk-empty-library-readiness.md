# SDK 空记忆库测试的首次加载等待

2026-11-10。关联发布计划 R1-02（网页数据状态真实）和 R3-05（可复现构建与发行检查）。

## 失败与根因

提交 `c95f21e` 的[正式制品构建](https://github.com/Tsou92/Cloud-Memory-Hub/actions/runs/42797854686)
在 `quality / runtime` 的网页回归阶段失败：
`MemorySpace.sdk-start.test.tsx` 第 36 行找不到“共 0 条”。当时为 338 项通过、1 项失败；
正式 Linux、Mac、汇总与发布任务均跳过，没有生成 `verified-release`。这不是镜像回执校验失败。

补丁 0004 的旧测试只等待 `role="status"` 不存在。补丁 0028 将 SDK 记忆库的初始总数
从 `0` 改成 `null`，正确区分“尚未读到结果”和“结果为空”，但旧测试未同步等待条件。
组件首次挂载时为 `busy=false、total=null`，已经有记忆库区域、空计数提示和空列表，
加载提示尚未出现；随后 effect 才启动 SDK 请求。因此“没有加载提示”既可能代表尚未开始，
也可能代表已经完成，不能作为首次读取成功的证明。CI 失败时的 DOM 正是这一初始状态。

## 修复范围

只调整[补丁 0004](../../upstream/patches/0004-show-sdk-library-on-first-open.patch)中的测试：
先等待明确的成功结果“共 0 条”，再断言加载提示不存在、列表项为零。
保留页面说明、两个入口标签及不调用旧记忆库接口的断言；其他两个测试保留。
组件实现、请求行为和界面样式均未修改，补丁清单摘要同步更新。

## 实际验证

使用合成数据和隔离 HOME，在私有源码副本中观察真实组件的首次挂载。
authority 响应延迟 20 ms，SDK 响应延迟 150 ms；通过 MutationObserver 在首次记忆库区域
出现时评价旧等待条件，没有修改组件或缩短请求流程。

- 本机 Node 22.14.0 / Vitest 4.1.11：未控制调度的原三项测试单次通过，不宣称原测试每次必败。
- 三轮受控观察都记录到：SDK 尚未调用、加载提示不存在、总数不存在、计数提示为空。
  原负向等待在 SDK 响应前结束，三轮均在总数断言处失败；等待正向结果则都在响应之后完成，三轮均通过。
- 修复后的原三项测试通过；单文件 Biome 检查通过。
- 项目原有 `make check-web` 通过：固定 Node 24.10.0 / Linux amd64 Docker，17 个文件、339 项测试全部通过。
  该流程包含 TypeScript / Vite 构建及原来的全部网页测试选择，未降低检查门槛。
- 独立只读复核确认组件补丁内容未变、断言未弱化，补丁摘要与清单一致。

本记录证明此次测试等待修复及本地 Docker 回归，不代表后续正式 CI、发行附件或 NAS 制品验收已经完成。
