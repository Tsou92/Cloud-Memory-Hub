# 面向自行部署的发布准备度审计

关联 FR-01、FR-02、FR-04、FR-05、FR-06、FR-10、FR-11、FR-12、FR-13、ENG-01。审计基线为 `1279f1b`，不把后续修复计划计为当前能力。执行顺序与退出条件见[发布计划](../release-plan.md)。

## 目标与结论

用户已要求按上线发布标准逐一完善：通过 GitHub 获取 Cloud Memory Hub，其他用户能够自行部署到 NAS，在网页中完成配置并接入自己的 Agent。既有独立产品主页项目 `Memory-Hub-Website` 也纳入完善与 Vercel 重新发布范围。此前“由维护者完成两台 Mac 安装后可使用”的 MVP 交付，不等同于此目标已经完成。

现有跨设备读写、通用 MCP／Skill、任务交接、部分真实宿主自动采集及模型提炼有实测证据，继续复用。当前阻断集中在三个方面：网页没有接入实际 Hub 项目；忘记后仍可能进入自动召回；安装、配对、备份恢复和发行流程需要维护者手工完成。不能把服务健康、页面可打开或模型列表可获取单独作为发布通过依据。

首版应通过本文和发布计划中的有限门槛。六入口完整自动化、离线读取缓存、全部历史导入和复杂全域日志治理仍保留为后续需求，不作为首版所有功能的共同前置。用户确认的自动定期备份、版本回滚及手动完整导出导入有明确发布阶段，不因 MVP 收敛而被删除。

本记录只保存合成复现描述、代码路径和脱敏结果，不附真实记忆、模型凭证、个人连接配置或备份。临时复现附件保留在审查现场，不以个人临时路径作为公开复现入口；后续修复应将必要的合成回归纳入仓库，并补齐红转绿记录。

合成复现依次执行：创建非空普通记忆与原文 → 管理员预览并完成忘记 → 请求 `history-list` 和 `memory-search` → 调用实际 `_recall` 并比对返回正文 → 请求旧网页 DELETE 路径。脱敏结果为：忘记 completed、语义搜索排除目标、原文仍出现在列表、同一原文正文进入 hook 上下文；旧 DELETE 返回 `409 governance_workflow_required`。测试显式阻断网络，模型为合成替身，`browser_tested=false`。这是缺陷复现成功，不是功能验收通过。

## 发布前必须修复的产品问题

| 编号 | 当前状态与具体证据 | 发布要求 |
| --- | --- | --- |
| RR-01：忘记后自动召回（P1） | **已实现但行为有缺陷，已合成复现。** `apps/hub/src/cloud_memory_hub/remote_read.py` 的 `_read` 把 `history-list` 和 `history-get` 都当成可读取忘记原文的历史访问；`agent_hook.py` 的 `_recall` 每轮自动请求 `history-list`，导致原文被带入上下文。 | 分开用户主动追溯和自动召回的用途。忘记后搜索与下一轮自动上下文都不含目标内容；用户明确查看原文仍可读。修复涵盖分页、重开进程和无关内容保留，不扩大为全部旧日志物理删除。 |
| RR-02：网页与 Hub 数据脱节 | **后端能力已有，网页未接通，真实页面已观察。** 首页记忆为 0、同步尚未开启、应用为空；记忆库和历史为空。上游网页使用 `local` 用户空间，而 `remote_read.py` 使用 `cmh:<instance>:<scope>`；“问记忆”也未接入实际 Hub 项目。 | 网页显式选择已授权项目，与 Agent 读取同一权威数据；计数、列表、原文、来源和问记忆一致。无权限、加载失败和确实为空必须区分。不能仅替换名称或计数来制造通过。 |
| RR-03：网页治理入口 | **治理机制已有，当前网页入口未接通。** 独立审查实际旧 `DELETE` 请求返回 409；`boundary.py` 明确拒绝会重新激活旧版本、保留历史的上游删除路径。 | 复用 Hub 预览与确认流程；成功结果须与实际生效一致。没有完整证明的类型保持拒绝，并在提交前说明可用范围，不把 409 改成成功，也不要求本阶段完成复杂全域日志治理。 |
| RR-04：网页配对和状态 | **设备／来源／授权接口已有，自助网页流程未接通。** “连接其他应用”展开后仅提示“本机配对仅在桌面 App 可用”；帮助页自动启动不可用，无法通过网页完成 NAS 产品的接入闭环。 | 新用户能够创建项目、配对独立设备、取得适用的 MCP／Skill 安装指引，查看最近连接、待传／拒绝／失败状态并撤销设备。NAS 网页不能依赖不存在的桌面本机配对能力。 |
| RR-05：产品身份与运行状态 | **配置和展示不完整，真实页面已观察。** 浏览器标题仍为 MemHub，底部为“本地存储”，帮助页显示 `development`／`build development`／`commit unknown`。 | 明确显示 Cloud Memory Hub、当前服务位置、版本和构建来源；状态来自实际服务。保留应有上游署名，移除或解释不适用的桌面功能。 |

RR-01 是已有“忘记”承诺的正确性缺陷，不能后置。RR-02 至 RR-05 是自行部署后能否使用网页的直接缺口。现有管理网页的可复用布局、模型表单和 SDK 展示组件应继续使用；项目与权限应通过 Hub 权威边界接入，不由前端拼接用户空间绕过授权。

## 不得混称完成的事项

- 模型候选获取通过，不等于真实项目网页和所有候选生成调用通过。
- MCP 探针、CLI、Skill、实际宿主 hook、真实模型回答分别计证；Codex 桌面原生 MCP 及其自动逐轮调用不能由 CLI 结果替代。
- 永久拒绝项已终止且后续合法项继续，不能代替客户端删除规则广播或离线读取缓存。
- 保存旧镜像、复制单库、手工三卷归档、schema 迁移备份，均不能单独证明完整导出导入或灾难恢复。
- 新日志不含正文不代表旧日志已清理；未知来源恢复的安全拒绝不等于完整恢复已完成。
- 文件存在、质量工作流定义、历史测试计数，不等于目标发行提交和目标平台已通过。
