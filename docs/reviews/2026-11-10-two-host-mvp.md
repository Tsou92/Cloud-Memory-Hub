# 两台 Mac 共享记忆与交接 MVP 验收

日期：2026-11-10。关联 FR-01、FR-02、FR-03、FR-05、FR-14、ENG-01；接续[通用 Agent 入口验证](2026-11-10-agent-access-mvp.md)。本轮验证真实跨机网络和 MCP 工具链，产品仍处于 G2 接入验收阶段。

## 客户端与网络

用户授权 SSH 后，MacBook 与 Mac mini 分别在稳定路径安装 `1419979` 客户端。两端均为 arm64，Mac mini 为 macOS 27.0；平台事实来自本机证据及实际 SSH 核对，不是由探针中的设备 ID 推断，也不采集硬件指纹。

两台 Mac 各有独立设备身份、来源和本地队列，绑定同一个 NAS 项目。NAS 的 Tailscale HTTPS 入口已启用，两端均通过证书校验和授权读取，HTTP 状态为 200。连接配置、具体域名、地址与凭证留在私有配置，不进入仓库。

Mac mini 的系统 DNS 起初错误地把 NAS 名称查询送往公网 DNS。用户执行了已准备的 sudo 脚本：备份旧状态，仅在 `/etc/resolver` 为 NAS 完整域名增加规则，指向该机器现有的 Tailscale DNS。变更后，系统解析和经证书校验的 HTTPS 授权读取均通过；没有改成全局 DNS 替换。

## 真实两机 MCP 结果

[probe_two_hosts.py](../../scripts/probe_two_hosts.py)在 MacBook 启动本地 MCP，并经 SSH 在 Mac mini 启动另一 MCP 进程。两个进程分别使用自己的私有配置直接访问同一 NAS HTTPS 服务；SSH 只承载远端进程的标准输入／输出，**不转发 Hub 连接**。

| --- | --- |
| 两端已安装 MCP 初始化并公布七个工具 | 通过 |
| 同 Hub、同项目，设备与来源相互独立 | 通过 |
| MacBook 保存后 Mac mini 读取新原文 | 通过 |
| Mac mini 保存后 MacBook 读取新原文 | 通过 |

报告为 `status=passed`，总耗时 **9.549 秒**。这是包含前置检查和全部七项流程的总时长，**不是单次同步延迟**；本轮没有将其当作一分钟目标的性能统计。正文均为合成样例，长交接按完整内容比较，未以第一页或摘要替代。

探针报告明确 `physical_host_identity_verification=external_to_probe`：两台实体 Mac 的事实由前述独立平台核对提供。实际运行使用两台主机；将相同测试逻辑放到单机运行，不会因此证明双机网络。探针及本轮证据已通过独立只读审查。

复用方式如下，私有配置格式见脚本说明；它要求已经配对的两个客户端，不创建项目、签发设备或修改 Agent 配置：

```sh
/path/to/runtime/bin/python /path/to/probes/probe_two_hosts.py \
  --config-file /path/to/private/two-hosts.json
```

同目录需保留 `probe_agent_access.py`、`probe_claude_recall.py` 和 `probe_claude_native.py` 三个现有辅助脚本。正文通过工具输入传递，连接凭证从各端私有文件读取；不将个人路径、地址或凭证写入公开报告。

## 服务状态与未验证范围

NAS 新 MVP 服务保持 healthy，旧验证服务保持不变。本轮未启用模型，探针也没有请求 Agent 模型自行决定调用工具；它证明两台 Mac 上的 MCP、授权上传、原文读取和精确交接链路，不能直接记为真实 Agent 自主调用或已有聊天下一轮自动召回。

用户明确授权两台 Mac 接入后，已在两端的 Claude 用户级 JSON 和 Codex 桌面配置 TOML 中新增 `cloud-memory-hub`，合计四处 MCP 配置；对应四个 Skill 目录也已安装。每台 Mac 在变更前备份两个配置文件。前后比较确认原有 MCP 完整保留、Codex 其他设置一致，Claude `settings.json` 的 SHA-256 不变。两机 `installation-report` 均为 passed；真实凭证、安装路径和备份只留在各机私有目录。

安装后，两台 Mac 分别使用真实 Claude 的 `mcp get cloud-memory-hub`，以及 Codex 桌面内置 CLI 的同名查询回读配置，四次查询均退出 0。已安装 Skill 核对一致，查询前后配置未变。此项只证明原生客户端命令能读取配置，不是 Codex 桌面实际工具调用或模型自主使用的证据。

另从当前 Codex 桌面对话调用已安装 CLI 保存合成交接，再经 SSH 调用 Mac mini 已安装 CLI 读回。两端各字段一致，且与现有凭证过滤流程的 NFKC 规范化结果一致；该流程会将示例中的全角逗号、冒号变为半角，不能声称输入字节原样保留。重试沿用同一请求 ID。示例编号和完整结果仅保存在私有安装目录。

配置安装不等于模型已自主调用。后续计算机操作检查中，工具以安全原因拒绝控制 Codex 桌面，该检查已结束；本轮没有取得桌面原生 MCP 调用证据，不以配置文件、CLI 元数据或上述 CLI 备用路径代替。真实宿主的自主工具使用与同会话更新仍待验证；此前 Claude 模型替身探针的有限结论保持不变。
