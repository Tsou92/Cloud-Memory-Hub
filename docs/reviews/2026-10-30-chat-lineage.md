# 普通聊天历史来源接线

关联 FR-08、FR-09、FR-10、FR-11；设计与兼容性见 [ADR-0024](../adr/0024-chat-input-evidence.md)。

## 实现与审查

历史快照通过独立附加表与原有产出、上下文、reconciliation 输入同事务保存；旧输入信封保持不变。复用原文重建、精确 raw 产出索引、摘要和预算检查，复用固定上游 `ChatMessage`、`WriteRequest` 和工具消息过滤规则核验完整正文及身份。只接受原请求完整或原生聊天回退两种精确渲染，不以文本相似性猜测生产者。缺标记可以通过精确产出核验，重复生产者、错误正文／身份、未知来源和不完整捕获拒绝发布来源。

`cmhj:` 阶段保留捕获副本，只让语义记忆依赖历史输入；当前独立原文及 L1 副本不被反向挂到旧来源。缺字段保持未观测；只从已完成 SDK 持久结果补档，不再次写入或调用模型。沿用既有配置卷、事务、扫描预算和读权限，没有新服务或队列。

顺序自审确认：Core 的 agent 身份实际包含来源、日期和工作区，纠正了跨来源测试最初的错误假设。实际验收分别覆盖同来源同日跨 session 的输入关系，以及不同来源历史隔离；不将此表述为跨 Agent 自动注入完成。该事实未改变双向通用接口和跨设备共享的产品需求。

## 当前验证

本地 Hub 487 项测试通过，含新增 15 项来源用例；269 条警告来自上游弃用 API。覆盖重启与任务载荷回收后的读取、管理员预览传播方向、来源／会话／项目隔离、正文／身份／摘要损坏、缺失和歧义生产者、自引用、失败／超限捕获、事务全回滚、完成任务补档及旧字段缺失。

`make check` 通过格式、静态检查、19 项工程门禁、路径、链接及凭证扫描；`make probe-chat-graph` 通过三个独立进程的真实 SDK 存储与 HTTP 读取／预览。提炼采用合成结果，使用上游 direct-store 选项；没有调用外部模型，不能据此证明模型质量。CI 已增加探针，但没有远程 CI 执行证据。

本轮 NAS 初检免密 SSH 正常，原镜像 `dae8cae` 为 running healthy。新版镜像、旧版往返和 NAS 升级的验证待完成后补记，不能用本地结果代替。
