# 用量展示与跨项目检索措辞

日期：2026-11-13。关联 FR-14、FR-03、FR-09。

## 用量展示

需求 §9 要求展示外部模型用量与费用。Core 已有的 `model_request_audit.py` 会为每次
提炼记录请求数、成功/失败/进行中与 token 合计，但控制台从未读取。

- 新增 `GET /hub/v1/console/usage`（`console_api.usage_routes`），复用同进程的
  `core.state.model_request_audit_store.report()`，只返回计数与 token 合计，不含
  prompt、响应或供应商身份以外的内容。审计存储不可用时返回 503，不显示 0。
- 设置页新增「用量」分组与 `HubUsage` 组件：模型请求数、成功/失败、进行中、
  输入/输出/合计 tokens，可手动刷新。
- 明确写着「不是账单，provider 账单为准」「网页问答尚未计入」「历史导入与多模态
  未实现」。不估算金额——模型提供商与计费方式尚未选定（需求 §9 同款限制）。

## 跨项目检索措辞

需求 §3 的「按需跨项目检索」不等于「任意项目互相检索」：ADR-0004:23、
ADR-0008:9、ADR-0057:13 与 `remote-read.md:7` 都要求每次请求只接受一个明确项目或
`global`，不默认合并。因此本轮**不做**「全部项目」入口，改为把规则写清楚：

问记忆页在「只查找当前项目的记忆」后补一句——通用偏好在顶栏切换到「全局偏好」
再提问，项目之间不会自动合并内容。

## 验证

- `HubUsage.test.tsx` 4 项通过：展示计数与 token、不编造价格、服务不支持时明说
  而非显示 0、手动刷新。`R6Settings`、`HubQuestion` 回归合计 17 项通过。
- `tsc -b` 通过；53 个补丁（含本补丁）从干净检出准备通过，叠加后 5 个文件一致。
- 后端受影响的 `console_read`／`remote_api`／`media_guard`／`source_capture`／
  `admin_credentials` 共 56 项通过；2 项失败为嵌入模型缺失，在未修改的
  `origin/main` 上同样失败。
