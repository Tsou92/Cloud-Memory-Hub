# 在途任务只读候选清单

日期：2026-11-09。关联 FR-10、FR-11、ENG-01；承接 [ADR-0034](../adr/0034-inflight-ingest-and-content-reimport.md) 与[候选设计](../research/inflight-candidate-inventory-2026-11-09.md)。本切片不接入 execute/resume，不取消任务、清理正文或改变 SDK 状态；不能当作 G-A/G-C 或完整删除恢复已完成。

## 实现与复用

从既有原文迁移提取纯 footer 还原和 frozen 请求比对，复用 `EventEnvelope`、`write_request`、`validate_original`，不以虚构回执证明队列曾被接纳。比对仍仅豁免原有 event_at/time_quality/priority。Purger 的元数据归属检查与新清单共用 `verify_request_owner`；合法 active/revoked 来源都保留历史所有权。job/source/device/instance/event/project 身份加强为既有规范 UUIDv4 格式，global 项目例外；此前可能仅字符串相等但格式损坏的数据现在明确拒绝。原有原文与 purge 错误码合同保留。

清单复用固定上游 main_database、WriteRequest、终态集合与 reaped marker，不增加表、协议、状态机或模型调用。内部范围值复制并冻结 records/rules；它不是客户端授权凭证，生产调用者仍必须在治理、Drain 与接纳独占区内完成权威范围核验。本轮尚无此生产接线。

观察先查来源和回执元数据，再按来源、回执、请求以及确认的 cmhe 锚点查任务并去重。全局非终态审计仅用来源／请求前缀及元数据找无归属任务；其他项目和无归属任务不读正文。元数据与正文均先在 SQL 中测字节、检查预算，再读取值；任何预算超限中止整个观察，不能返回部分结果声称完整。两个已有库采用固定顺序的只读快照，Core reader 不嵌套借用。

已确认 cmhe 与仅来源／内容命中的任务分组，额外修订不得升级成已确认原文。非终态损坏正文、未知状态、缺规则等产生固定原因 blocker。严格的原生终态清理标记可作为 identity-only 候选，仍不证明 SDK 是否曾写入；所有候选的 sdk_effect 始终为 not_checked。带真实回执的终态先核原文身份和规则，再保留该边界。

## 实际验证

新增共享校验专项与既有 original_archive/purge_recovery 定向组合 84 通过。覆盖 footer、消息顺序、冻结字段、规范身份、非法元数据、撤权来源、真实接纳事务失败后的 queue-only 回建，以及真实回执损坏时的错误优先级。

候选基础和独立边界联合 19 通过，使用真实 Hub、HTTP、Core 队列和 SQLite 文件，未调用外部模型。包括确认版本去重、额外修订和换身份同内容分组、无回执队列、来源撤权、归属／原文／冻结输入损坏、终态清理身份、未知状态、旧规则缺失与数量／字节预算。观察前后数据对比及 SQLite authorizer 检查没有业务写入；其他项目与无归属任务的正文列访问被禁止，观察仍正常返回。

独立快照负对照仅在内存移除 Core BEGIN：同一测试在元数据和正文之间由第二连接实际改写，产生 payload_unproven 并失败；正式代码通过。审查另发现 owner 的宽泛异常转换会吞掉外项目来源补查的预算超限；新增两项测试先失败，修复后通过，确保不会把部分扫描当完整结果。

共享校验、候选、原文、来源抑制与治理请求定向组合 152 通过。统一 `make check-runtime` 为 **920 通过、5 跳过、6 个既有在途缺口预期失败、289 条上游弃用警告**；`make check` 通过。可选后端跳过和仍未解决的成功验收场景不算通过。两轮独立代码审查未见新的阻断项。

## 未完成边界

- 数量／返回字节预算不等于数据库扫描时间或内部 I/O 上限。全局前缀审计不声称能识别两个身份字段均失去 Hub 前缀的任意损坏行。
