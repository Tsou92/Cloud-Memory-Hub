# 内容重导入与治理期间任务协调

日期：2026-11-09。关联 FR-10、FR-11；按 [roadmap](../roadmap.md) 的 G1 删除恢复退出条件推进。[ADR-0034](../adr/0034-inflight-ingest-and-content-reimport.md) 仍分步实现，本文不代表在途清扫或 G1 已完成。

## 行为与兼容

用户已确认：任一消息经 NFC 和空白规范化后至少 16 字符且命中忘记/删除规则，拒绝整个事件。治理时从校验原文生成来源与内容规则，随原签名意图保存；使用原 HMAC 目标和独立策略标记，不增加数据库或列。内容先在内存计算 SHA-256 再包装 HMAC，避免合法长转义文本超过目标身份上限；治理目录不保存原文或裸摘要。

旧 forget 从保留原文重建；其中被后续带当前策略标记的签名操作覆盖的原文，可直接复用已存规则，只重建剩余部分。未覆盖原文缺失/损坏或旧 purge 无法证明规则时拒绝，不改写旧意图。策略标记证明全短消息也已执行采集。物理记录和规则合计超过 10,000 项时拒绝，不截断。

补丁 0018 复用 Core Drain 的 claim、续租、执行与产出观察，只暂停领取并等待完整 worker。claim 在线程中提交后，即使调用者重复取消，也先登记并等待 worker；取消治理等待者不取消 worker。维护回调在领取锁外，治理不等待可能调用 resume 的 Drain 主任务。

Hub 保持恢复锁 → 暂停领取并等待 worker → SDK/接纳独占的顺序。上传只在实际接纳阶段持共享准入，复用线程等待；请求取消仍等入库线程结束。维护期间新上传返回可重试的 503。启动 ready 仅影响 claim，原治理完整性与持久待执行意图检查仍在每次来源授权中保留。

## NAS 制品与升级

镜像为 `cloud-memory-hub:dev-60ad0ce`，修订 `60ad0ce3619954b296759c95d11599a625b8ae6a`，配置摘要 `sha256:c5bd25b83ba8c0abd579cd96c6cfa1fe3d39ab807ec83d76f5dfe22fe725e36f`。导出包 261,281,280 字节，SHA-256 `9a375124ed060b7e16f8065ab10ef86686dad83f460f4946fa34df04c6b24d85`；传输及安装后核验一致。补丁仅空白上下文行格式归一化，固定上游及全补丁校验证明结果源码不变。

常驻实验实例再次验证为空后，从 5b54fe0 停服升级。三份卷和部署配置均先备份、校验归档可读性及摘要；升级后和再次重启均健康，身份、凭证、挂载、数据库版本及回环网络边界保持。继续使用 3 GiB/2 CPU、只读根目录和移除全部额外能力；未修改 SSH、未接管 Agent 配置、未启用收费模型或导入真实历史。

本次未做旧镜像回退演练；备份存在不等于已证明旧版可安全运行新治理规则。后续清扫实现仍需独立兼容评审和恢复验证。
