# 客户端只读处理进度验收

关联 FR-01、FR-02、FR-07、FR-12、R2-04；设计与兼容边界见
[ADR-0062](../adr/0062-client-processing-status.md)。本次证据来自本机源码测试与真实本地 HTTP，
没有部署到 NAS，没有联系第二台 Mac，没有修改日常配置或读取日常队列。

## 行为与复用

Hub 事件回执复用固定上游持久任务的 `created_at/updated_at`，增加
`server_enqueued_at/processing_updated_at`。数据库与协议版本不变；旧 Hub 缺少时间字段时，
新客户端保留处理状态，时间为 `null`。

`cloud-memory-setup status --check-remote` 先验证当前设备、项目与来源授权，再 GET 查询
当前项目／来源按本地入队顺序选出的最多五条事件。选中行内部验证绑定、摘要与过滤规则，
返回元数据而不返回正文。终止拒绝项不进入样本。客户端不发送待传事件、不确认接纳，
也不新建状态缓存；本地待传而服务器已接纳的差异会保留并明确展示。

仅收到精确的 `event_not_found` 才可对待传项显示没有回执。本地已接纳项找不到回执、
未知路由、权限问题和网络失败都保留为异常。部分查询失败保留其他已验证结果，CLI 返回
非零退出码。最多并发两个请求，共用二十秒样本查询期限。

## 本机回归

- 新状态测试与既有 `client_setup`、`transport`、`remote_ingest` 测试合计 **118 项通过**。
  覆盖旧 Hub、作用域／来源隔离、五项上限、终止拒绝排除、非法 JSON、重复键、摘要和绑定
  损坏、伪造回执、无效时间／状态、部分失败、空样本、CLI 退出码、并发与总时间上限。
- 永久拒绝及本地投递回归合计 **70 项通过**。共用的有界错误响应解析仍只承认精确拒绝码，
  不将其他 HTTP 错误误认为永久拒绝或事件未接纳。
- 合成私有队列在状态查询前后逐字节一致；请求记录全部为 GET。输出不含源正文、设备
  凭证或远端额外正文。既有本地数据库版本不变。
- 本地 TCP 测试实际运行 Hub 事件接口与持久队列，先上传合成事件，再通过测试准备操作
  将任务置为 `completed`。状态查询返回的两个时间与原持久任务字段一致；查询后队列
  字节与已上传计数不变。这里的 `completed` 是合成任务状态，**没有调用真实提炼模型**。
- 本次文件的 Ruff 格式、静态检查与 `git diff --check` 通过。工作树包含同期备份功能修改，
  完整 `make check` 由主任务统一执行；本记录不将其他功能的检查计入本次证据。

首次补充回归命令误用了不存在的 `test_local_outbox.py` 路径，未运行任何测试；更正为已有的
`test_local_delivery.py` 后得到上述 70 项通过结果，未将无测试运行计为通过。

独立只读审查未发现可复现的 P1/P2 问题，核对了采样绑定与摘要、处理状态枚举、GET-only、
未知／缺失回执、部分失败、旧 Hub 兼容及安全输出。审查者未重跑测试，以上测试数量来自
实现者的实际运行，不作为第二份独立测试证据。

## 结论边界

样本最近首次入队时间和最近已完成任务更新时间，仅描述这最多五条本地事件，不代表设备
全历史最后成功时间。`completed` 只表示服务器持久任务完成，不证明记忆提炼质量、检索
可用或另一设备已读取。真实 NAS、真实外部模型和第二台设备的新版状态验收尚未执行；
本次没有重新构建或发布客户端安装包。
