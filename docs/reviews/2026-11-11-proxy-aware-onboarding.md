# 代理环境接入修复验证

日期：2026-11-11。关联 FR-02、FR-03、FR-07、FR-12、ENG-01；设计见 [ADR-0068](../adr/0068-proxy-aware-agent-onboarding.md)。

## 根因与修复

旧安装器以强制直连完成验证，实际却给宿主写入原生 HTTP MCP。真实 Mac 的 Claude 继承了代理但没有该 NAS 的绕过规则：相同设备身份直连初始化成功，经过代理则 TLS 失败；只给该 NAS 的精确域名与地址补充绕过后，真实 Claude Code 2.1.322 的单目标 MCP 检查显示 Connected。此次检查没有调用记忆写入，也没有改变其他代理、MCP 配置或系统网络。

产品默认继续使用原生 HTTP MCP。连接器支持 auto／environment／direct，先以无凭证健康请求确定线路；只有直连可用、宿主路径仍冲突时，在领取身份和写入配置前返回待处理状态与具体引导。已有身份／进度保留，POST 不自动换线重放。HTTP 回环始终直连；HTTPS 保留证书验证。

第一层安装脚本与后续组件下载也支持环境路径失败后对同一 Hub URL 直连回退；Hub 不跟随跳转，外网运行时下载继续沿用原代理与摘要验证。Clash／Shadowrocket 的精确规则、NO_PROXY、重启与验证步骤见[完整指南](../proxy-and-network.md)。当前环境只能经代理访问时，不引导用户错误地关闭代理。

## 本机验证

- 连接器及网络策略共 56 项，1 项既有 Windows ACL 跳过，其余通过；测试覆盖无代理、代理必需、坏代理但可直连、全部失败、只读探测与 POST 不重放、精确规则和已有进度恢复。
- 真实 TLS／CONNECT 代理 fixture 证明：仅代理可达的 HTTPS 来源可初始化健康路径；坏代理而仅精确测试域名直连可达时只返回待修复，不发送邀请或凭证。证书由本次测试临时生成、校验并清理，没有降低生产 TLS。
- POSIX 下载组件 7 项、复制命令 4 项实际执行通过；两个下载层均覆盖代理必需、直连回退、失败恢复、禁止跳转及参数边界。
- 管理员 API、公开安装资源及真实 Hub 独立连接／重试／撤销组合 24 项通过。
- 独立只读安全审查提出的 IPv6 zone 恢复指令注入和原始 HTTPException 诊断越界均已修复；同一测试反例验证固定错误及不泄漏凭证。

## 限制与失败记录

本机没有 PowerShell。PS7、Windows PowerShell 5.1、Windows ACL 与固定运行时下载等专属场景在本机明确跳过，依赖跨平台 CI，不算作本机通过。GUI 宿主是否继承了安装终端的环境仍不能仅凭连接器断言，状态明确保留未验证及待重载。

两次工程门禁在新增测试中的合成邀请／代理字面量上触发秘密扫描。已改为具名合成 fixture，未添加扫描器排除或降低规则；最终结果以完整 `make check` 为准。真实设备域名、地址、设备凭证、代理内容及原始日志只留在忽略的私有验证目录，没有写入公开测试或本文。

本记录不是远程 CI、最终 Linux 发行镜像或生产 NAS 升级已完成的证明。用户当前旧 Claude 进程需要退出，重新加载其 shell 环境后启动，既有进程不会自动获得新环境。
