# 项目控制台与记忆问答发布修复

关联 FR-01、FR-03、FR-05、FR-07、FR-10、FR-11、FR-12、ENG-01；对应[发布计划](../release-plan.md)第一阶段和 RR-01、RR-02、RR-05。开发基线 `1279f1b`。以下本地结果不表示 NAS 已升级，也不替代最终自行部署验收。

## 本次实现

- 忘记后的原文从自动 history-list 召回中排除；按精确 ID 主动查看仍保留既定语义，purged 仍禁止读取。
- 管理员控制台复用设备读取的权威查询和过滤，显式选择真实项目或 global；列表、搜索、原文、来源与问答绑定同一范围。读取异常与空结果分开，未计算总量不显示为零。
- 复用上游记忆库、原文详情和模型设置组件；问答引用可以打开当前项目记忆，支持续页与失败重试。切换项目取消旧请求，旧响应不能填入新项目。
- Anthropic 问答复用已有 Messages 适配器及上游答案／引用校验。没有可用模型时返回摘录；模型失败报告错误，不伪装为空库。最多使用六条经过过滤的有限记忆片段。
- Docker 的 Hub 网页构建显式启用控制台；保留非 Hub 上游入口。构建版本从镜像的源码 revision 注入，未知开发构建仍显示未知，不伪造版本。
- 新增页面与模型配置测试纳入 Docker 的 web-tests 门禁。

设计与合同：[ADR-0056](../adr/0056-forgotten-history-recall.md)、[ADR-0057](../adr/0057-administrator-console-reads.md)、[ADR-0058](../adr/0058-anthropic-memory-question-answering.md)、[控制台接口](../console-api.md)。上游差异由 `0028-hub-console-scope.patch` 和 `0029-sdk-anthropic-qa.patch` 固定摘要管理。

### 已安装容器验证

Linux amd64 镜像 `cloud-memory-hub:preview-c2924db` 已完成实际构建，镜像 ID 为 `sha256:542c57aa640f524748ade82116b7c8d89880f7dd5f7235a620ce11f264228348`。该镜像在随机命名、全新临时卷中通过安装验收：禁网模型资产与编码、初始化、身份与来源授权、写入与重放、真实 SDK 读取、安装后的 CLI 与召回 hook、捕获与过滤、管理员项目控制台与摘录问答。重启后重复验证，并确认撤销设备读取授权后仍拒绝，而管理员入口保持可用。全程没有配置外部模型；不是 NAS 真机或实际 Agent 模型验收。

容器网页门禁的 11 文件共 212 项通过，含模型设置、引导、原上游记忆视图及新 Hub 页面。新增 `scripts/probe_console.py` 使用蓝／绿两个已知合成项目正文及独立空项目验证隔离；不仅互比同一 API 的返回值。global 保留旧探针数据，不将它当空库。

中文搜索的全角冒号也已按凭证过滤使用的 Unicode 形式规范化，普通查询不再因标点被拒；全角拼写的凭证标签仍在调用 SDK 前拒绝。修改后的设备读取、控制台读取与问答组合 32 项通过，无跳过。最终包含这项修改的镜像另行验收，不能用前述镜像结果替代。

以上测试使用临时真实 Hub／SDK 存储和合成数据；模型响应由 MockTransport 提供，测试禁止外部 socket。组件测试不等于浏览器验收，提炼替身不等于实际模型质量。普通中文冒号误拒是在组合测试中发现并修正；SSE 分段与遗忘的竞态是源码审查发现加修后回归，没有旧实现实测失败证据。各测试范围可能重叠，不能相加为独立测试总量。
