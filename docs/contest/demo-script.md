# 合成案例演示脚本

**状态：本演示脚本未执行、未录制；使用已公开并核验的 v0.1.3 正式制品准备排练。** 本轮产品的 NAS 冷备份后升级、原 MCP 读写读回和真实新登录页已通过；这些验收不代表下列演示镜头已经拍摄，也不代表 Uliya 可运行。本脚本使用明确合成内容，不证明模型提炼质量或官方决赛合规。官方决赛要求真实 NAS 操作且禁止模拟数据／虚拟演示，不能直接把本脚本生成的合成演示当作决赛材料。

## 开始前

1. 核对同一 v0.1.3 发行版本和来源摘要。使用专用演示项目；两台实际电脑各使用独立设备身份，分别接入已选择的真实 Agent。若只有一台电脑，只标为跨 Agent，不标为跨设备。
2. 在用户授权的环境完成 NAS 部署、HTTPS 可达性和宿主重连。不要为拍摄修改日常身份、真实项目或已有记忆。
3. 只展示本页合成文字与脱敏结果；隐藏登录页输入、连接邀请、完整配置和其他项目。凭证不进入聊天、终端录屏或字幕。
4. 明确本次调用是否由真实模型决策。若使用测试替身，必须标注其边界；不得用预制字幕或替身响应伪装真实工具读回。

## 场景与话术

演示项目名称：**星舟演示项目（合成）**。建议时长约 3 分钟；以下是拍摄顺序，不是性能承诺。

| 镜头 | 操作与话术 | 必须看到的实际结果 |
| --- | --- | --- |
| 1：说明与连接 | 说明“服务运行在 NAS，两端共享同一个合成项目；不需要独立 App”。两端各执行 `memory_status` | 同一实例／项目、不同设备／来源获授权；公开画面仅显示必要状态 |
| 2：A 保存决定 | 在 A 说：“把这条合成项目决定保存到 Cloud Memory Hub：星舟演示项目的欢迎页使用青绿色，先完成键盘导航，再检查窄屏布局。” | `memory_remember` 的真实接纳回执；不能把 accepted 解说为已完成提炼 |
| 3：B 读取决定 | 在 B 说：“从 Cloud Memory Hub 读取星舟演示项目最近的决定，逐字引用刚才保存的内容。” | `memory_recent` 实际返回相同正文；不能用模型凭当前提示猜出答案 |
| 4：A 保存交接 | 将下面五字段通过 `handoff_save` 保存，记录实际返回的完整交接 ID | 真实接纳状态和返回的 ID，不预造 ID |
| 5：B 接续 | 只把实际交接 ID 提供给 B，请它调用 `handoff_load`，列出决定、下一步与阻塞 | 五字段与保存内容一致；说明不会恢复另一 Agent 的隐藏上下文或工作文件 |
| 6：B 回写、A 读回 | B 保存“合成进展：键盘导航检查已列入待办；下一步核对窄屏菜单。”A 再读取 | 反向真实回执与正文读回。该文字是合成进展，不声称真的做过页面测试 |

交接五字段使用以下合成内容；传递时遵循实际工具 schema，不把表格当成可执行代码：

| 字段 | 内容 |
| --- | --- |
| goal | 完成星舟演示项目欢迎页的交互检查。 |
| state | 已确定青绿色主题，键盘导航与窄屏检查尚未执行。 |
| decisions | 字符串数组，仅一项：欢迎页使用青绿色。 |
| next_steps | 字符串数组，两项：检查键盘导航。；检查窄屏菜单。 |
| blockers | 空数组。 |

## 如何核验，如何处理失败

- 原文 ID 和交接 ID 使用服务端真实回执；请求 ID 不能代替回执 ID。写入结果未知时保留原请求 ID、正文和现场，不新建身份或换 ID 掩盖失败。
- 每次读取都保留实际工具结果，逐字核对正文、逐字段核对交接。只看到宿主回答不算完成工具链核验。
- 如测时效，用同一个计时源从写入调用开始，到对端实际读回为止；保留完整耗时与重试，不拼接两台机器的墙上时钟，不承诺“实时零延迟”。
- 若网络、鉴权或接入失败，画面和记录明确失败及停止位置；不换为本机模拟结果，不把空搜索当作没有原文。
- 本脚本不含删除、撤销或恢复操作。若另需演示，必须作为独立授权场景处理，不临时扩展此排练。
