# Uliya 接入方式待确认

本说明用于核实 Cloud Memory Hub 的参赛接入条件，尚未发送给赛事方。主产品 v0.1.3 已发布，以下缺口不影响现有 MCP／Skill 用户部署使用，也不构成新增产品需求。

## 已有产品接口

正式版本提供 Streamable HTTP MCP，入口为 `/hub/v1/mcp/{source_id}`。每个设备使用独立 Bearer 凭证，来源绑定项目，每次请求重新核验权限。管理员凭证不用于 Agent 接入；当前没有实现 OAuth 发现与授权。连接通过管理页面生成，不能把私人连接地址、邀请或凭证写入参赛包。

参赛场景需要调用真实的 `memory_remember`、`memory_recent`、`handoff_save` 和 `handoff_load`：一端保存项目决定，另一端读取，并按服务端返回的完整交接 ID 接续任务。原文接纳和读取不要求先完成外部模型提炼。服务独立部署在 Docker 中，不由 Skill 静默安装。

接口依据是正式 v0.1.3 源码中的 `docs/adr/0065-one-link-remote-agent-onboarding.md`、`docs/agent-access.md` 及实际发布的 MCP 工具；不能把普通 MCP 客户端的验证替代为 Uliya 验证。

## 需要确认的三个问题

1. **调用入口**：Uliya 是否允许接入自建 Streamable HTTP MCP 服务？如允许，请提供配置入口、工具调用规范，以及是否支持显式设备 Bearer；若只能委托注册专家，请提供能够调用该服务的正式专家与能力规范。
2. **配套部署**：预测试及决赛环境能否使用独立的 Docker 服务？请明确安装责任、可达网络、凭证的配置位置及允许持久保存的数据范围。Skill 包本身可以仅包含允许的 Markdown 文件，配套服务和许可随外围材料提供。
3. **作品范围**：若当前 Uliya 尚不提供上述入口，是否接受“已运行的 NAS 服务＋已验证的通用 Agent MCP／Skill”作为初赛预测试作品？需要明确允许的宿主与安装验证方式，不能据宣传示例推定兼容。

## 当前证据与后续验证

2026-11-11 复核的[官方指南](https://hackathon.ugnas.com/skill-docs.php)要求依据工具包的真实能力创建 Skill；已核对的 2.0.0 工具包仅列出六位注册专家，没有通用 MCP／HTTP／Docker 或 Hub 记忆交接动作。[赛事页面](https://hackathon.ugnas.com/index.php)提及第三方工具及多 Agent 协作场景，但未给出这些接口的调用、鉴权或部署合同。因此目前结论是**缺少受支持接入方式的证据**，不是认定赛事全面禁止外部服务。

取得明确接口后，才按其真实工具名称和权限实现独立参赛 Skill，验证安装、写入、另一端读取、精确交接及失败处理，再录制与结果一致的视频。若官方答复不支持，保留主产品和本地材料，不改造成无关的文件整理技能。
