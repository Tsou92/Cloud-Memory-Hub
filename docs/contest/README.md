# Cloud Memory Hub：参赛外围材料草稿

Cloud Memory Hub 把共享记忆服务部署在 NAS Docker 中，让不同电脑和 Agent 读取同一项目的记忆，并通过任务交接继续工作。

普通使用路线是：在 NAS 部署服务，在网页创建连接，再用命令或交给 Agent 的安装话术接入 MCP／Skill；不需要另装独立图形 App。

**本目录仍是本地参赛材料草稿，不是可投稿成品或可安装 Skill。产品 v0.1.3 已公开发布，七件正式附件及同版 NAS 验收已完成；Uliya 受支持调用入口、可运行参赛 Skill、演示视频和官方环境实测仍未完成。** 这些参赛条件不构成主产品发布门槛。

产品来源为 [v0.1.3 正式发行](https://github.com/Tsou92/Cloud-Memory-Hub/releases/tag/v0.1.3)（Release ID `440667317`），固定提交 `25b9f7526bd5509d031dd9511845f6521f3acf92`。七件附件的文件名、大小和 SHA-256 已登记在[交付核验清单](verification-checklist.md)。

## 给谁用，解决什么问题

适合在多台电脑、多个编码 Agent 之间切换的开发者。希望减少反复解释项目背景，并把已确认的决定、进度和下一步交给另一端。

使用分三步：

1. 在自己管理的 NAS 上按正式发行指南部署 Docker 服务，打开管理页面。已有实例升级前先备份；必要的首次登录由用户在本机终端完成，密码不发送到聊天。
2. 在网页为项目创建独立设备连接，在目标 Agent 接入对应 MCP／Skill；宿主需要时重新连接。模型密钥仅在管理页面配置。
3. 请 Agent 保存项目决定；切换设备或 Agent 前保存任务交接，再由另一端按完整交接 ID 读取。工作文件仍需独立同步。

共享原文和交接按服务端接纳结果读取，不要求先完成模型提炼；自动提炼需要可用模型配置。远程 MCP 不会自动扫描完整历史，也不提供本机离线补传队列。Skill 是工作约定，不能保证所有 Agent 每轮自主调用。
