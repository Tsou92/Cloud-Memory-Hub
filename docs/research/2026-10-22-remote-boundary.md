# 远程接入前的复用边界核对

日期：2026-10-22。基于 [当前固定版本](../../upstream/manifest.json) 的源码核对；尚未实施远程接入，也不是客户端真机验收。

## 已有实现与下一步用法

| 能力 | 上游路径（相对仓库根） | 核对结果与处理 |
| --- | --- | --- |
| 凭证去除 | `memhub/apps/core/src/one_memory/input_sanitization.py` | 复用现有私钥、认证头、命令参数、赋值、已知令牌、URL 凭证六类处理和来源区间映射。现有代码不能单独证明中文凭证提示、Cookie、附件和未知凭证已覆盖；需要本地补充过滤及出站截获测试。 |
| 来源读取／工具证据 | `memhub/apps/core/src/one_memory/imports/sources/parsing.py` | 工具证据已有清洗调用，可复用解析；普通正文、元数据及附件同样必须经过本地统一出站边界，不能只过滤工具输出。 |
| 写入身份及队列 | `memhub/apps/core/src/one_memory/memory_server/contracts.py`、`routes.py`、`durable_queue.py` | 复用稳定请求身份、持久队列、重复请求与冲突区分、未知结果查询，不另建一个向模型写入的竞争队列。远程协议先建立本地待传队列，再提交现有中心队列；两者职责不同。 |
| 主机授权 | `memhub/packages/host-bridge/src/host-grants.ts` | 已有凭证摘要、原子替换、权限版本和撤销；优先用于 Mac 上宿主接入。它明确是可信本机安装器的控制面，不是远程 HTTP 认证接口；主机类型受 `isHostId` 约束，不能直接当作任意未来 Agent 的 NAS 身份库。 |
| 来源授权 | `memhub/apps/core/src/one_memory/imports/grants.py` | `SourceGrantStore` 授权本机文件根及文件身份，会检查根目录变化。保留其本地权限作用，不能通过伪造 NAS 路径把它当设备授权。 |
| SDK 记忆读取 | `memhub/apps/core/src/one_memory/api.py` 的 v2 接口 | 当前管理接口使用 `user_id=local`；设备不能直接共用管理员凭证或获得完整管理 API。需要服务端确定设备／项目范围，在检索和原文读取时执行。 |

## 实施顺序和不可省略的验证

1. 明确版本化远程合同、稳定设备／来源／项目身份及权限撤销；客户端自报项目不能自动获得权限。
2. 在 Mac 侧组合现有清洗和来源解析，先形成过滤后的事件，再进入本地持久队列。所有元数据、错误信息和重试路径一起验证；无法处理的附件保留本地隔离，不能先上传外部模型。
3. 建立服务器接纳记录与上游请求 ID 的稳定映射。区分“已上传”“已接纳”“已提炼并可召回”，不以 202 响应替代一分钟可用目标。
4. 定义项目与全局范围、同步游标、忘记／删除记录及恢复代际。设备重连先核对抑制状态，后上传旧队列；旧备份不能回滚这些规则。
5. 用两个隔离连接组件验证中断、重复、冲突和撤销，再验证实际桌面与终端的已有会话下一轮。日常配置仍在实际接入前单独处理。

先完成合同和威胁边界，再实施新增中心身份／同步模块。以上核对不构成重新实现上游已有授权、清洗、存储或队列的理由；仅扩展已确认的远程职责缺口。
