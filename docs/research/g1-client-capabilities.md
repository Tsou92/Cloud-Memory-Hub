# G1 六入口能力清单

日期：2026-11-10。关联 FR-01、FR-02、FR-05、FR-06、FR-08、ENG-01；按[路线图的阶段范围纠偏](../roadmap.md)收口。本清单依据仓库已有调查和验证报告整理，没有在本轮启动客户端、读取真实历史或重跑所引测试。

G1 要回答每种入口可复用什么、哪些能力已有证据、哪些还未知。六套完整适配器的交付仍属于 G3；G2 先完成两机两 Agent 的共享最小闭环。列出未知项不等于该项已通过，也不改变最终全自动接入要求。

## 证据等级与能力含义

- **有限实测**：已有真实客户端或实际组件的执行报告，只对报告中的版本、合成样例和调用链成立。
- **复用依据**：上游实现、接口文档或本机公开安装资源提供候选路径，尚无本项目对应客户端验收。
- **未验证**：已有候选路径，但目标调用链未运行成功；**未知**表示现有调查尚未确认相应合同。

“自动写入”区分记录自动采集、Hub 持久接纳和记忆提炼发布。只有前两项通过时，不能标为已经自动生成可召回记忆。“按需读取”区分通用连接组件读取与 Agent 实际调用；“下一轮读取”要求保留已有对话，下一轮自动取得更新，不能用新建对话或手动 MCP 调用代替。

## G1 客户端部分的有限收口事项

以下是并行保留的能力缺口，不作为当前 G2 MCP／Skill／handoff 实现的前置。当前桌面隔离启动失败及通用入口进展见 [MVP 验证记录](../reviews/2026-11-10-agent-access-mvp.md)。

1. 后续补齐真实 Codex 桌面接入：确认当前消息采集、同一对话下一轮上下文更新，并明确宿主合同与产品接线证据的区别。失败时记录具体失败点和可行替代，不能用 CLI 结果代替桌面。
2. 对其余四入口补齐有界能力探针／合同调查，逐列得出“可复用、需适配、已证实不支持或仍未知”的结论。尤其确认 Open Design 扩展合同，以及 Hermes 既有 memory-provider 的共存方式；不为完成清单而提前开发四套完整适配器。
3. 汇总桌面与 Claude CLI 的证据，明确最短共享链中尚未验证的采集→提炼→下一轮读取连接，给 G2 的两机两 Agent 实现提供确定输入。客户端升级后对相关合同复测，不将过去报告当作当前版本保证。

上游基线／补丁证据、NAS 与两机可达性、删除恢复设计结论仍由[路线图](../roadmap.md)的其他原 G1 条件验收。本文只完成客户端证据清点，不宣布 G1 已结束。

两 Mac MCP 共享、Claude 当前轮自动共享及 Codex Skill／CLI 到 Mini Claude 的接续已有有限实测；Codex 桌面原生 MCP 和每轮自动触发、一分钟目标统计、全量历史及实时争用、离线读取缓存、全部六入口自动读写、完整治理与备份仍按原 G2/G3/G4 范围推进。已有报告不证明这些未完成结果；其中实际阻断 G1 原验收条件的问题才进入 G1 当前工作。
