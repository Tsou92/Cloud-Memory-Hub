# Hy-Memory 新基线候选验证

日期：2026-10-22。状态：候选验证完成，接受为隔离开发基线；决定与回退边界见 [ADR-0003](../adr/0003-sdk-authority-baseline.md)。当前固定版本以 [manifest](../../upstream/manifest.json) 为准，旧运行容器和数据卷保留。

## 来源与升级价值

候选提交 `b7d9f0e0f417eae30b192882f848b432484c20a6` 比原固定提交多三次提交，涉及 249 个文件。主要变化为[上游 PR 132](https://github.com/Tencent-Hunyuan/Hy-Memory/pull/132)：记忆及原文的权威存储转交 SDK，Core 保留模型配置、授权、持久写入队列及管理状态。候选 Core 锁定 `hy-memory==2.0.5.dev3`，不能与旧 SDK 2.0.4 混用。

值得复用的新增能力包括 SDK 原文精确导入、请求结果查询、完整数据快照／恢复和带验证账本的迁移。已确认的测试替身兼容问题部分由上游自行调整；候选尚未应用本仓库旧补丁。

## 需求不能随上游缩减

| 上游变化 | Cloud Memory Hub 仍需满足 |
| --- | --- |
| 当前记忆正文只由 SDK 管理 | 通过 SDK 正式接口读写；中心同步状态只引用稳定 ID |
| 新产品明确移除可见修订历史和 Undo | 保留 FR-09／FR-13 的用户修正来源、历史版本和回滚；需补充 Hub 历史层和对应恢复验证 |
| 物理删除、无旧治理墓碑界面 | 保留 FR-10／FR-11 的忘记、彻底删除区分及删除记录；旧队列／旧备份不得复活 |
| 旧 session inbox／outbox 删除 | 为两机同步定义管理事件和游标，不能假设上游仍提供已开对话刷新 |
| 快照要求停止写入 | 复用快照函数并实现受控停止、恢复及失败回退；不能复制活动文件冒充完整备份 |

升级只能改变实现方式，不能删除已确认需求。新版本通过单元测试也不代表上述补充行为已完成。

## 实验证据

- 独立目录、固定提交、上游锁文件；不修改原检出、已运行镜像或用户配置。
- Hub 现有 11 项认证／凭证／真实 Core 集成测试在候选依赖上通过。
- Linux Node 24.10.0／pnpm 11.24.0 管理网页构建成功，保留大包警告。
- 完整 `core-pr` 首轮：4,981 通过、37 失败、25 跳过、12 排除、2 预期失败；耗时约 329 秒。
- 37 个失败定位到源码树缺少内置向量模型。使用上游脚本获取并校验 5 个文件，共 23.2 MB；针对失败项复测 37 通过。
- 完整 `core-pr` 重跑：5,034 通过、9 跳过、12 排除、2 预期失败，耗时约 322 秒；模型补齐也使原先缺模型的 16 个跳过项得到执行。测试结束有观测日志异步任务未排空警告，未将其省略或标为已修复。
- Host Bridge 在 Linux Node 24.10.0／pnpm 11.24.0 中：60 个文件通过、1 文件跳过；816 项通过、1 预期失败、1 跳过，约 75 秒。
- Host Bridge 测试环境先后遇到精简 Node 镜像缺 Python、包注册表连接中断以及 npm 压缩包中 CLI 缺少可执行位，均发生在测试启动前；修正隔离测试环境后才取得上述结果。
- 比较新旧 Core 锁文件的包版本，只有 `hy-memory` 从 `2.0.4` 变成 `2.0.5.dev3`。新检出未使用旧测试补丁，Hub 锁文件已相应更新。
- 后续真实浏览器发现全新库的状态 API 错报 legacy；原版完整测试未覆盖该首启链路。新增回归先复现失败，再以一行补丁复用上游 `authority()` 判断；详见[补丁 0003](../../upstream/patches/README.md)。这条缺陷不被原版的通过总数掩盖。
- 状态接口修正后，浏览器还暴露简化页默认视图没有接到 SDK 组件的问题；补丁 0004 复用已有记忆库／问答／历史组件。新增三项首启测试及原有相关组件测试共 109 项通过；容器与浏览器结果继续记录在运行报告。

上述模型文件不能进入 Git。容器构建使用上游固定清单获取、校验并确认安装后的路径；新增禁网模型探针验证真实编码，执行结果另记[运行时记录](../reviews/2026-10-22-runtime.md)。依赖来源和完整模型许可证仍需纳入发行审计。

## 本机接入证据

只读取应用版本和公开程序资源，没有读取用户对话或修改配置。当前宿主应用为 ChatGPT 26.1016.51333（内置 Codex CLI 0.163.0-alpha.11），Cherry Studio 2.1.7、Open Design 0.24.1；本机可找到 Claude Code、OpenCode、Hermes 终端入口。这些是安装存在证据，不是双向同步通过证据。

上游 Codex 说明仍以 MCP 按需召回为主。本机应用包含 `UserPromptSubmit` 设置项；[官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)提供每轮提交时返回额外上下文的正式合同。插件 Hooks 仍需用户信任，见[官方插件打包文档](https://developers.openai.com/plugins/build/plugins)。因此下一轮自动读取有可验证的实现入口，但仍需独立桌面会话的实际验收，不能用 CLI 或文档代替。

记忆正文是不可信资料，即使通过 Hook 加入上下文也必须显式包裹为引用数据，不授予系统权限；输出必须限长，不能把原始凭证或未过滤附件带入宿主。
