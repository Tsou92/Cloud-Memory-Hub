# ADR-0003：采用 SDK 权威存储的新上游基线

日期：2026-10-22。状态：接受用于隔离开发；不授权既有数据迁移或正式发布。
关联：ENG-01，以及 FR-02、FR-09、FR-10、FR-11、FR-13 的后续实现基础。

## 证据与选择

采用 `b7d9f0e0f417eae30b192882f848b432484c20a6` 与其 Core 锁定的 SDK `2.0.5.dev3`。旧基线 `0244ebe38ce0288a44a8b6fc7f209ab2bf6c3766` 与 SDK `2.0.4` 保留为历史记录，不混用两套数据合同。完整评估见[候选验证记录](../research/2026-10-22-upstream-candidate.md)。

新基线复用 SDK 对记忆和原文的权威存储、精确导入、请求结果和一致快照接口；Core 继续负责配置、授权及持久队列。其未修改的 `core-pr` 测试在补齐校验通过的内置模型后达到 5,034 通过，Host Bridge 测试 816 通过；Hub 11 项集成测试通过。跳过项和预期失败项单独记录，不算通过。

上游锁文件的包版本变化仅为 SDK 从 `2.0.4` 升到 `2.0.5.dev3`，其余依赖继续保持锁定。旧的两个测试补丁不适用于新合同，移出活动 manifest，保留文件及原适用版本说明。随后浏览器实测发现全新库状态接口误报旧模式，新增一行兼容补丁，复用上游现成的状态判断，见[补丁说明](../../upstream/patches/README.md)。

浏览器进一步发现 SDK 简化页仍默认展示已停用的旧地图。补丁 0004 将默认入口接到已有 SDK 记忆库、问答和历史组件，并补充首启三种状态的回归。没有重写 SDK 读写、提炼或列表组件。

## 兼容性与数据边界

本次只在新建的隔离测试卷中运行新版本。旧镜像、旧源码检出、原测试卷保留；不将直接替换镜像当作迁移或回滚。已有库未来升级需要：停止写入、完整备份、上游迁移验证、Hub 管理记录协调，以及失败后恢复旧版本和对应旧数据。上述迁移流程尚未实现。

上游移除了旧修订历史、Undo 和部分 session 管理表，这不改变 Cloud Memory Hub 的需求。后续增加 Hub 管理事件、历史引用和不可回滚的忘记／删除记录，记忆正文通过 SDK 正式接口管理，不再建一个竞争的当前记忆库。具体协议和数据库结构在实施前另行记录。

## 镜像完整性

复用上游 `fetch_embedding_model.py` 与 `embedding_assets.py` 中的五个 SHA-256 摘要，构建时下载并校验模型，安装后再次验证实际运行路径。文件不进入 Git，也不在用户首次启动时自动联网下载。容器验收应在禁网条件下加载真实模型并生成向量，证明不是仅有文件名或服务存活。

模型来源及许可证说明随上游第三方声明保留；上游关于 ONNX 导出仓库许可证的未决项仍为发行审计事项，不能由开发测试替代。

## 尚未完成

这不是 G1 完成或产品发布决定。NAS、真实模型、六种客户端、两机同步、已有对话下一轮、删除防复活及备份恢复仍需对应实现和实际验收。Core 测试结束时有观测日志异步任务未排空的警告，保留为运行时退出验证事项。
