# ADR-0013：运行服务与维护命令的进程互斥

日期：2026-10-26。关联 FR-10、FR-11、FR-13、ENG-01；作为 [ADR-0012](0012-governance-scope-and-lineage.md) 的写入隔离前置条件。

## 复用调查与缺口

固定上游的 `DurableWriteDrain.stop()` 会停止循环，`run_forever()` 的 finally 等待已开始任务；调用前的 sedimentation／来源授权可阻止新模型调用。但这些机制没有阻止第二个服务进程或维护命令同时打开相同 SDK 存储。SDK bridge 的 `exclusive_access()` 仅覆盖单个 bridge，队列租约及 `session_lease.py` 是任务／会话租约，不能作为整个服务进程持有存储的证明。

继续复用这些队列、SDK 和授权实现。增加部署入口的 OS 文件锁，只负责当前 Hub 命令之间的存储互斥，不重写任务调度，不把此锁当作在线写入暂停或未知任务核对。

## 行为

- `serve` 在构造 Core、启动后台 worker 前，独占 data、config、governance 三个根目录的 `.cmh-storage.lock`，直到服务进程退出。
- `init` 独占 config 和 governance；`migrate-governance` 独占三目录。`--writers-stopped` 仍是必需的操作者声明，但运行中的新版本 Hub 会使迁移直接拒绝，不能只凭该标志绕过。
- Compose setup 与 hub 挂载同一组 data/config/governance 卷。维护命令不能只挂身份与治理卷，然后将镜像内另一个空 data 目录误当作原存储。
- 按规范化路径排序获取非阻塞锁；任意目录已被占用时释放本次已取得的锁，返回固定 `storage_in_use`。不同的实例目录可并行运行。
- 锁文件为空，不保存 PID、凭证、正文或主机信息。使用 no-follow 打开，验证当前用户、私有权限、普通文件、单硬链接和打开后的 inode 一致性；不修正不安全权限或替换已有锁文件。
- 正常退出和进程被终止后由 OS 释放锁。保留空锁文件，不能通过删除“旧锁文件”解锁；文件存在不等于有活跃进程。复制备份中的空文件也不能复制活跃锁。

## 兼容性与边界

面向当前支持的 macOS 和 Linux 本地文件系统，使用 POSIX flock。没有数据库 schema 或 HTTP 协议变化。旧镜像、直接调用 SDK 或内部 Python 构造函数的进程不识别此协议，所以第一次升级仍必须由部署工具观察旧容器已经退出。不能由新版本取得锁便宣称任意旧进程、共享文件系统或外部程序已经停止。

维护和恢复不得替换仍被持有的根目录或锁文件；SDK 内容目录位于 data 根目录之下，可在取得维护锁、确认服务停止后按恢复协议处理。初始化只创建新的私有目录；正常启动不得因此重建缺失的身份库或治理库。

后续在线执行仍需：全 bridge 的操作准入、暂停领取与等待在途任务、未知结果核对、重新规划、持久意图及选择性抑制。当前仍不开放实际删除接口，不改变保留／删除语义，也不把整库隔离当作最终产品行为。

## 验证要求

真实子进程验证同目录竞争、不同目录独立、进程终止后可重开，以及部分获取失败后全部释放。真实 `serve` 运行时，第二个服务（即使使用不同端口）和带 `--writers-stopped` 的迁移都应被拒绝；停服后迁移可以继续。验证软链接、硬链接、不安全权限和非普通文件被拒绝。安装后的 Linux 镜像也应覆盖这条入口，不能仅测试锁函数。

这是已授权开发范围内的架构自审。后续 SSH 恢复后已完成本地与 NAS 安装验证，见[实际证据](../reviews/2026-10-26-storage-exclusion.md)；实例内 SDK 准入继续见 [ADR-0014](0014-shared-sdk-admission.md)，不将存储租约算作完整队列排空。
