# ADR-0076 备份导出的认证加密

状态：已实现（0.1.13 未发布）。日期：2026-11-19。关联 FR-11、FR-13、ENG-01。

## 背景

完整导出包含管理员 Bearer、Fernet 加密密钥、设备配置、原文与治理记录；导出的明文 `.cmh.tar` 等同整套凭证。此前只能依赖私有目录与传输安全，备份文档明确写着“传输中的备份未加密”。

内部 `/backups` 版本仍是普通目录，由宿主文件系统保护；本 ADR 只处理用户主动带到其他设备或离线保存的导出副本。

## 决定

- `backup_maintenance export` 新增可选 `--encrypt`，生成认证加密的 `.cmh.tar.enc`；未加密 `.cmh.tar` 保留兼容。
- 口令来自 `--passphrase-file`（0600 私有普通文件）或 `CMH_BACKUP_PASSPHRASE` 环境变量；不接受命令行参数，避免进程列表泄露。优先使用文件。
- `inspect`／`import`／`restore` 的 `--archive` 按文件头自动识别加密格式，并要求同一口令；未加密归档行为不变。
- 内部 `/backups` 版本不加密；磁盘／卷级加密仍由宿主 NAS 负责。

## 格式

`CMHBK1` 版本 1：

- 头部：magic `CMHBK1`、1 字节版本、16 字节随机 salt、8 字节随机 base nonce、4 字节块大小（固定 1 MiB）。
- KDF：`hashlib.scrypt`，n=2¹⁵、r=8、p=1、maxmem=64 MiB，派生 32 字节 AES-256 密钥。
- 分块：每块 4 字节明文长度 + AES-GCM 密文与 16 字节 tag；nonce 为 base nonce + 4 字节块序号；AAD 为头部 + 块序号 + 是否最终块。
- 结束块：长度 0 的最终块，作为完整结束标记；解密端要求其后无尾随字节。
- 解密写入私有临时目录中 0600 的 tar，调用方完成 `unpack_backup` 后删除。

scrypt 参数与块大小固定在版本 1；改变参数必须新增格式版本，不能静默改变旧归档的解密语义。

## 安全边界

- 提供机密性、防篡改和防截断；**不是数字签名**。能替换归档文件的人仍可提供一个不同的合法归档（加密或明文），调用方必须只导入自己控制的来源。
- 口令丢失无法恢复；口令文件与归档不应放在同一位置。
- 环境变量可能被同机有权限的进程读取；文档优先推荐 0600 文件。
- 加密只覆盖导出的副本；内部 `/backups`、运行三卷和 Docker 宿主日志仍是明文，需要宿主级磁盘加密或私有存储。
- 增量备份不在此范围：每次导出仍是完整归档。

## 备选

- `age`：成熟格式，但新增外部依赖与工具链，当前 `cryptography` 已能提供所需 AEAD。
- 整文件 Fernet：接口简单，但需要把整个归档读入内存，不适合最大 1 TiB 的导出。
- 加密内部 `/backups`：需要调度器长期持有密钥，改变恢复与备份语义，范围显著更大。
- 不加密：保留现状，但把凭证风险留给用户。

## 验证

- 加密／解密往返、错误口令、篡改、截断、1 MiB 块边界与真实备份导出后 `unpack_backup` 均通过。
- `_source` 对加密归档要求口令文件，缺失时返回 `backup_passphrase_required`。
- 未加密导出与原备份、导入、恢复测试保持通过。
