# ADR-0002：复用 Core 的 NAS 运行边界

日期：2026-10-22。状态：实现和验证中，尚未达到产品发布条件。
关联：FR-12、ENG-01；认证与凭证存储是后续 FR-02／FR-07 的基础，不等同于已完成它们。

## 证据与决定

固定版本的 Core 提供 `create_app(settings, secret_store=...)`，可直接注入现有 SecretStore 合同。管理网页可以在 Linux Node 24 中构建，以相对地址访问相同源 API。上游默认的 KeyringSecretStore 面向操作系统安全存储，不能假定无桌面的 NAS 容器存在可用 keyring。

因此使用薄封装：

- 直接运行 MemHub Core、数据库、任务、模型配置和管理网页。
- NAS 外层验证管理员凭证、浏览器会话和精确 Origin／Host；认证后才转交原有 Core。内部凭证不下发浏览器，不向外开放内部接口或原有本机会话交换接口。
- 复用上游 UISessionStore 的会话生成、有效期与撤销；新增登录页面和远程边界。管理员凭证仅用于管理，后续设备接入须独立的可撤销权限，不能共用管理员凭证。
- 实现 SecretStore 接口的容器后端，使用 Fernet 认证加密保存模型凭证；密钥与记忆数据分离挂载，错误密钥拒绝启动。该后端用于系统凭证，不把凭证存入共享记忆。
- 显式关闭 NAS 对本机 Agent 来源的扫描，后续由 Mac 连接组件提交经过本地过滤的内容。
- Docker 默认仅发布回环端口；非回环访问要求 HTTPS 和明确的公开 Origin。代理配置、真实网络与设备接入仍需验证。

## 可复现性

上游固定提交及测试补丁进入 manifest。准备脚本验证来源、提交、补丁校验值和精确工作树，不重置未解释的修改。Hub 依赖单独锁定，但约束到上游锁文件的版本，避免无意升级 FastAPI、SDK 或其他传递依赖。

上游代码和许可证打包到制品中；本仓库维护增量封装和补丁，不丢失来源。

## 当前限制与退出条件

当前边界不是最终设备同步协议，不具备离线补传、本地内容过滤、多模态采集、完整备份和删除传播能力。未完成这些能力及相应验收前，不能称为满足完整需求的可用版本。

原基线的上游回归问题及后续基线选择见 [ADR-0003](0003-sdk-authority-baseline.md)。G2 要求真实 Core 集成、容器启动／重启、加密凭证持久性、认证／跨源拒绝与 UI 配置验证。公开交付还需要凭证轮换／恢复说明、完整回归、安全审查与 NAS 真机证据。
