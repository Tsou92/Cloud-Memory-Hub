# ADR-0011：独立治理记录与离线同步的前置约束

日期：2026-10-25，2026-10-26 更新。状态：治理记录及运行时绑定已接入，尚未开放用户删除或离线缓存。关联 FR-06、FR-09、FR-10、FR-11、FR-13、ENG-01。

## Step 0：复用、范围与实测

继续使用固定上游 `b7d9f0e` 和已安装 SDK 2.0.5.dev3。`HyMemoryBridge` 提供正文读写、精确导入、互斥访问与物理删除回执；`DurableWriteQueue` 提供持久任务、调用前授权和未知结果处理；SDK snapshot 提供停止写入后的文件快照与保护副本。保留这些实现，不创建另一套当前记忆库或模型队列。

`RetiredGovernanceStore` 在 SDK 模式已经退役，不能恢复旧 Governance 表作为正文权威。`managed_restore.py` 恢复的是要求 evidence 表存在的旧主库，不覆盖当前 SDK 数据面。SDK snapshot 的 writers_stopped 是调用方承诺，不能直接作为在线、按项目分页同步接口。

`make probe-sdk-governance` 在独立子进程中实测：删除链头使旧版本重新 active／is_latest；原始记录保留；被删正文留在 SDK history；相同内容换 ID 可再次精确导入；停止写入、用原快照恢复后，被删链头重新有效。其他项目保留。报告标为 observed_gaps，不是产品删除验收通过。数据全部合成，未调用外部模型。

最小完整改动需要：独立治理记录、来源／派生关系闭包、调用前抑制、物理清理协调、恢复核对、同步快照与客户端缓存。它们必须串联，不能仅在查询层隐藏记录便宣称“彻底删除”。本次实现独立记录及回滚检测原语；其余作为同一产品的后续步骤保留。

## 架构与恢复约束

治理数据库不保存正文、路径、密钥或原始内容摘要。每个目标使用由实例、项目、目标类型和稳定标识组成的带密钥摘要；普通 SHA-256 不能用于低熵私人内容。独立密钥从受控配置提供，不写入治理库。记录按项目形成单调序号和带密钥的摘要链，操作 UUID 保证重试一致；相同 UUID 携带不同意图须拒绝。

忘记与彻底删除分别保存 forget／purge 意图，已确认的治理记录不随业务数据回滚、撤销或重新导入而消失。意图提交只表示治理规则已持久化，不表示正文清理已完成。后续执行器必须在抑制生效后处理 SDK、原始记录、演化链、派生记录、队列、修订历史、索引／缓存及受控备份；只有逐项核验后才能呈现完成。

```text
用户选择目标 -> 授权 + 展示关联范围 -> 提交治理意图（耐久）
  -> 阻止相关新提炼／读取 -> 等待已开始写入结束并核对未知结果
  -> 计算并保存关联目标 -> 调用 SDK 清理 + 队列／历史／备份清理
  -> 核验结果 -> 发布项目治理水位 -> 客户端原子应用抑制与缓存变更
                         |
旧快照恢复 -> 停止服务 -> 保留当前治理记录 -> 合并／重放规则 -> 核验 -> 重新开放
```

治理目录单独持久挂载，正常业务快照恢复禁止覆盖它。完整导出可携带治理记录用于新实例迁移；导入到已有实例时合并当前规则，不用旧副本替换当前权威。目录丢失、密钥／实例不匹配、摘要链损坏或客户端证明服务端水位倒退时，拒绝继续读取／写入／自动恢复，要求恢复可信治理副本。

单机上若业务数据、治理目录和所有外部见证同时被任意回滚，单靠同一旧磁盘无法证明丢失了更晚的操作。产品管理的恢复流程通过保留独立目录和客户端最高已见水位避免此路径；不能把摘要链宣称为可检测任意整机回滚。失去可信记录时保持隔离，不自行重建空记录以“修复”。

在线读、持久队列、SDK 和治理库不是一个 SQLite 事务。采用先记录意图、持续抑制、可恢复执行、最后核验的流程，不声称跨库原子提交。SQLite 本身提供单库事务与隔离，WAL 的快照隔离不覆盖其他 SDK 存储，见 [SQLite 隔离说明](https://sqlite.org/isolation.html) 和 [原子提交说明](https://www.sqlite.org/atomiccommit.html)。

## 代码质量、协议与兼容性

基础模块仅维护 intent、scope head 和变更读取，正文仍由 SDK 管理。复用当前私有文件检查、UUID／scope 校验，使用 SQLite BEGIN IMMEDIATE 与同步提交。初始化必须显式调用并只创建新文件；正常打开不得偷偷生成缺失数据库。所有错误只返回固定码。

项目水位包含 ledger_id、sequence 和 digest。客户端提供已见水位后，服务端核验实例链相同、序号不倒退且该序号摘要一致。不同项目不共享变更内容。后续快照还需设备授权 revision、业务数据代际和与同一治理水位对应的完整发布状态；现有 read/list/search 不改成伪快照。

基础提交 `8c701bc` 尚未接入运行时。后续接线加入独立挂载、显式初始化／迁移与整体故障隔离；设备权威库版本提升为 2，设备 HTTP 协议仍为 1。旧镜像拒绝该身份库，不能通过镜像回退绕过治理意图。发行仍复用现有 Docker／Mac 连接组件，不新建制品种类。

## 测试图与失败模式

```text
initialize -> 新库 [单元] / 已存在拒绝 [单元]
open -> 绑定匹配 [单元] / 缺失、权限、软硬链接、损坏、错密钥 [单元]
append -> 新意图 + 水位同事务 [单元]
       -> 重试同结果 / UUID 内容冲突 / 多写入者 [单元]
       -> 事务中进程死亡 -> 重开无半条意图 [真实进程]
changes -> 连续页 / 跨项目隔离 / 已见水位落后合法 [单元]
        -> 恢复旧库导致序号倒退或分叉 -> 明确拒绝 [真实文件恢复]
治理执行 -> 旧版本、原文、修订历史、派生、队列、备份 [待接入真实 SDK 集成]
离线端 -> 同步中断、撤销、旧快照、删除规则先应用 [待接入客户端集成]
```

服务断电不能留下只写入意图或只推进水位的状态；密钥错误不能返回“空规则”；未知库版本不得写入。客户端遇到回滚／分叉须停止使用缓存，不换身份绕过。后续忘记、彻底删除、同步、恢复四条用户流程均需真实存储集成测试，不用此基础模块测试代替。

## 性能与实施顺序

启动时完整验证摘要链，运行中每页验证连续性；变更按项目和序号索引，不在热路径扫描全部项目。提交量、分页与目标数量设边界并明确报错，不能静默丢弃目标。后续大范围治理通过持久计划分批处理，整个范围在核验结束前持续受抑制；不是将超限目标当作已处理。

顺序实施：治理记录 → 写入／读取抑制和关系计划 → 清理与恢复协调 → 一致快照／增量 → 本地缓存与召回 → NAS 和两机验收。各项依赖同一治理语义，当前顺序实施，不启动并行 Agent。

接线阶段需在设备权威库保存不可变的 ledger_id 绑定和各项目最后已见水位，治理目录仍单独挂载。先提交治理意图，再保存外部水位，二者完成后才能确认接纳；中断后根据摘要链继续核对。普通业务恢复保留治理目录，独立治理目录被回滚则由外部水位检测；两份状态同时回滚的边界仍按上文处理。

启用治理后提升设备权威库兼容版本，使不识别治理规则的旧镜像拒绝启动。旧实验实例的迁移必须停服、备份并显式执行；普通 serve 不得生成缺失记录库或重置绑定。新实例 init 先创建凭证及身份，再创建治理库和绑定；初始化中断保留可诊断状态，不悄悄覆盖。读写边界须核验绑定／水位，读取前后的治理状态变化也需拒绝旧结果。

## 运行时接线与迁移合同

`hub_governance:/governance` 独立于业务和配置卷；自定义 `CMH_GOVERNANCE_DIR` 时也必须与 data/config 互不嵌套。密钥由既有随机加密密钥经独立 HMAC 域派生，不存入记录库。绑定、项目最高已见水位和签名保存在身份库的版本 2 表中；设备、凭证、授权和来源回执不重建。

同一实例的合作写入者先持有身份库事务，再访问治理库。先验证旧水位，提交意图，再验证新链并持久化水位，最后确认接纳。进程在两次提交之间死亡时，旧水位保留、治理意图保留；下次打开验证新链并推进水位。此时仍不能宣称清理完成。已签名水位不能降低，同序号不同摘要拒绝。整个身份库和治理库一并回滚仍属于前述外部见证边界。

`init` 创建全新实例；旧实例显式执行 `migrate-governance --writers-stopped`。该参数是操作者已停服的声明，不是自动停服或证明旧进程已退出；部署工具必须先观察旧容器终止，再迁移。重复迁移只核验既有绑定；版本 2 缺失治理库时不得生成新库。版本 1 且仅新建空治理库的中断可通过显式迁移续接，非空未绑定记录必须人工恢复可信状态。

启动在构造 Core 前和 ASGI lifespan 启动前各核验一次。HTTP 管理、远程接口和健康检查在入口及每次输出前检查；未发出响应时返回固定 503，流式响应已发出的片段无法撤回，后续片段停止输出。队列领取及调用前继续复用上游 `_source_writes_on` 授权回调，治理故障时所有来源（包括 manual）返回拒绝。身份库故障和治理故障均不能变为空规则。

当前执行器尚未接通，发现任何治理意图会隔离整个实例，启动拒绝、健康检查 503；这仅是开发阶段的失败保护，**不是最终按目标执行忘记／彻底删除的实现**。上游 SDK 直接 DELETE 入口返回 `governance_workflow_required`，避免它在无治理记录的情况下重新激活旧版本。完整产品仍必须实现关联范围预览、选择性抑制、原文主动读取、物理清理和恢复核验，不能长期以整库不可用替代这些要求。已经开始的 SDK 操作可能在隔离后完成；后续执行器必须等待、核对并清理，当前不声称已中断所有在途模型调用或获得跨库原子删除。

迁移前备份可用于开发环境撤回未启用操作的升级；只要记录库存在治理意图，就不得仅恢复旧身份库、丢弃记录卷或启动旧镜像。生产恢复流程和受控备份清理仍待实现。当前部署命令和验证边界见[运行指南](../development-runtime.md)。
