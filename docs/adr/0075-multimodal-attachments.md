# ADR-0075 多模态附件的本地文本抽取

状态：已接受并实现，随 v0.1.13 发布（2026-11-19）。日期：2026-11-18。关联 FR-08、FR-14、FR-15。

## 决定

采用“本地抽取文本 + 本地过滤，只上传派生文本与来源元数据”的方案（方案 A）：

- 原始附件字节不离开来源设备，不进入 Hub 原文归档、备份、离线缓存或外部模型请求。
- 采集器在本地读取受支持的附件，抽取文本后走现有凭证过滤，再把派生文本作为普通 Event 内容上传。
- 默认关闭，按来源显式开启：source 文件增加 `media_text_extraction: true`；该开关不改变来源绑定摘要。
- 首期支持 PDF 文本层与 `text/plain`／`text/markdown` 文件；图片、扫描件、加密 PDF、Office 文档与 URL 引用继续拒绝。
- 派生文本带文件名、MIME、页数、字节数与 sha256 前缀，便于检索与来源追溯；原件仍由原 Agent／现有文件同步管理。
- 模型路径不变：派生文本继续使用用户已配置的文本模型；不新增视觉模型。
- 忘记不会删除本地原件；彻底删除只清 Hub 归档中的派生文本。界面与文档不得暗示“忘记＝删除附件”。

## 背景与约束

- ADR-0005：客户端上传前必须完成过滤；服务端只做防御性复核。
- ADR-0017：Hub 归档的是过滤后的完整 Event，不是附件字节的无损副本；原文归档只有 `payload_json` TEXT，没有二进制列。
- Hub 事件体上限约 1 MiB，无法容纳典型截图／PDF；新增二进制通道会同时扩大备份（默认保留 7 版）、加密、治理与彻底删除范围。
- 现有模型适配器只接受文本内容块；图像／PDF 视觉输入需要新增上游补丁、视觉探针与费用统计，不能在首期隐式启用。
- 隐私过滤器是尽力而为：它能识别常见凭证键名与文本，但不覆盖 PII、图片像素或未标注的短密码。

## 实现

- `apps/hub/src/cloud_memory_hub/media_text.py`：本地 PDF 文本层（pypdf，≤50 页、≤20 MB）、`text/*` 解码、sha256 与派生文本头；抽取文本 ≤64 KiB。
- `source_capture.py`：source 配置新增 `media_text_extraction: bool = False`；在解析前替换受支持的 `document` 块为文本块，再走原有 fail-closed 守卫；任何抽取失败停在原记录并返回固定错误码。
- 媒体守卫扩展 `input_image`、`input_file`、`input_audio`、`input_video` 与 `image_url`、`file_url`、`file_data` 的结构性拒绝，避免部分宿主把图像块静默跳过。
- 新增测试覆盖：文本／PDF 抽取、扫描件无文本、加密 PDF、页数与文本上限、Claude／Codex 记录改写、图片仍拒绝、开关默认关闭、开关不影响绑定摘要。

## 未纳入

- 图片与扫描件 OCR（第二阶段；需本地 OCR 引擎、人工确认与更完整的 PII 规则）。
- 把图片发给外部视觉模型（需逐文件明示同意、视觉探针、上游图像内容块适配与费用统计，另立 ADR）。
- Hub 内二进制附件库与跨设备直接打开原件（会扩大备份、加密与删除治理范围）。

## 验收

- 合成 PDF／文本样例：抽取、过滤与入队通过；上传、检索、来源追溯与忘记／彻底删除的端到端验收尚未执行，列为后续验证项。
- 含附件记录在开关关闭时仍返回 `source_media_not_supported`；开启后只上传派生文本，原始 base64 不出现在事件或归档中。
- 图片、扫描件、加密 PDF、超页数、超文本上限与 Office 文档均明确拒绝，不越过失败位置。
