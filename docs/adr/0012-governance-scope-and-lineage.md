# ADR-0012：治理范围预览与来源关系

日期：2026-10-26。状态：复用调查与真实 SDK 探针已完成，规划器及执行器待实现。关联 FR-06、FR-09、FR-10、FR-11、FR-13。沿用 [ADR-0011](0011-governance-authority-and-offline-sync.md) 的持久治理规则，不新增正文权威库。

## 上游实测与复用选择

固定 SDK 2.0.5.dev3 / 上游 `b7d9f0e`。`scripts/probe_sdk_governance_links.py` 在独立进程、私有临时数据和显式启用的 Kuzu 中构造合成原文、演化版本、摘要及活跃／归档／其他项目的派生节点。没有启用生产图存储，也没有调用外部模型。

实测得到：

- `MemoryNode.source_raw_memory_id` 已存在于向量存储，但 SDK `get` / MemHub `get_sdk_memory` 不返回该单一指针；只看公开读取结果会遗漏摘要的原文。
- 默认列表不包含 superseded 记录；存储端 `list_by_user(status_filter=None, only_latest=False, allow_raw_layer=True)` 能保留原文和旧版本。
- `find_referencing_memories` 只列 active 节点，遗漏归档派生；它本身不限制 user_id，合成跨项目引用也会被返回，必须另行核验归属。
- `get_evidence_vdbrefs` 在注入底层查询失败后返回空列表；治理不能把这种空列表当作“没有关联记录”。
- 复用 SDK 图存储的参数化 `_run`，按 user_id 查询所有状态的 DERIVED_FROM，能保留归档派生并排除另一个项目。

不复用普通搜索排序、相似度、主题邻居或只返回 active 的反向查询来决定删除范围。保留 SDK 存储、模型和访问线程；仅增加固定版本存储接口的严格适配层和关系规划器，不复制向量／图引擎。适配层应显式验证后端可用，错误向上返回，不静默变成空结果。私有接口的依赖必须由上述探针和实际存储集成覆盖，升级 SDK 时重新验证。

## 范围选择与传播方向

输入限定为已授权项目和用户选中的实际记录 ID。记录归属从存储读取，不能由请求、来源标签或引用字符串决定。服务端分配操作主体，不能接受客户端自称管理员的 actor_id。治理权限与普通读取权限分开验证。

来源边只从 SDK 明确保存的结构读取，包括单一原文指针、`source_raw_memory_ids`、`evidence_raw_ids`、`source_memory_ids`、`evidence_chain`、演化关系，以及图的 DERIVED_FROM。每个指针都核对真实记录及归属；缺失、后端不可读、未知形状或跨项目关联须明确报告，不能悄悄当作完整计划。不能凭“同一主题”或文本语义相似自动扩大清理范围。

规划分两步：

1. 对用户选中记录及其演化版本，追溯明确的来源祖先，形成此次选择的根范围；预览中展示原文和旧版本扩大了哪些范围。
2. 从根范围向派生方向传播，纳入共享这些来源的摘要／派生及其演化版本。**不能再从这些附带派生反向吞并不相关的其他原文。**

例如原文 A 生成事实 X，而摘要 Y 同时依赖 X 和独立事实 Z：选择 X 时需处理 A、X、Y，但不能因此自动删除 Z 及其独立原文 B。Y 的其他来源仍可保留，后续重建只能使用未被抑制的来源。选择 Y 本身时，其来源范围更大，必须在预览中显式展示。这是防止关系连通后误删整个项目的必要区别。

版本循环、重复指针和多路径汇合应去重，并保留每个被纳入记录的原因。同 ID 在不同后端有冲突归属或不一致内容时，不凭向量优先规则跳过冲突。大范围操作需要可恢复的分批计划；扫描或输出超限必须报告未完成，不能截断后声称范围完整。

## 预览、并发与执行

在线预览属于观察结果，不是可以直接执行的快照。开始执行前需要统一的写入隔离，停止新领取，等待已开始的 SDK 操作结束并核对未知结果，然后重新计算范围。`HyMemoryBridge.exclusive_access` 是单个 bridge 的锁，SDK clone snapshot 只是合并并发读取；两者都不能证明全部 Core／SDK 写入者已经停止。

执行计划需绑定实例、项目、治理水位、内容代际和关联范围摘要。范围改变时不能静默执行旧预览；在产品界面或 Agent 操作中更新用户可核对的范围。提交持久意图后才能执行后续动作，过程区分已接纳、抑制生效、执行中、核验中、完成及可恢复失败，不能用意图落盘代替“彻底删除完成”。

忘记保留用户主动查阅原文的能力，停止相关自动读取及再次提炼；彻底删除还必须清理正文、原文、修订历史、派生和索引、队列内容、缓存、受控备份及 Hub 自身保留的内容日志。已经发送给 Agent 的上下文无法从对方会话中撤回，原 Agent 文件和用户自行保存的副本继续遵守需求边界，不自动修改。

重新导入时，仅匹配记忆 ID 不足以抑制换 ID 的同内容。还需要项目内稳定的来源身份和过滤后内容指纹；来源封装中的设备 ID、游标和传输标识不得改变内容规则。指纹使用治理密钥的独立域，不持久化原文或普通哈希。该规范须结合实际写入／提炼路径验证，不能把当前 SDK 精确导入夹具当成跨设备重导入已解决。

## 验证与未完成项

已完成 SDK 探针证明普通检索接口不足以规划完整范围。后续实现了真实存储驱动的[只读范围观察接口](../governance-preview.md)，并以合成数据验证方向性闭包、项目隔离、缺失指针和扫描超限；这仍**不是完整治理验收通过**。下一步接通暂停协调、选择性读取与写入抑制、持久计划和执行器。

至少验证：演化环不死循环；归档派生不遗漏；跨项目引用不越界；共享来源只向派生传播、不侵入独立原文；故障不得返回“空关联”；预览到执行间新增派生会使旧计划失效；崩溃后保持抑制并续做；恢复旧业务数据不会撤销治理记录。当前整体隔离仍是过渡保护，完整忘记／删除和离线缓存要求不变。

这是已授权开发范围内的架构自审，未进行独立同行审查。没有改变用户已确认的保留、删除、跨项目或原 Agent 文件边界。
