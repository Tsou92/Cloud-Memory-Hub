# ADR-0067：在后台修改管理员凭证

日期：2026-11-11。关联 FR-07、FR-12、ENG-01。

## 问题与复用

v0.1.3 仅在初始化时生成管理员凭证，登录后的设置没有修改入口。固定上游的 `UISessionStore` 已提供随机、过期的浏览器会话；Hub 已有同源检查、登录限速、私有文件读取和内容凭证过滤。复用这些能力，不新增账户数据库或改变设备鉴权。

上游会话是进程内 opaque ID，不是 JWT。固定上游与 Hub 初始化命令均没有管理员凭证轮换；因此在 Hub 边界增加小型凭证状态和原子文件写入，前端只扩展现有设置分组。

## 行为

登录后在「设置 → 账户与安全」输入当前凭证、新凭证与确认值，也可在浏览器生成新凭证并自行保存。新值沿用 32–256 字符限制，仅允许无空白的可打印 ASCII；不能与当前值相同。凭证不进入 URL、浏览器持久存储、日志或模型请求。

新增 `POST /hub/v1/admin/credential`。需要管理员身份、精确的同源 Origin 和当前凭证再次确认；管理员 Bearer 也不能绕过 Origin。请求体最多 4096 字节，复用登录失败限速。

成功后新凭证立即生效并持久保存；所有旧浏览器会话失效，清除当前 cookie，要求重新登录。设备凭证、项目授权、模型密钥和记忆保持原状。

## 持久化与失败

继续使用 `config/admin-token` 的私有单文件格式，不迁移数据库。串行完成当前凭证再校验、私有临时文件写入、fsync 与原子 replace；不留下旧凭证备份。明确未替换时保留旧有效凭证。替换后的同步失败必须核对实际文件，不能无条件继续接受内存旧凭证；无法确认时拒绝管理员鉴权并返回固定错误。

认证状态切换、会话失效和内容过滤器更新必须一致。已派生的请求过滤器也必须识别新有效凭证，避免仅替换控制台对象而遗留旧快照。不得修改 frozen HubConfig 的内部字段。

## 兼容性与验收

原初始化、登录、退出及设备 MCP 合同保留。包含本变更的镜像才能显示该入口，v0.1.3 不包含。重启后从现有凭证文件载入新值。沿用既有备份安全合同：恢复已有实例时保留当前管理员凭证；导入空目录时恢复归档内凭证。不改动备份或恢复实现。

合成验收覆盖旧凭证与旧 cookie 失效、新值立即登录与重启后登录、错误当前值、非同源／设备拒绝、请求预算、限速、并发修改、写入失败、派生过滤器的新值屏蔽，以及前端校验和错误恢复。测试结果另行记录，不把源码存在视为发布或真机通过。
