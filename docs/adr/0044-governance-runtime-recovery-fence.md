# ADR-0044：治理恢复失败后的运行时写入屏障

日期：2026-11-10。状态：实现、完整回归和独立审查已完成，安装验收进行中。关联 FR-10、FR-11、ENG-01；适用于现有普通执行器，也作为 ADR-0043 文件恢复接线的前提。

## 问题与已有实现

现有 Executor、Core drain、SDK admission 和诊断排空已经协调完整 worker；Authority 检查主日志、计划与待完成操作，generation permit 和 source authorizer 共用 `require_writes_ready`。继续复用这些入口，不新建队列、持久日志或第二套权限。

实际合成 HTTP 反例：purge 已完成后重试同 operation_id，Purger 重放中的真实 I/O 失败返回 503，但旧 completed 状态、Executor.ready 与 Authority 写入检查仍可保持开放。completed 只能证明过去完成，不能证明当前恢复检查通过。只在 resume 成功时设置 ready，也不会清除之前成功留下的状态。

## 决策与兼容性

区分领取许可与恢复故障：开始排空可暂停领取，但健康情况下已经运行的 worker 仍需完成 SDK、产出观察和日志工作。不能把瞬时 `ready=False` 直接作为 source 写权限，否则治理会破坏正在等待的 worker。

取得 SDK 独占后，增加独立的临时维护计数，保持到诊断、SDK 准入和 drain 的全部退出完成。资源可能先释放锁，再异步退出或报告失败，因此不能只在捕获退出异常之后才阻止新的 SDK 调用。正常退出只解除本次临时计数，不清除此前存在的恢复故障。

最终主日志与计划核验区分两条路径。健康例行检查仅调用原 `require_writes_ready` 核验，不清除故障标记、不抢 SDK 独占，也不增加临时维护计数；保持在途 worker、正常读取和显式维护的并发合同。启动未验证或真实恢复已置故障时，先复用原 drain 与 admission 边界，再进行可解除故障的最终校验，临时计数覆盖其全部退出。该边界不创建 SDK 或诊断存储，空启动继续懒加载。不能因命中重放缓存而直接暂停健康 worker 的许可，也不能让每次健康例行检查造成普通读取 503。

在同一个 Authority 实例上维护仅属于当前进程的恢复故障标记，供现有 `require_writes_ready` 共用。Executor 初始化时保持未验证；成功执行完整 resume 后开放。SDK 调用前许可和 source 写许可原本已调用这个入口，无须另造授权合同。只读结构与抑制检查不依赖该故障标记，避免恢复自锁。上传仍可经过原身份、过滤及抑制检查后持久排队；故障屏障禁止新的 SDK 记忆效果，不把“禁止提炼”误称为所有事件接收或数据库写入均禁止。

```text
启动未验证 ──完整 resume 成功──> 健康、可领取和写入
健康 ──开始维护排空──> 暂停新领取；已运行 worker 继续收尾
实际恢复/执行/排空失败或取消 ──> 故障；禁止领取及新 SDK 调用
故障 ──重新核验全部已提交操作成功──> 健康
```

失败必须在释放维护独占边界前阻止后续写入，并使原重放缓存失效。不能以一个局部操作成功清除既存故障；完整 resume 必须重新验证所有已提交操作及最终主日志/计划关系，不能仅凭本地计划为空开放。治理已启动的 joined worker 在取消后仍等待实际结束；清理/关闭失败仍是失败，不能在 finally 无条件开放。

Core 在等待排空已有 worker 时被取消，会释放本次暂停而让已有 worker 继续，这是现有上游合同。此时屏障阻止后续 SDK 许可与新领取，不强杀已获得许可的执行；下一次完整 resume 重新等待这些 worker。不得将排空阶段的取消返回称为所有既有调用已经结束，也不通过提前撤销健康 worker 权限来制造“已排空”。

原生 Core 管理读取没有 Hub 的逐记录抑制过滤。真实反例表明，精确恢复已删除的原生向量记录后，删除重试在真正清理前失败，Core GET 仍可能返回正文，而对应 RemoteRead 已返回 404。故障期间必须阻止未经此过滤的 Core 业务转发，并在首个响应正文及每个流式块之前重新检查故障；不能把结构 `require_ready` 成功称为所有读取安全。复用现有延迟响应头与流式复核算法，仅增加轻量进程状态检查；保留认证、闭集静态页面和 Hub 治理维护入口，不重复逐块扫描数据库。

最后一次运行状态检查在最外层结构异步检查结束后执行，并在真实响应头发送返回后再次执行，避免嵌套检查通过后、外层等待数据库或响应头期间发生故障却继续发送正文。已经提交给响应发送端的字节不能撤回；后续未发送的正文块停止，连接按原流式协议结束。

请求格式错误、无权限、过期预览、UUID 冲突与已知不支持的用户选择本身不构成运行时恢复故障，不得让任意错误请求暂停正常服务。仅真正进入恢复、持久执行或维护资源发生故障的路径设置故障标记；确认范围检查仍位于意图提交之前。

该标记不写入数据库，不改变主日志、准入证书、operation_id、completed 或旧数据格式；不是独立反回滚证明。进程重启重新从未验证状态开始，依赖原真实重放。当前 schema2 实验组件仍不开放普通服务，不能用本修复替代文件全域覆盖或混合记录授权。

## 验证和并行边界

必须有实际 HTTP/SDK 组合反例修前失败、修后通过：已完成操作重试 I/O 失败后，领取、source 写许可与 SDK generation 均拒绝，未消耗新一次性许可；故障仍在时反复恢复不开放，修复真实故障后的完整 resume 再开放。补充初次启动、普通 resume 失败、真实取消等待、合法落后恢复和故障后读取路径。恢复原生记录后必须验证 Core GET 被拒绝、RemoteRead 仍正确抑制；处理中途与流式输出中途发生故障不得泄漏后续正文；正常静态和治理入口继续可达。

保留正常 worker 排空成功回归，以及过期预览、冲突请求和不支持选择的正常服务可用性。复用现有真实 Core、SQLite、HTTP、SDK 合成写入 fixture 与本地模型替身，不访问真实历史或外部模型。完成前执行相关回归、完整 Hub、`make check`、独立审查和同一镜像的本地/NAS 隔离验证。

实现集中在 Authority/Executor 的运行状态，测试与文档可以独立审查；不并行改相同运行模块。诊断恢复工作图、原记录审阅/确认、Core/Docker 输出域以及产品 schema2 接线仍按原路线继续，不因这一修复视为完成或缩减要求。
