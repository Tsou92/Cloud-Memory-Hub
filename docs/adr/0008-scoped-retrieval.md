# ADR-0008：按项目授权的 SDK 读取

日期：2026-10-24。状态：实现及本地 SDK／HTTP／CLI 验证完成，容器验证进行中。关联 FR-01、FR-02、FR-03、FR-05、FR-07、FR-09、ENG-01；完整自动召回、离线读取和删除传播仍需后续验收。接口见[读取合同](../remote-read.md)。

## 复用与边界

固定上游 `b7d9f0e` 的 `HyMemoryBridge` 已实现记忆列表、语义检索、按 ID 读取及原始记录读取；`builtin_retrieval_snapshot()` 使用本地 ONNX，仅检索、不生成。直接复用 Core 的 SDK library bridge 与关闭生命周期，不新建记忆库、索引或模型服务。旧 `context_raw.py` 查询已退役的 evidence 表且固定 `user_id=local`，不适用于 SDK 权威远程记录。

新增 Hub 授权封装，SDK namespace 由服务端构造为 `cmh:<instance>:<scope>`，与上传一致。请求只接受一个明确项目或 global；不默认合并其他已授权项目。跨项目调用逐项目显式请求，global 也必须单独授权。记忆读取要求 memory:read，原始历史要求 history:read；写权限不授予读取能力。

列表和搜索把 namespace 传入上游查询，候选产生前即限制范围。上游按 ID 接口只有主键参数，无 scope 参数；Hub 先授权，再读取单个主键，核对返回的 user_id 后才构造响应，越界和不存在均返回 404。此路径不调用生成模型、不把越界记录加入上下文。搜索返回的格式化聚合文本不直接输出；读取其有限个成员的当前权威记录，核对 namespace、active 和 is_latest，避免旧摘要掩盖生命周期变化。不是全库搜索后过滤。

## 合同与隐私

增加 POST `/hub/v1/memories/{list,search,get}` 和 `/hub/v1/history/{list,get}`。查询词放在 JSON 正文；连接组件从 stdin 读请求，先使用现有本地过滤器，再传输。NAS 拒绝仍需过滤的查询，不将其交给 SDK；响应内容再做凭证过滤。不存在默认真实历史导入或客户端配置更改。

每次读取前检查当前凭证和项目权限，返回前重新检查；期间设备 revision 变化也拒绝本次结果，即使权限撤销后又恢复。无法撤回已经发出的数据。原始内容和来源 metadata 是不可信历史，不是指令；来源正文中的标记不是服务端认证声明。返回 scope、实例、设备 revision、SDK 原始引用和分页位置，省略与读取无关的内部资料。文本分块且明确 next_content_offset；分页是实时视图，不是同步游标或一致快照。读 API 不把空列表等同于处理完成。

真实 SDK 用例揭示：其列表序列化未输出 is_latest，bridge 默认值会误把旧版本视为最新。因此列表也按 ID 重新核对权威状态，失效条目移除但保留真实分页推进。SDK get 的 source 是 vdb／graph，不能冒充来源应用；记忆中的该字段留空，通过原始引用读取实际来源。

每次列表最多 10 条、文本块 4096 字符、搜索最多检查 64 个成员，响应最多 120 KiB。最多两个并行 SDK 读取，忙时固定 503；网络层保留现有完整请求期限。上游同步线程无法强制安全取消，取消时沿用其等待线程退出行为，保持占用槽位，避免超时请求无限堆积。SDK list_raw 内部最多读取 100000 个 scope 内条目再分页；当前接口不声称完成大规模历史性能验收，后续需优化上游存储分页。

## 兼容性和验证

本轮不改数据库 schema 或已有写入合同；session 增加 scoped_reads 能力标识。旧服务端不具备能力时客户端拒绝读操作，不回退管理员接口。撤销来源仅停止该来源后续写入，已有记忆仍由项目读权限控制；忘记、彻底删除需要独立治理合同，不以撤销来源代替。

验证包含真实 SDK 合成存储／本地 embedding 检索、同项目跨来源读取、项目与 global 隔离、权限分离、猜测 ID、失效／取代记忆、检索期间撤销／轮换、凭证过滤、分页和已安装 CLI。实际 Agent 下一轮注入、两台 Mac、NAS 正式 HTTPS、模型提炼质量、删除后离线缓存失效均不能由这些测试代替。
