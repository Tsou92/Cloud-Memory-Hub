# ADR-0006：远程来源与上游持久写入接入

日期：2026-10-23。状态：接纳端已实现，本地／NAS 容器及空实例升级回滚验证通过。关联 FR-02、FR-03、FR-04、FR-06、FR-07、FR-08、ENG-01；本批不宣称完整同步、召回或删除恢复验收。

> 历史设计说明：以下 schema v1 的“回执仅存摘要／正文只存队列”方案已由 [ADR-0017](0017-accepted-original-archive.md) 取代。接纳 schema v2 在同一回执事务保存完整过滤原文；设备权威库也已由 ADR-0011 升为版本 2。旧处理队列和 SDK 暂存回收不能满足长期原文要求，不能将本 ADR 的预期投影当作长期保留证据。

## 复用与补充

固定上游 `b7d9f0e` 的 `memory_server/durable_queue.py` 已提供持久接纳、幂等冲突、claim／lease、模型等待、unknown 核对和 SDK 输出回执。Hub 直接调用同一 `DurableWriteQueue.submit/get`，通过 `EvidenceInput`／`materialize_write_input` 和 `WriteRequest` 冻结输入，不复制队列 SQL，不新增模型调度。

`api.py::_source_writes_on` 仅识别本机来源授权。增加可选的来源判定回调，未接管的来源继续原逻辑；Hub 只接管 `cmh:` 来源。现有 claim、supervisor 和最后调用模型前的检查都复用这个入口。回调故障按拒绝处理，不将远程来源伪装成本机文件授权。

## 来源、项目及接纳

管理员创建来源，绑定一个设备和一个项目／global scope，登记任意合法 adapter 标识，不限制 Agent 品牌。服务器生成 source UUID；设备只能向属于自己、未撤销且 scope 一致的来源上传。来源 scope 不可原地改变，重新关联需新身份，避免旧离线内容被默默转移项目。

`POST /hub/v1/events` 使用设备 Bearer，接受 ADR-0005 的已过滤事件；先检查身份，再读有上限的正文，并在持久接纳事务内重新核对身份、来源与 `events:write`。服务端重复过滤检查只做防御验证，发现仍需过滤则拒绝，不代替 Mac 上传前过滤。

投递 ID 映射到稳定上游 request key；原始 source／conversation／record／revision 保留在输入身份和元数据中。服务器自建 SDK user namespace 对应 instance + scope，同一项目可跨来源共享，全局偏好处于独立 namespace；设备提交的 SDK user/agent 身份不被接受。后续读取必须按授权 namespace 查询，不能先全局查再截断。

正文支持 `conversation_turn` 的 messages（role、text、可选 metadata）和 `operation` 的 text／metadata。顶层 content metadata 和各条 metadata 随对应正文作为明确标记的历史来源资料保存到 SDK 原文投影，不能只留在最终会清理的处理队列。未知字段、超限或无法解释的内容拒绝，不静默丢弃。这些是历史资料，不是新系统指令或工具授权。

返回 receipt 含 instance/device/event ID、已过滤事件摘要、稳定 receipt ID、`status=accepted` 和上游 `processing_state`。这只证明持久接纳；处理成功、另一端可检索和 60 秒目标分别验收。未配置模型时仍能保存已接纳任务，不能伪报 processed。

## 事务、撤销及兼容性

来源及事件回执仅保存身份、摘要和上游 job/request ID，作为设备权限库的独立 `cmh_ingest_schema` 扩展 v1；设备基本 `PRAGMA user_version=1` 保持不变。旧镜像忽略附加表，保留原设备撤销能力，未知 `cmh:` 来源无法被旧处理权限放行。扩展缺损／未知版本拒绝打开，不能删表重建。

接纳持有权限库写事务，核对权限后调用上游持久提交，再记录回执。设备／来源撤销与接纳在同一权限库串行。两个数据库不宣称分布式原子提交：若 Core 已提交而回执事务失败，同一确定 request key 重放会取得原 job，不产生重复模型任务；返回成功前必须两边均提交。测试需注入这个窗口。

来源／设备撤销后拒绝新上传与设备状态读取，未开始调用模型的任务由原队列权限检查挡住。已经发出的外部请求不能撤回；此前已合法接纳的来源内容不会因设备凭证撤销而自动删除，内容删除继续使用独立治理语义。任何后续读取与结果返回都需重新检查当前权限，不能使用旧会话授权缓存。

本批不修改已有 Agent 配置，不导入真实历史，不激活真实模型。离线传输组件在来源与接纳端验证后接入。忘记／删除水位、回放抑制、原始历史去重、原文检索及客户端下一轮注入仍保持待完成，不能将上传成功视为整个目标完成。

## 设计自审

来源管理与设备权限使用同一短事务，避免授权快照过期后继续接纳；实际内容仅在已有 Core 队列中存一份。处理前回调重新查询当前设备／项目／来源状态，不使用请求时缓存。Core 已接纳而 Hub 回执未提交的窗口通过确定的上游请求身份恢复；终态正文回收后仍使用原摘要核验重放。模型调用结果不由 Hub 再写一套状态机。

服务端源控制与持久回执是新增的远程信任边界，不能用上游本机文件授权代替。补丁仅加入默认关闭的可选判定回调，未接管来源保留原规则，并保留原队列／统一写入回归。每次请求的持久操作放在线程池，授权按主键查询；没有新增服务或依赖。此为开发者自审，完整验证记录见 [接纳端记录](../reviews/2026-10-23-remote-ingest.md)，不是独立同行审查。
