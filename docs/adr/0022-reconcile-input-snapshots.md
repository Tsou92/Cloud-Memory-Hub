# ADR-0022：合并决策的实际输入快照

日期：2026-10-29。状态：接受，实施中。关联 FR-08、FR-09、FR-10、FR-11。

## 问题与复用

固定 SDK 的 CodingWriter 同时用于 working／coding。经验 reconciler 把检索后的候选传给同一次模型决策，再原地更新经验；事实 reconciler 还会从历代事实生成摘要和继承 details。已有 output IDs、history_request_ids 和链轮次无法说明这些输入，且原地更新后，仅凭旧 ID 不能重建模型当时看到的正文。

复用原生候选格式化、事实历史截断、details 预算分配、写入结果持久化及按 request_id 重放。不另建提炼器或运行数据库。最小 SDK 补丁在实际使用点捕获不可变候选快照、格式化输入片段和成功／失败状态，由原 durable result 保存。候选的完整记录快照用于身份与版本核对，rendered 片段用于区分实际呈现文本；未呈现的字段不被宣称为模型输入。

## 合同及兼容性

生产力结果新增 `reconcile_inputs`，格式版本 1；分阶段记录经验决策、事实决策、事实历史摘要和 details 继承。快照包括真实类型、原生 ID、完整记录和当时呈现的输入片段。摘要和 details 阶段关联新事实 ID。决策成功、空决策回退及异常回退分别记录，异常只留类型状态，不保存异常消息。没有 drafts 时是已捕获的空阶段，不把字段缺失的旧结果推断为空输入。

捕获对象属于一次 write 调用，不挂在共享 reconciler 上，防止并发串台。记录经 JSON 深拷贝后冻结；后续 UPDATE、SUPERSEDE 和对象修改不能改写既有输入。捕获有数量和序列化字节预算；失败或超限时整个捕获标记 unavailable，不返回部分 complete。捕获故障不改变上游原有 ADD／INSERT 回退语义，也不重新调用模型。响应仅在原持久结果成功提交后具备重开证据。

不改变已有结果字段、表版本、模型提示词或调用参数。旧代码可继续读取新增字段之外的数据；现有 Hub 关系图暂不把快照 ID 当作当前记忆的父节点，避免原地 UPDATE 形成虚假的自引用。后续关联层必须区分旧版本输入和本次产出，核验归属与来源后再使用。普通聊天输入、完整输入来源合并、选择性执行和恢复防复活仍是总目标中的未完成工作。

## 工程自审及验证计划

架构：仅扩展固定上游的可选捕获参数和 CodingWriter 响应，沿用 SDK 持久结果。质量：捕获逻辑集中，失败状态明确；不通过检索结果或最终操作猜测未记录的输入。性能：每次写入最多 512 条快照、512 个阶段和 2 MiB 捕获数据，超限整项不可用，不追加无界日志。

```text
实际候选检索 -> 模型输入快照 -> UPDATE 原记录 -> 旧快照保持相同
事实替代 -> 截断后的历史 -> 摘要实际输入／details 实际入选片段
空 drafts／空候选／模型异常／空决策 -> 明确状态，不制造完整依赖
并发写入／字节超限／非法快照 -> 独立捕获或 unavailable
真实 SDK add -> durable result -> 进程重开／同 request 重放 -> 相同捕获
```

运行集中测试、相关固定上游回归、完整 Hub 回归及 `make check`；安装包／NAS 验证必须另有实际运行证据。本记录为实现者的架构、质量、测试和性能自审，不代表独立同行审查，也不代表删除执行已完成。
