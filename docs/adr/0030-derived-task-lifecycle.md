# ADR-0030：写入派生任务的生命周期

日期：2026-11-04。状态：实现与验证中。关联 FR-02、FR-04、FR-10、FR-11、ENG-01。

## 复用调查与范围

固定上游 writer 的 `_schedule_episode_summary` 使用 `create_task` 启动会话滚动摘要，但没有保存句柄；`write` 和 `write_extracted` 的 finally 只等待图投影。SDK 随后保存终态写入回执，Hub 的共享准入也随调用结束而释放，因此会话摘要可能在回执完成和维护屏障进入后继续写入。图投影包含主题摘要，已有请求级句柄，但直接 await 在取消时会传播取消，不能作为稳定的派生任务收尾。

复用原会话滚动、摘要函数、图投影、请求对象、SDK 回执库和 Hub 准入；只在 writer 增加请求级句柄及共同收尾。主流程期间继续并发，所有退出路径在返回之前等待本次派生任务实际结束。没有新队列、数据库或摘要算法，也不改变用户的功能开关。同步 session/dynamic/series finalize 已被原流程 await，保持原路径。

## 生命周期与兼容性

```text
SDK 接纳写入 -> writer 主流程 + 本请求派生任务并发
                 -> finally: shield + 等待全部派生任务
                 -> 返回 / 重新抛出取消
              -> 原 SDK 终态回执 / unknown
              -> Hub 释放 SDK 准入 -> 维护可进入
```

请求保存会话摘要任务列表，避免句柄丢失；图仍保留原请求级句柄。共同收尾使用 asyncio.gather(return_exceptions=True) 等待全部任务，外层 shield 防止调用者取消传播到任务。重复取消仅延迟传播至收尾完成，不清除调用者的取消状态。子任务自身取消也在其他任务结束后传播。普通摘要／投影异常沿用原有非致命处理；取消后 SDK 保留 unknown，不自动重试写入。

原图投影的提前等待仍可使用，完成后移除对应句柄；最终收尾可重复调用。每个请求仅等待自己的任务，不使用 writer 全局任务集合，不串行化不同用户。等待后才释放句柄，避免提前失去任务引用。取消语义依据 [Python 3.12 asyncio 文档](https://docs.python.org/3.12/library/asyncio-task.html)：TaskGroup 会在异常时取消其他任务，不符合已开始写入必须先完成收尾的要求，因此采用已有 create_task 配合 shield/gather。

不修改数据 schema、SDK 结果字段或现有记忆 ID。正常写入可能多等待尚未结束的摘要时间；这属于完整写入的实际耗时，不能再以过早回执满足时效目标。进程崩溃、运行循环被强行关闭或外部直接取消底层存储任务仍需持久恢复核对，不能用本次进程内收尾宣称崩溃安全。

## 验证与顺序自审

先以阻塞的合成摘要复现“writer 已返回、摘要仍未结束”；修复后验证正常与失败退出、重复取消、图任务取消但摘要仍在运行、同请求多个任务、同 writer 并发请求、SDK 持久结果及 Hub 维护屏障。相关上游 episode、写入结果、图投影回归和完整 Hub 套件需运行。安装制品与 NAS 结果单独记录。

结构仅修改上游 writer 的一处生命周期边界，测试复用真实 SDK/存储并明确标注模型替身；复杂度为本请求任务数 O(n)，不增加存储查询或模型调用。架构、代码、测试与性能采用顺序自审，不是独立同行审查。完整摘要输入快照、生产来源、执行时序证明、删除执行、恢复防复活及两机六入口仍按原目标继续；本次不开放删除执行。
