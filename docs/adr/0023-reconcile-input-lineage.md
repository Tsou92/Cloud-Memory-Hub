# ADR-0023：不可变输入的生产来源与关系合并

日期：2026-10-30。状态：接受；原生来源标记、Hub 输入归档与关系合并已通过本地／NAS 安装和兼容性验证，常驻实验实例已备份升级并重启健康。关联 FR-08、FR-09、FR-10、FR-11。

## 复用与关键缺口

ADR-0022 已保存模型合并时实际看到的记录，但原生经验 ID 会被 UPDATE 重用，不能把旧输入直接连到同 ID 的当前记录，也不能按归档接纳时间推测生成顺序。复用 SDK 原生 SQL upsert、持久写入结果、Hub 原文归档和方向性规划；在正文的同一条 SQL 写入中记录其生产请求和内容摘要，再用已核验 SDK 产出与原文交叉验证。

## 原生来源标记

经验及事实表各增加可空的 `origin_request_id`、`origin_digest`，沿用上游已有的 additive-column 初始化；旧行保持无来源，不猜测回填。reconciler 从 writer 显式传入 SDK request_id，不能由模型生成。insert／update／insert_fact 默认不携带来源，必须显式传参才会设置标记；独立调用更新已读对象不能沿用它旧的来源。两个标记与正文在同一 SQL upsert 中写入。

摘要覆盖身份、作用域及语义内容和原生创建／更新时间；摘要同时绑定生产请求 ID，排除摘要本身、原生反向关系及事实状态／后继指针。这些排除字段会由后续事实替代或互链更新，且不属于被捕获的模型正文；它们继续按现有显式关系观察。捕获仍保存完整记录和实际 rendered 片段。旧镜像若修改正文却保留来源列，新版核验摘要时拒绝过期来源。内部一致性摘要不是治理目标指纹，也不声称能抵抗能任意修改全部数据库的管理员。

## Hub 持久化与图方向

新增独立版本的输入归档扩展表，在原输出关系及上下文的同一事务中保存 schema、状态、阶段、实际输入、成功产出目标和摘要。旧结果以 `capture: null` 表示 unobserved；unavailable 不变成空 complete。捕获预算和整体库存预算都生效，损坏、跨项目、来源缺失、生产结果不匹配或循环必须明确拒绝，不能生成部分完整范围。

扩展表采用独立 schema 1；与旧 lineage／context 表并存，旧镜像可忽略新表读取既有格式，新版通过完成队列补核对旧回执，不重复调用模型。写入时核验快照格式、项目和来源摘要，但允许其生产任务尚未完成；读取关系时再要求生产原文、已证明的类型化产出及输入证据齐全，避免跨任务提交次序造成循环等待。新捕获明确 unavailable 或有实际输入却缺生产证据时，预览拒绝提供不完整范围；旧结果 unobserved 保持既有观察边界，不宣称完整血统。

生产记录的 user／agent／source 必须与生产请求一致，事实另核对 session；输入允许同项目不同来源，但不能跨项目。来源链接同时带上生产轮已捕获的历史上下文，避免只跟随合并阶段而遗漏提炼输入。fallback／skipped 的副本需追溯保留，但不会成为本次成功产出的语义父节点。阶段图单独检测循环，且全局记录、边、字节预算覆盖新增快照。

将每个阶段作为独立 `cmhi:<receipt>:<stage>` raw 历史节点，保存其实际输入片段和不可变快照；父节点包括本轮原文、被验证的生产原文及该旧产出实际依赖的输入阶段。只有 used 阶段影响实际成功产出的记忆；fallback／skipped 仍作为该次持久结果中的历史副本保留，不能假装影响了最终产出。阶段 output_id 必须与本次成功产出核对。所有生产来源必须对应同项目的已接纳原文及精确类型的已核验 SDK 产出。

```text
原文 A -> 生成旧记忆（正文和来源标记同次 SQL）
旧记忆 -> B 的实际输入阶段 -> B 的成功产出
     A 的输入阶段 ---------^
B 原文 -------------------^
C 后来更新同一 ID：不把 C 原文写回 B 的历史输入
```

不从旧输入连到可变的当前记忆，因此同 ID UPDATE 不产生自引用。读取原文来源时可继续沿阶段查到真正的生产原文；选择某一原文后沿派生方向扩展，不反向吞并其他独立原文。新前缀加入普通记忆保留标识校验。

## 工程自审与验证

架构：保留原 SDK 正文及写入结果权威，不新增提炼队列。质量：来源由存储写入点生成，Hub 复核记录摘要、身份、原文及已证明产出；不信任单一候选 ID。性能：按项目批量读取，使用现有请求索引和内存映射建立有界图，不逐节点调用模型或反复扫描全库。

覆盖真实 ADD→UPDATE→再 UPDATE、事实替代／历史继承、同 ID 多轮顺序、重启及补核对；验证旧结果／直接插入无来源、旧代码改写、来源伪造、跨项目、缺失生产记录、损坏 JSON、循环和预算。运行相关上游、Hub、源码／安装探针、NAS 及工程门禁。自审不等于独立同行审查。

本次仍不开放删除执行。普通聊天全部输入、在线维护排空、选择性抑制、物理清理、备份防复活和六入口两机闭环继续属于原目标，不能由关系观察替代。
