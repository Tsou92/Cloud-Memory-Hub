# ADR-0055：被明确拒绝的上传不阻塞后续队列

日期：2026-11-10。状态：本地回归、NAS 隔离安装、两机备份升级及新版 MCP／CLI／项目钩子验证通过；已有宿主会话 MCP 热重载未验证，见[验证记录](../reviews/2026-11-10-terminal-upload-rejections.md)。关联 FR-01、FR-06、FR-10、FR-11、ENG-01。

## 已复现问题与复用

[联合验收](../reviews/2026-11-10-next-turn-and-reconnect.md) 在 NAS 当前安装镜像复现：忘记后重投相同长句，服务端正确返回 `409 governance_content_suppressed`，但客户端把所有 409 映射为身份冲突，保留队首并停止，使后一条正常事件也不能投递。

复用现有 LocalOutbox、设备绑定、过滤后事件、HTTP 上传及 capture 原子事务；上游 Core 队列负责服务端模型处理，不负责 Mac 的网络投递，不能拿它替换本地持久队列。仅增加本地终态记录与明确拒绝的分流，不实现删除规则广播、离线读取缓存、日志治理或 NAS 业务库迁移。

## 最小行为变更

仅当向已通过实例、设备和来源预检的 `/hub/v1/events` 上传时，实际 HTTP 409 返回有界、格式正确的 JSON，且精确原因是 `governance_content_suppressed`，才将该事件记为终态 rejected。响应正文不进入日志，未知字段／未知原因、截断／过大／无效响应、其他 409、403、鉴权失败和身份不符仍沿用停止与保留行为，不推断为可丢弃内容。

终态记录保留原事件、过滤后正文、摘要和封闭原因；不产生接纳回执、不冒充 accepted、不再自动上传该事件。同一批继续后续合法事件，重启后继续跳过该终态。同一事件重复提交返回 `status=rejected`、固定 error 和 `retryable=false`，不重新入队；换内容复用 ID 仍拒绝冲突。状态的 `rejected` 原因计数包括服务端终态拒绝，与 queued／accepted 分开。

记录拒绝须在本地写事务中核对事件 ID、设备／实例绑定、payload 摘要以及尚未 accepted；重复同一拒绝幂等。acknowledge 不得覆盖已拒绝事件。持久化失败仍停止，不能只在内存跳过。只有明确的上述语义拒绝可继续；既有隐私、权限和完整性检查不降级。

## 本地格式与升级

LocalOutbox 升至 schema 2。保留原 `events` 表、序号、接纳状态和全部 payload，新增按 event_id 绑定的 `delivery_rejections` 表，保存 payload_digest 与封闭 code。pending、enqueue 返回值及计数据此派生终态；原有 capture 表、capture_schema 与 capture-key 均保持。

新建队列直接使用 schema 2。普通打开 schema 1 明确要求升级，不隐式修改；旧客户端继续因版本不支持而拒绝 schema 2，不能忽略终态表重新发送。提供仅本机的显式 `upgrade-outbox` 命令（Agent 与 connector 入口），要求指定新的私有备份文件，不通过 MCP 暴露迁移。

升级校验私有路径、当前绑定和版本，在排除其他写者的事务内取得一致 SQLite 备份，再增加表及版本。失败保留原库或原子回滚，不覆盖既有备份；已经升级可幂等返回。备份不是复制一个正在变化的主文件。两机安装时先准备新运行目录，暂停会使用该队列的旧客户端入口，备份、升级并将该队列的 MCP／Skill CLI／hooks 全部指向新版本；不保留旧 reader 与新格式混用。回退仅在停止使用并确认未产生需保留的新事件后恢复完整升级前状态，不能只降级程序。

## 验收

- 原阻塞用例先在旧实现失败，再证明拒绝项保留且下一合法项接纳；重开客户端不重投拒绝项，重复提交和计数幂等。
- 未知 409、错误类型／正文、权限失败、摘要或身份不符仍停止，后项不被错误放行；持久化故障保留现场。
- schema 1 一致备份及升级保留 queued、accepted、原回执、序号和 capture 游标；失败回滚、重复升级、旧 reader 拒绝 schema 2。
- 当前安装镜像／NAS 独立实例验证普通 forget、混合事件整条拒绝、后续合法事件继续，无新增被拒回执或任务；保持搜索排除和原文可显式读取。
- 两台 Mac 使用新客户端与原 NAS 服务完成真实接纳、读取与 hook 回归；凭证不输出，不重放既有 unknown 模型任务。
