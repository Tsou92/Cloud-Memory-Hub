# ADR-0070：一次完成 NAS 首装和首台设备接入

关联 FR-01、FR-02、FR-03、FR-07、FR-08、FR-12。入口在电脑执行，沿用 SSH 登录，由同一次运行下载并校验固定 GitHub 正式制品，复用该版本的 Compose、初始化和健康检查。默认通过已登录的 Tailscale Serve 提供私网 HTTPS，也可使用已指向目标端口的 HTTPS 入口。模型配置独立于会话接续。

只管理该安装器创建的 Compose 项目、目录和私网监听。重跑恢复同一实例，遇到已有非托管安装、端口或其他卷时明确停止。升级仍走原发行升级流程。本次无业务库迁移，不复制上游记忆、配对或模型能力。

安装器在已启动的容器内通过现有项目与邀请 API 完成首台连接。管理员凭证留在 NAS，一次性链接通过 SSH 输出管道和本机私有状态传给现有配对器，不写入命令、聊天、安装输出或源码。已有配对进度重用同一领取身份。电脑默认使用当前目录名和设备名，模型设置和手工项目创建从基础接续入口移出。

需要先部署服务时，`--nas-only` 复用同一套 SSH、镜像校验、Compose 和健康检查。服务就绪后输出管理地址并以 0 结束，配对由后台发起。该模式可直接使用已有 Python 3.11 以上版本，不创建本地工作区、设备身份或客户端设置。CLI 在连接前拒绝示例占位符 `USER@NAS`，下载和导入镜像时输出阶段。

本机 Docker 目标通过 `--local` 或 PowerShell 的 `-Local` 选择，复用经校验的正式 Compose 和 Linux amd64 镜像。仅连接本机 Docker，默认地址为 `http://127.0.0.1:8800`，不需要 SSH 或外部 HTTPS。管理页首次设置继续使用从实例私有管道读取的证明。已有其他 Docker 项目受所有权检查保护。

命令自动配置受支持的项目钩子。Codex 桌面的首次信任按宿主原有要求完成；命令区分 NAS 健康、MCP 配置和等待宿主启用。普通对话被 NAS 接纳且另一会话能读回，才算通过自动接续验收。OpenCode、Hermes 和通用 MCP 的自动采集边界沿用现版。
