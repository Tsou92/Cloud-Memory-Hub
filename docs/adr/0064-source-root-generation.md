# ADR-0064：本地来源目录重建后重新授权

状态：已实现，macOS 完整 Core 与 NAS 定向回归通过；最终提交 CI 和发行镜像待验。关联 FR-07、FR-08、ENG-01。

## 原因与复用

固定上游 `b7d9f0e0f417eae30b192882f848b432484c20a6` 的
`one_memory.imports.access` 已有目录授权、描述符相对读取和路径复核。
继续使用这些入口、`SourceGrantStore` 和既有来源候选确认流程，不另建授权系统。
真实 GitHub CI 的两项原测试发现：Linux 删除并重建目录后立即复用 inode，
旧 `root:v2` 的路径、inode、mode、uid、gid 全部相同，状态与实际读取均错误放行。
保留这两项测试；不能通过延迟、保留旧 inode 或跳过 Linux 来消除失败。

上游 `_changed_ns` 仅能从 macOS 的 stat 读取创建时间，Linux 返回零；
固定源码没有可复用的 statx 实现。因此增加最小 Linux 元数据适配，复用原哈希和拒绝流程。

## 身份与错误合同

新的 `root:v3` 包含规范路径、inode、mode、uid、gid 和纳秒创建时间。
继续排除 `st_dev`，保持 macOS 重启后卷设备号变化不撤销同一目录授权。
不使用会随目录子项活动变化的 mtime／ctime。

Linux 从已打开目录描述符通过 `statx(AT_EMPTY_PATH)` 读取所需字段，检查返回
mask 包含权限、所有者、inode 和 `STATX_BTIME`；不能把请求位当作返回支持。
元数据来自同一次查询。macOS 使用同一已打开描述符的 fstat 创建时间。
路径身份检查和实际文件读取前的根描述符检查必须使用同一算法。
字段缺失、系统接口不可用或查询失败均返回既有 `source_unavailable`，不回退到零或仅 inode。

独立审查复现了同一授权边界的目录切换问题：构造的根对象与随后按路径核对的目录可能
不同。`SourceGrantStore.authorized_root` 必须把返回对象的 `root_identity` 与保存授权
精确比较；grant 与 connect 还必须把构造对象的身份与用户确认的 expected 身份比较。
保留原路径复核，不能只增加一次路径查询。反例必须验证替换目录正文不可被实际读取，
以及不匹配对象不能写入授权或候选表。

创建时间用于识别普通文件系统目录重建，不是防特权篡改的密码学身份，也不宣称文件系统
保证其全局唯一。本机 Linux 独立卷 10,000 次连续目录重建出现 9,999 次 inode 复用，
创建时间全部不同；该实验是已观察证据，不能替代 NAS、CI 或所有文件系统的保证。
本次只修复来源根目录身份；原生文件级身份合同不顺带重构。

## 兼容与升级

现有字符串字段可保存 v3，无需数据库表迁移。旧 v2 缺少原目录创建证据，不能静默升级：

- 保留授权行、历史、队列和游标；旧授权按身份变化拒绝继续读取，用户重新预览、确认当前来源。
  默认／环境来源已有 location → authorize 或 connect 的明确确认入口。旧自选目录的
  `source_candidates.root_id` 同时被锁定，现有重新连接会拒绝；该恢复缺口必须单独验证，
  不能把新身份算法本身写成已完成所有旧来源的迁移。
- 旧候选确认令牌不能直接沿用，必须重新发现候选并确认新的身份。
- Hub 本地历史采集的 `CaptureStore` 也绑定根身份。旧绑定停止并报告
  `capture_binding_mismatch`；不能覆盖绑定或删库来消除错误。现有 MCP 设备凭证、
  项目权限和远端 memory／handoff 不使用该目录身份，保持不变。
- 本地采集恢复需明确登记当前来源；没有原目录证据时不能承诺保留原身份的自动迁移。
  现有安全操作是登记新 source UUID 后在原状态目录 capture-init，保留旧表与密钥；
  新来源的游标／去重空间独立，可能重新扫描并重复导入，不能称为无损续采，不能自动执行。
  客户端升级说明必须标出这一限制。
- 回滚旧代码会恢复旧目录识别缺口，不作为安全恢复手段；保留备份供核对，生产升级先验证。

旧自选目录的有限恢复复用现有显式 `sources/connect` 事务：仅当保存的候选和旧授权
共同指向同一个 v2 身份、候选 revision 精确匹配、用户明确确认自选目录，且请求提交的
v3 身份与当前目录匹配时，允许重新授权当前目录。候选路径仍由已保存候选解析，不能
在该入口改路径。候选身份和 revision 与新授权在同一事务内更新，失败回滚；运行中的
导入仍拒绝，其余旧任务沿原 root_changed 流程取消。旧请求 ID 的重放保留原幂等合同，
不会暗中升级授权。此为明确批准当前目录，不能据此断言当前目录就是最初授权的对象。
缺少确认、过期 revision、任意 v3 身份不匹配或旧候选／旧授权不一致均维持拒绝。
普通 v3 目录迁移和任意旧采集绑定的自动重绑不在此例外内。
