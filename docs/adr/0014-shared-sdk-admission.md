# ADR-0014：实例内共享 SDK 操作准入

日期：2026-10-26。关联 FR-10、FR-11、FR-13、ENG-01。沿用 [范围设计](0012-governance-scope-and-lineage.md) 和 [进程租约](0013-runtime-storage-exclusion.md)。本步只提供 SDK 操作屏障，暂不开放维护或删除 HTTP 接口。

## 复用调查与范围

固定上游 `HyMemoryBridge.exclusive_access()` 已按 asyncio Task 支持单 bridge 重入；`_joined_thread()` 会在请求取消后继续等待实际线程结束。直接复用二者，不能把它们替换为取消后立即释放的锁。Core 的处理 supervisor 工厂与 `_sdk_library_bridge()` 会创建不同 bridge；前者的 prepare 初始化也未经过 exclusive_access，因此单 bridge 锁不能保证全实例排空。

最小补丁为 Core／bridge 增加可选异步上下文工厂，传给以上两处工厂；无注入时保持上游行为，prepare 纳入已有互斥。Hub 仅新增一个实例级协调对象，提供准入和内部独占观察上下文。继续复用现有 Docker／Mac 制品，不引入新调度器、数据库、协议或外部服务。

## 状态与顺序

```text
普通 SDK 操作 -> 实例准入 -> bridge 独占 -> SDK／已加入等待的线程 -> 退出准入
内部独占请求 -> 立即关闭新准入 -> 等所有已准入 Task 退出 -> 请求者独占 -> 恢复准入
                    新 Task 拒绝       已准入 Task 可重入
```

同一 Task 的嵌套 bridge 调用算作同一次准入；身份来自 current_task，不能用可被子 Task 继承的 ContextVar 作为持锁证明。不同 bridge 的正常操作保持原有并发，等待 bridge 局部锁的操作也计入在途。独占请求者不能已经处于普通操作中，不能重复或并发请求独占；这些情况明确报错，避免等待自己死锁。关闭准入后新 Task 立即返回固定 bridge 错误，不无限积压等待者。

屏障只在一个事件循环内使用，跨循环误用明确失败。采用 asyncio.Event 通知在途集合清空；加入／退出集合和状态切换不含 await，退出时不会因重复取消而漏掉释放。取消独占等待或独占主体失败会恢复普通准入，但不取消现有 SDK 工作，也不声称其未写入。独占主体的同 Task 可以调用 SDK 做核对，子 Task 不继承这个特权。

使用标准 [asyncio 同步原语](https://docs.python.org/3.12/library/asyncio-sync.html)；它们不跨线程同步。请求取消不能停止底层线程，继续沿用上游等待实际结束的策略，参见 [asyncio 任务取消与线程](https://docs.python.org/3.12/library/asyncio-task.html)。协调对象不保存正文、凭证或外部任务标识。

## 边界与兼容性

这还不是完整维护协调器：队列中已领取但尚未进入 SDK 的任务、未知写入结果、管理数据库与新上传接纳并不在该集合内。后续必须先阻止领取／接纳、等待整项执行、核对未知结果，再进入 SDK 独占并重新规划。当前不调用这条内部独占能力进行真实治理，不把 SDK 空闲等同于可安全删除。

合作服务进程仍由存储租约隔离。直接调用底层 SDK、上游独立 CLI 或私有 `_get_client()` 后自行使用 client 都不属于本协议；Hub 产品路径必须通过 bridge 或显式 exclusive_access。底层 SDK 自身的后台行为仍需单独核实。普通运行不自动暂停，不修改用户的提炼开关或来源授权。

## 自审与验证计划

范围审查：一个协调类、一处可选上游扩展及两处工厂接线。架构与错误路径已明确；代码质量保留原有错误类型和锁顺序；性能为每个最外层操作 O(1) 集合更新，不扫描存储、不将不同 bridge 串行化。顺序实现，不启动多 Agent；本记录不是独立同行审查。

| 路径／故障 | 所需验证与可见结果 |
| --- | --- |
| 两个 bridge 正常并发，维护同时进入 | 维护等待两个实际操作结束；新的操作明确拒绝 |
| 在途 Task 重入另一个 bridge | 可以完成，不被自身屏障阻塞；子 Task 被拒绝 |
| 等待或持有独占时取消、主体异常 | 恢复准入，已运行工作不被错误标记完成 |
| 自身升级、并发独占、跨循环调用 | 固定错误，不死锁、不变成永久暂停 |
| 请求重复取消，底层线程仍运行 | 屏障持续等待线程实际结束，随后可独占 |
| SDK 初始化／读取／写入／关闭 | 均进入同一实例准入；上游未注入调用保持原行为 |
| Core 管理读取与处理工厂 | 实际 Core lifespan 验证两处接线；合成 SDK 数据可在独占前后读取 |

执行 `make check`、Hub 运行时测试及上游 bridge／SDK API 对应回归，结果见[验证记录](../reviews/2026-10-26-sdk-admission.md)。安装制品与 NAS 验证单独记录，源码测试不能算作安装或真机通过。完整队列协调、持久计划、选择性抑制与删除执行仍按原里程碑推进。
