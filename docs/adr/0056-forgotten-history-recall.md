# ADR-0056：自动历史列表排除已忘记原文

日期：2026-11-10。状态：本地实现与回归通过，待集成审查和服务端安装验证。关联 FR-03、FR-05、FR-10、FR-11、ENG-01。

## 已复现问题与复用

真实 SDK、Hub 治理与 HTTP 的合成复现确认：忘记执行完成后，记忆搜索已经排除目标，但 `history-list` 仍返回已忘记原文；当前 Claude hook 的 `_recall` 会自动读取该列表并把原文重新放进下一轮上下文。这违背“忘记后停止自动调用，原始历史仍可主动查阅”的要求。

继续复用固定上游 `b7d9f0e0f417eae30b192882f848b432484c20a6` 的 `HyMemoryBridge.get_sdk_raw/list_sdk_raw`、SDK 权威存储，以及 Hub 的 `SourceHistory`、`UnifiedReadBridge`、治理抑制表和 `RemoteRead`。上游原文接口不读取 Hub 独立治理表，也不区分 Hub 的自动列表与显式读取，因此只修改现有 Hub 可见性判断；不增加存储、上游补丁或客户端过滤副本。

## 行为与兼容性

- `history-list` 是 Agent `recent` 和自动 hook 共用的列表入口，默认排除本项目治理表中的 forgotten 与 purged 记录，包括接纳原文和 SDK 原生 raw。
- `history-get` 仍允许有 `history:read` 权限的调用方按精确 ID 主动查阅 forgotten 原文；purged 继续返回不存在。权限、作用域、正文过滤和分页预算保持原规则。
- 记忆的 list/search/get 继续排除全部被抑制记录。其他项目的记录只受其自身权限与抑制状态约束；未忘记的原文继续可读。
- 不新增请求字段或协议版本，不改数据库格式、忘记执行范围或彻底删除语义。已有客户端连接新服务端后自动得到收紧的列表结果，无须改 hook／MCP 配置。
- 列表沿用按底层记录位置分页、随后过滤的合同；过滤后页面可以为空，`next_offset` 非空时仍可继续。此次不增加回填扫描或改变排序。
- 新客户端连接旧服务端仍受旧行为影响；本修复生效依赖服务端升级。回退服务端代码会恢复此缺陷，不得把回退后的自动召回称为已遵守忘记。已经发送给 Agent 的上下文无法撤回。

## 验收范围

复用现有真实 SDK 合成提炼、Hub 治理预览／执行和 HTTP 夹具，先证明修复前回归失败，再验证忘记完成后：列表与 `_recall` 不再包含目标接纳原文及原生 raw；按 ID 手动读取保留原文；同项目未忘记原文、另一授权项目原文和原有分页仍正常。补充 purged 的 list/get 拒绝合同，保留既有彻底删除与授权读取回归。

普通测试使用临时数据与合成模型替身，不调用外部模型。通过结果只证明本地服务端／召回函数组合，不代替 NAS 安装、真实 Claude 宿主或两机验收；实际验证结果记入测试索引。
