# ADR-0001：复用 Hy-Memory / MemHub，新增能力必须说明缺口

日期：2026-10-21

状态：**已接受的工程原则**，依据用户明确要求。具体模块引入方式仍须技术验证。

## 背景

项目要连接多设备、多 Agent，并提供原始证据、自动提炼、召回、治理和管理后台。上游已经包含 SDK、MemHub Core、来源适配、Host Bridge、管理界面和测试，不能把这些能力重新实现一遍。

## 决定

1. 以固定上游版本为复用基线，维护 [来源清单](../../upstream/manifest.json)。
2. 对已有可用实现直接使用或封装；必须修改时采用最小补丁并保留相关测试。
3. 只有明确不能满足需求的部分才新增实现，原因进入 [复用评估](../research/upstream-assessment.md) 和 PR。
4. 对协议版本、运行数据、设备身份、删除规则和备份语义的扩展不能破坏上游已有合同。
5. 引入、修改、升级分别可追踪；保留上游许可证和声明。

## 备选方案

- 从头重建记忆后端和管理界面：不采用，重复已有工作，增加维护与验证成本。
- 仅使用 SDK，其余全部新建：不作为默认路线；若具体模块无法拆分或无法满足部署边界，必须用实验和差异证明后再考虑。
- 基于 MemHub 扩展 NAS 中心与本地连接层：优先验证方向，保留已有能力和测试；跨设备边界需要实测。

## 后果

需承担上游版本跟踪、补丁维护与回归测试，但能减少重复代码。源码中存在某个模块不等于其仍在生产路径中；复用前需检查组合入口和实际测试。
