# ADR-0024：普通聊天输入证据

日期：2026-10-30。状态：实施中。关联 FR-08、FR-09、FR-10、FR-11。

## 复用和范围

复用固定上游 `b7d9f0e` 的 `pipelines/writer.py`、普通聊天 writer、消息解析／窗口／姓名行渲染、client 持久写入结果，以及 Hub 的已接纳原文和输入关系。普通聊天当前未提供实际历史输入证据；不能从最终记忆文本或查询时的当前窗口猜测来源。已有 productivity 输入快照不覆盖这条独立管线。

完整目标保持普通聊天所有实际输入的可追溯关系；最近原始对话、已有标签、合并候选、基础画像、摘要及异步图处理分别核验。先在上游实际历史选择点捕获不可变证据，再接入 Hub 原文核验和关系图。其他输入不能因为历史捕获通过而视为已覆盖，不开放选择性删除。

## 数据和兼容性

在普通聊天持久结果增加可选 `chat_history`，schema 1，包含状态、被实际使用的原始节点快照和实际渲染文本。缺字段表示旧版未观测；`not_used` 表示未进入提炼历史链路；`complete` 包括实际空历史；`unavailable` 表示未能可靠捕获。异常或预算溢出不发布部分 complete 证据，不改变原提炼行为。

捕获必须沿原解析器跟踪每条最终消息的贡献节点，包括跨节点续行和文首姓名行的独立来源，不能只截取节点列表或按内容匹配。只保存实际贡献节点，排除当前写入和被裁掉且没有贡献的节点。完整快照保存原始 ID、生产请求标记、用户／agent／session／source 和正文；生产标记本身不是 Hub 来源证明，仍须核验已接纳原文和精确产出。

原生 L1 写入实际没有生产 request_id 标记；该可选字段为空时原样保留。Hub 必须通过已有精确 raw ID 产出索引查找唯一生产原文，并核对实际内容／身份，不能把空标记解释为没有历史输入。

调用内对象持有捕获结果，512 条记录／2 MiB JSON 预算，失败只保留固定状态；不使用全局或 writer 实例上的可变“上一轮”缓存。旧 client／Hub 可忽略新增字段，旧结果不猜测回填。原模型提示和窗口行为保持原合同，不新增模型调用或持久队列。

## 架构、质量和性能自审

变化位于原数据选择点及既有结果透传，复用原存储，无新服务。以消息和节点身份跟踪，而不是重复实现第二套解析器；捕获失败只影响证据可用性。只在实际历史返回时序列化一次，预算限制额外内存，避免无界重复保存 embedding 或其他无关字段。

```text
原始节点 -> 原解析器 -> 窗口／截断／姓名行 -> 实际历史文本 -> 原 extractor
                |               |
                +-- 贡献身份 ---+-> 有界不可变快照 -> 原持久结果
                                                    |
                              Hub 原文及产出核验 <--+ [后续接线]
```

## 测试计划及未完成项

覆盖多行消息、跨节点续行、窗口裁剪、姓名独立来源、非 user 截断、当前节点排除、真实空历史、旧来源缺标记、读取异常／超限、并发隔离，以及真实 SDK 写入结果重开和幂等重放。保留上游历史和 writer 回归，运行 Hub 回归与 `make check`；安装镜像和 NAS 证据另记，不以单元测试替代。

Hub 图接线、其余普通聊天输入、删除执行、完整恢复和六入口两机验证仍属于同一产品目标。当前评审为顺序自审，不等于独立同行审查。
