# ADR-0033：原文删除后的稳定来源屏蔽

日期：2026-11-09。状态：设计已确定，实施与验证中。关联 FR-10、FR-11；补充 [ADR-0032](0032-governance-execution.md)。

## 故障证据与复用

在当前治理执行代码上，合成事件完成彻底删除、确认回执不存在、重启后，以同一 source_id/conversation_id/record_id 和新 event_id/revision 上传，返回 202 并入队，应返回 409。已有忘记测试没有覆盖“回执已删除”。原因是接纳端用回执反查屏蔽集合，彻底删除同时删除了这条对应关系。

沿用固定上游 b7d9f0e 的 Core 持久队列、SDK 删除及现有 Hub 原文校验。上游队列幂等键是 request_id，不能阻止新 event_id 的重导入；SDK 不认识 Hub 的来源三元组，因此在 Hub 补齐这一边界。复用治理记录已支持的 `source_record` 类型及带密钥摘要，不新增正文库、队列或哈希算法。

## 决策

- 独占执行区内、清除任何正文之前，从范围内 cmhe 回执校验完整事件，生成稳定来源三元组的规范 JSON（固定版本、固定字段顺序）。不包含 event_id、revision、时间、正文或凭证。
- 使用现有 journal.target(scope, source_record, canonical_identity)；实例、项目、类型隔离和 HMAC 由原实现负责。去重后的摘要直接纳入同一签名 Intent.targets，随执行计划及独立治理记录保留。物理记录 ID 仍仅存于原 suppressed 表。
- 已签名意图中的来源规则在 planned 阶段即保守生效；未落治理日志的孤立计划仍按原流程丢弃。有意图的未完成计划仍阻止 SDK 新写入。
- 设备身份和来源授权通过后、提交队列之前查询规则；命中返回 409 governance_source_suppressed。原事件的已存在回执重试仍可返回原接纳结果，不重新提炼。
- 重试响应的 suppressed_count 只统计物理记录，来源摘要不增加删除数量。治理记录与抑制行必须核对完整集合，不能只校验剩余行的签名。

## 兼容与边界

数据库列、schema_version 与治理协议均不变：source_record 是既有 TargetKind。旧记录不改写，不重新签名历史意图。

- 旧忘记操作：原文回执仍在，保留已有稳定来源反查路径。
- 旧彻底删除操作：若包含原文但没有来源摘要，无法从已删除内容可靠补齐。对应项目的新上传返回 503 governance_source_rules_unavailable；SDK 来源授权同样拒绝。读取、其他项目不受此兼容保护影响。不能用空规则假装迁移成功。恢复规则需要可证明的旧来源资料，尚未提供自动修复工具。
- 无治理操作的实验实例无需迁移。已有操作必须先停服备份；不能回退到缺少此修复的镜像并继续上传，旧代码会重新出现本缺陷。
- 本段只承诺同一稳定来源身份的禁止重导入。更换来源/会话/记录 ID 的同内容、离线规则传播、执行前已经在队列中的请求及并发接纳协调仍须后续验证与实现，不将本段计作 FR-11 全部完成。
- 用户已接受的 HNSW 未使用槽位限制保持不变。

## 验收

用真实 Hub HTTP、原生 SDK/存储及合成提炼结果验证：忘记与彻底删除后重启，原来源的新修订不能入队；无关来源记录可接纳；项目隔离；旧记录保护；规则不存原来源身份或正文；缺失抑制行被拒绝。运行 make check、相关治理/接纳测试及 Hub 全量回归；安装与 NAS 验证结果另行记录。

顺序自审，非独立同行审查。
