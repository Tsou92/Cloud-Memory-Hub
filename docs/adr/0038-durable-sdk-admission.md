# ADR-0038：可证明未进入 SDK 的任务准入

日期：2026-11-09，2026-11-10 更新。状态：持久准入、SDK 入口与治理取消／恢复已接线，本地回归和独立审查通过；安装及 NAS 验收进行中，证据见[在途执行记录](../reviews/2026-11-10-inflight-execution.md)。关联 FR-10、FR-11、ENG-01；承接 [ADR-0034](0034-inflight-ingest-and-content-reimport.md) 和[只读候选清单](../research/inflight-candidate-inventory-2026-11-09.md)。不改变已确认的产品范围或内容匹配策略。

## 问题与范围审查

当前队列与 SDK 结果库可被分别恢复。`pending`、`hy_invoked=0`、结果不存在均不能证明没有写入过；现有签名治理日志只记录 forget/purge，也不能提供该证明。仅增加执行拒绝会阻止假完成，但不能实现正常等待任务的遗忘、清除和旧队列恢复。

采用两条互补路径：新请求以正向出生登记和完整准入记录证明未许可；旧请求或已许可请求继续要求真实产出覆盖证明。后一类证据不足时保留现场，不强制取消或把拒绝当作成功。新协议须在同项目已有其他记忆时也能真正取消所选未许可任务，不能只针对空 SDK fixture。

复用固定上游 Core 的队列、worker、输入转换、状态机及结果核对；复用 Hub 治理锁、SDK 准入、签名日志、Checkpoint、独立治理目录和存储租约。新增一个持久准入组件和 SDK 调用前可选回调，不新增队列、模型调用或第二套记忆库。必要改动跨接纳、恢复和 SDK 边界，不能以减少文件数为由遗漏其中一处。

## 持久结构与真实负向证明

独立治理目录新增 `admissions.sqlite3`，使用与主治理日志不同的派生 MAC 密钥和记录类型。对既有 `GovernanceJournal` 只抽出可替换的记录模型，继续复用原有链、事务、Checkpoint、逐条验证和唯一操作索引；准入记录不伪装成 forget/purge Intent。

每个服务器随机产生的 birth UUID 为一个独立日志流。日志的 `scope_id` 在这里表示 birth；记录另存实际 `project_id`，不得拿 birth 当成项目权限。

```text
一个 birth 的完整日志流
  seq 1 ENROLLED  ->  seq 2 MAY_INVOKE
          |                  |
          |                  +-- 可能调用；禁止第二次放行，结果缺失仍保留不确定性
          +-- 完整流仍只有此项且外部见证一致 -> 可以证明从未获准调用
```

严格禁止倒序、第三项、不同出生身份的第二项及重置。两种记录采用不同域的确定性 operation_id；ENROLLED 的 ID 由实例、设备和 event 身份的 MAC 转为 UUID，借原唯一索引恢复稳定的 event→birth 映射；birth 本身随机生成，不由客户端 event_id 充当。

配置库增加签名单例 ledger_id 绑定，以及 event_key→birth_id→Checkpoint 的签名见证（birth 唯一）。主治理卷同时保存签名的 admissions_ledger_id 能力绑定，防止恢复旧配置丢掉单例见证后把新建空日志当成原日志；零事件时也不能替换准入文件。日常按 birth 验证最多两条记录，避免每次调用扫描全部历史；启动验证全部现存流和见证的相互覆盖。删除、倒退或不一致不得重新初始化为空。

准入日志先提交，外部见证后提交；均成功返回之后才允许下一步。持有同一配置库 `BEGIN IMMEDIATE` 锁完成流检查、追加及见证，复用现有锁序。调用者已经持有接纳事务时借用该连接，不能另开配置写连接自锁。崩溃造成日志领先见证时可验证并推进见证；见证领先或分叉拒绝。所有日志和所有外部见证同时回滚仍沿用 ADR-0011 的已记录限制，不新增零风险承诺。

ENROLLED 保存规范身份、过滤事件 HMAC、实际 SDK 输入 HMAC、操作种类，以及该事件既有来源／内容规则 HMAC；不保存正文、密码、来源／会话／记录 ID 明文或裸内容摘要；来源身份由事件、实际输入及来源规则的 HMAC 共同绑定。数量和条目字节预算延用有界原则。MAY_INVOKE 必须与出生登记完全相符。

## 接纳与内部身份兼容

新内部请求 ID 使用 `cmh2:<instance>:<birth>:<device>:<event>`。外部 EventEnvelope、HTTP 回执及本地 outbox 不变；项目 namespace 和 source_key 继续使用原 `cmh:`，不能全局替换前缀。

```text
验证设备、来源、过滤、幂等、已有治理规则
  -> 在独立日志登记 event / birth / 实际 SDK 输入指纹
  -> 原 Core queue.submit
  -> 原完整事件回执
```

同 event 重试复用相同 birth；同 event 不同正文拒绝。登记成功但 queue 或回执失败时保留登记，重试核对原映射，不再分配新出生域。旧已接纳 `cmh:` 回执保持旧身份，不通过再次上传或升级补造“未调用”证明。仅 HTTP 202、新数据库行或新的客户端 event UUID 都不是出生证书。

纯身份解析与原文回建支持两种内部 ID；新出生域的格式一致性不等于准入真实性，后者必须验证独立日志及见证。原文、lineage、Purger、候选观察继续复用已有校验；全局孤儿元数据审计同时识别 `cmh:` 和 `cmh2:` 请求前缀。

## SDK 入口与一次性许可

上游 `HyMemoryBridge._ingest` 的 `client.add` 与 `_ingest_extracted` 的 `client.add_extracted` 共用一个默认关闭的许可回调。必须同时注入 processing bridge factory 和 `_sdk_library_bridge` 两个构造点，不能只拦 `execute_job`。回调在已有 exclusive_access/write_lock 内、实际 SDK 调用之前执行并等待持久提交。

复用 `MemoryTaskRunner.request_for`、输入清洗和原生 imported-content 判路由计算实际 SDK 输入。桥层将最终实参构造一次，以同一份实参产生不可变描述并在许可后调用 SDK；add_extracted 的 contents 顺序、重复和完整内容都参与绑定。不能用 strip/frozenset 的结果核对集合代替实际输入，也不能让 callback await 期间的外部 list 修改改变已许可实参。

新出生请求必须匹配登记的操作与完整输入 HMAC；Hub SDK 权威路径的 source_context 为 None。旧动态上下文路径保留 legacy 行为，但不获得未许可证明。`import_sdk_*_exact`、update/delete 等独立变更入口不被描述为这两个生成门的覆盖范围，不能用它们创建伪造的新出生调用。

许可还须检查当前签名治理抑制及出生登记中的来源／内容规则，防止已取消 birth 从 seq1 首次升为 seq2。许可与治理取消沿共同准入独占和持久串行锁互斥：一方已获许可，另一方就不能再证明未许可。已有 MAY_INVOKE 固定拒绝第二次调用，不把 `append` 的幂等返回解释为新的许可；只能只读核对结果或治理恢复。

```text
生成调用 [集成验证]
  -> 构造真实调用参数
  -> 校验出生/完整两项链/外部见证/参数/现有治理规则
  -> MAY_INVOKE 日志提交 -> 外部见证提交
  -> SDK add 或 add_extracted
  -> 既有持久结果与 lineage
```

许可已提交、SDK 尚未调用时崩溃也视为“可能调用”，不得补写 NO_EFFECT。SDK 已写、结果未完成的窗口仍存在；新日志不伪造其结果。取消许可等待时，持久线程须按既有 joined-thread 合同收尾，不留下脱离调用者的许可写入。

## 真正取消、清除与恢复

沿用 `resume_lock -> quiesce 完整 worker -> SDK/接纳独占 -> 重算范围`。新执行在 plan/append 之前完成候选与证据检查，规则命中而 cmhe 未确认时要求重新预览，不能扩大物理删除范围。

对确认范围内、出生与冻结输入一致且完整日志证明未许可的任务，复用 Core 状态机真实终止；必须以 request、正文摘要、状态和更新时间做原子比较，保留 hy_invoked 原观察值，不将其重置为假阴性。unknown 只有该独立负证明成立时才允许通过受信治理 CAS 入口取消；不能把普通结果查询未找到伪装为该证明。已有 MAY_INVOKE／legacy 且产出未证实则保留原状态和正文，因为 Core 会自动清理终态正文，不能先 cancelled 再调查。

purge 仅定向清理本操作确认任务的终态正文，核对预期摘要；不能调用一次全局 reaper 后声称完成。forget 保留完整原文的主动读取，任务不再自动提炼。队列取消、抑制／清理、回读验证均完成后才能标 completed。

启动在开放 claim 前对已提交操作（含 completed）重放同一取消／清理。保留签名意图中的 cmhe 身份和出生登记，支持原文已经 purge 后仅恢复旧 queue；新观察不得改签旧范围。未提交孤立计划仍可丢弃重验。旧规则不可用的项目级封锁不能自动变成全实例启动失败，旧操作的兼容检查单独覆盖。

2026-11-10 执行接线评审补充：仅签名 cmhe(job UUID) 不能证明恢复后的同一行仍属当初那个 birth。新意图通过既有 `content` Target 的独立域，额外签入清扫策略标记和每个确认任务的 job ID／完整请求 ID／原始冻结正文 SHA-256 的 HMAC。仅日志保存 HMAC，不落裸正文摘要；状态与更新时间仍只用于当次原子比较，不签死，以支持合法取消和恢复。已经清理的严格原生 marker 提供原正文摘要，须与该签名绑定相符。不得给无此标记的旧意图补签或声称它已具备新清扫证明。

清扫先验证整个有界清单再开始取消；只有确认 cmhe 的完整出生及实际输入证明 ENROLLED 才能解除其 UNKNOWN 观察阻断。其他归属、预算、正文或规则问题仍明确拒绝。仅规则命中的未确认任务要求重新预览，不扩大删除范围。未匹配、未许可任务可保持原样，但若选择包含 native／snapshot 记录且另有未确认在途任务，负证明只覆盖过去未调用，不能证明未来输入不含所选内容；该组合在补齐输入范围证明前明确拒绝。旧／已许可非终态任务仍需完整产出覆盖证书，不能先终止再调查。

## 升级与降级保护

主治理日志显式升级到版本 2，作为独立卷中的旧镜像能力门；配置身份库升级到版本 3并建立准入绑定。仅升级配置版本不够：恢复旧 config 配合新 queue 再启动旧镜像会绕过新许可门。保留的主 journal v2 必须让这种旧启动在 SDK 之前失败。

显式停服迁移先按旧版本验证完整链，再事务更新主日志版本及 binding 签名；历史 Intent、目标 HMAC 和 Checkpoint 不重签。先创建准入日志，再将主 journal v2 和 admissions_ledger_id 能力绑定同事务提交，最后提交配置 v3；各步可重试，部分失败保留现场。主卷已绑定但准入文件缺失时不得创建替代空日志。新服务只有主日志 v2、配置 v3、准入绑定三者完整时才启用新请求域。旧镜像不能直接回退；仍使用三卷与部署配置备份、隔离升级和实际旧镜像拒绝启动验证。

## 验证计划与失败行为

| 路径 | 必须具备的实际证据 |
| --- | --- |
| 出生登记与重放 | 同 event 固定 birth；冲突拒绝；登记、入队、回执各崩溃点重启不换身份 |
| 日志与见证 | 空实例绑定、缺失、删除、倒退、分叉、seq错误、第三项均拒绝；日志领先可验证补齐 |
| SDK 生成门 | 两入口和两构造点；等待、拒绝、取消均无未获许可的调用；实际实参篡改失败 |
| 一次性许可 | 并发／重复 start 恰好一次许可；旧 pending 恢复不再次调用；许可后崩溃保留可能调用 |
| 已接纳任务 | 空 SDK 与同项目已有无关记忆都能取消未许可的确认任务，无关任务和原文保留不变 |
| 取消 CAS | 状态、请求、正文或更新时间改变时不修改现场；unknown 无证据不可终止 |
| 忘记与删除 | 原六场景保留成功目标，改验真实取消、定向清理、Drain 不调用、重启／旧 queue 无复活 |
| 有副作用与旧任务 | MAY_INVOKE、legacy、cache-only/history-only/生产力残留不能冒充无产出 |
| 升级降级 | 停服迁移与重试；旧 config＋新 queue＋保留新治理卷时实际旧镜像拒绝 |

所有失败对外返回固定原因，不回显原文。工程检查、Hub 全量、涉及的上游回归、安装镜像探针及 NAS 实测分开记录。真实外部模型质量和六客户端接续不由本变更的合成 SDK 测试替代。

性能重点为每 birth 最多两条的点查、持久提交开销、首次全量验证和并发等候；将测实际成本，不凭字节预算宣称延迟达标。已有日志类只增加记录类型扩展，默认治理行为须有原回归保护。

本变更不新做备份产品、客户端安装或管理网页；这些仍在 roadmap 中。旧／已许可请求的完整产出覆盖证书也不是本组件自动获得的能力，未证明时保持现场，但不能据此取消剩余需求或宣称完整删除恢复已完成。

SQLite 依据：[原子提交](https://www.sqlite.org/atomiccommit.html) 与 [synchronous 设置](https://www.sqlite.org/pragma.html#pragma_synchronous)。两独立库的提交不能当作一个原子事务：沿用每库同步提交，再通过完整签名链与见证修复只向前的落后状态。这里没有承诺断电硬件失效或所有副本同时回滚时仍能恢复被丢弃的证据。
