# ADR-0073 连接组件的离线读取缓存

状态：已实现（0.1.11 未发布）。日期：2026-11-18。

## 背景

连接组件通过 HTTP 读取 NAS 上的 Hub。NAS 重启、休眠、断网或 Tailscale 掉线时，所有读取都失败，Agent 只能回答「无法连接」。用户问的是已有记忆，而这些内容此前已经成功读过。

## 决定

- 连接组件把每次**成功**读取的回复写入本机状态目录的 `read-cache.sqlite3`（`~/.cloud-memory-hub/...` / 部署时指定的 state dir）。
- 缓存键是 `(instance_id, device_id, scope_id, operation, 规范化请求 JSON)` 的 SHA-256；只有完全相同的请求才会命中。换项目、换设备、换请求参数都不会串。
- 只在**传输层失败且标记为可重试**时回退：`transport_unavailable`、`remote_temporarily_unavailable` 等。权限、范围、鉴权与删除类错误（403/404/422）永远不会被缓存掩盖。
- 命中时在回复里加 `served_from_cache: true` 和 `cached_at`（ISO-8601 UTC），调用方必须把它当作可能过期的副本。
- 条目 30 天过期、最多 5000 条；写入失败或缓存文件损坏只禁用离线读取，不影响在线读取。
- 覆盖的显式读取：`memory-search`、`history-list`、`session-briefs`、`session-markdown`、`handoff-load`。**自动召回（hook）不走缓存**，仍要求在线，避免把旧内容当作本轮上下文。
- 文件权限 0600、目录 0700、明文存储。

## 未采纳

- **加密缓存**：密钥只能放在同一台机器的同一目录，防护增益有限，却增加解锁失败路径。改为明确文档与可删除。
- **写入缓存 / 离线写入**：已有本地 outbox 负责采集队列；离线写入是另一套语义，本 ADR 不涉及。
- **按操作设置不同 TTL**：当前没有证据支持；30 天统一过期，过期即不命中。

## 删除语义（重要限制）

Hub 上的「忘记」与「彻底删除」不会通知已离线的客户端缓存。已缓存的内容在本机保留到过期或手动删除，这是本机副本，不是 Hub 权威。需要立即清除时删除 `read-cache.sqlite3`；文档在《数据会去到哪里》与《接入指南》写明。

## 验证

- `apps/hub/tests/test_read_cache.py`：命中与元数据、请求/范围/操作隔离、过期、损坏文件、可重试回落、不可重试不回落、无缓存时报错。
- 自动召回保持在线路径，现有 hook 用例不改行为。
