# ADR-0063：受控三卷备份、定期执行与历史恢复

状态：接受，分步实现与验收；关联 FR-11、FR-13、ENG-01、R3-01 至 R3-03。未验收项仍为发布门槛。

## 范围和复用

固定上游 `b7d9f0e0f417eae30b192882f848b432484c20a6` 已有 `MainDatabase.back_up` 的 SQLite 一致快照、校验及私有文件发布，以及 `hy_memory.snapshot.snapshot_local_data_plane` 的停止写者后 SDK 快照。直接复用这两个原语，不另写数据库或向量存储导出。`sdk_migration_bundle` 仅包括 Core 与 SDK、不包括 Hub 权限／原文和独立治理卷，且固定写入运行 data 下的 backups，不能直接充当完整 Hub 备份；增加三卷清单和协调层。复用 `StorageLease` 排除运行进程，复用既有治理链、外部见证及启动恢复，不另建治理机制。

完整版本包含 `/data`、`/config`、`/governance` 的支持范围内持久文件，排除锁文件、已知可重建缓存与备份自身；包含模型凭证、设备凭证哈希、加密密钥及原文。因此备份目录必须私有，备份不会进入 Git、日志或无鉴权下载。默认独立 `/backups` 挂载；独立卷并不等于异机或异盘备份。用户可把此挂载放到指定位置并手动完整导出保存。

不在本次范围：热备份、云存储提供商、任意外部日志清理、旧来源不明数据的全域恢复、自动导入真实 Agent 历史。备份恢复是明确维护操作，不修改通用 MCP 合同。

## 定期执行和故障边界

容器的轻量父进程启动原有 `serve` 子进程。计划和执行状态持久化在 `/backups`，默认关闭；显式配置周期和保留数后启用。到期后发正常终止信号、等待子进程成功退出，再获取三卷租约调用快照。不能正常退出时不生成成功版本。备份结束或备份失败后重新启动原服务；收到容器停止信号时不再重启子进程。异常子进程退出由 Docker 既有重启策略处理。

```text
持久计划 -> 到期 -> 正常停止 serve -> 三卷租约 -> 暂存快照
                                     |              |
                                     |          清单/摘要/数据库校验
                                     |              |
                                     +-------- 原子发布完成版本 -> 重启 serve
停止失败/空间不足/中断 -> 固定错误码，暂存不列为成功，保留既有完成版本
```

不引入 Docker socket、不依赖宿主 cron 或 sudo。一次只执行一个维护任务；计划更新、状态写入和快照发布使用原子替换与目录同步。进程重启后读取既有计划，失败按持久下次时间重试，不能每秒无限停机。保留清理只涉及本功能已验证的完整版本，手动导出和不明文件不删除；清理失败和快照成功分别报告。

## 文件合同与导入

清单记录格式版本、备份 ID、UTC 创建时间、源码构建、实例与治理 ledger 标识、所有文件的相对路径／长度／SHA256。完整版本在校验后发布；读取拒绝缺文件、多文件、重复路径、符号／硬链接、特殊文件、越界路径、损坏清单和不支持版本。读取大文件采用流式摘要；压缩包解包在目标外的私有暂存中并限制总大小，不执行归档内容。

空目标导入三卷，保留原实例身份与备份时凭证；要求原实例已停止，以免同身份双主写入。旧快照无法自行证明其后不存在新的删除约束，灾难恢复不得宣称覆盖备份之后的治理历史。导入前后验证实例、密钥、治理链和数据格式；完成的导入仍必须经原有 Hub 启动恢复与健康检查后才称可用。

## 同实例历史回滚

备份是旧 data 与旧 config 的一致业务时间点，不能把旧 data 与整个新 config 随意拼接：新回执可能指向不存在的旧队列任务。恢复前保存当前完整保护版本，在暂存中验证同实例、同 ledger、同加密密钥和旧链是当前链的前缀。业务数据／来源／回执和模型设置恢复到选定版本；当前完整 governance、管理员凭证和加密密钥保留。

当前 `projects`、`devices`、`grants` 安全表覆盖暂存旧 access 数据库的对应表，使用一次事务及外键检查，保留当前撤销、轮换和权限。不得选择旧安全表来制造兼容。当前新增设备的旧来源可能不存在，恢复结果须明确要求重新连接来源，不自动上传或重放真实历史。安全表或签名绑定兼容性无法证明时，在替换运行数据前拒绝。

旧来源须在当前仍存在且身份／项目／适配器一致，旧来源状态与 revision 覆盖为当前值，避免来源撤销复活。当前治理 binding/floors 和准入 binding/witnesses 与当前独立治理卷一起保留并复验。旧队列未完成而当前准入已可能执行的任务不能直接再执行；此类有不确定写入的历史版本保留备份但拒绝自动回滚，不能通过清队列或重放真实内容绕过。

恢复不重命名 Docker 挂载根或替换正在持有的锁文件。替换前写入跨卷恢复未完成标记；启动入口遇到该标记保持关闭。只有全部文件校验完成才能清除标记。替换中断保留现场、保护版本与状态，不宣称原子三卷事务，不自动重试覆盖。治理恢复失败由既有启动保护保持写入和自动召回关闭。

## 工程评审和验证图

工程评审采用 plan-eng-review：已有发布计划作为范围来源；按用户已授权的自主执行，不追加逐项确认。最小新增边界是快照模块、维护入口、父进程调度和部署挂载；恢复与 UI 在前项可验证后分步接入。备份数据不做协议迁移；新格式单独编号，旧单库备份不会伪装为完整版本。

架构风险为三卷写者、旧权限复活和中断启动，分别由停止子进程加租约、当前安全表覆盖、持久恢复标记处理。代码质量要求共用快照校验器和固定错误类型，避免各 CLI 分别实现文件复制。性能以流式复制／摘要为准；完整校验会造成与数据量相关的维护窗口，记录实测而不承诺零停机。

```text
create
  + 正常非空 -> Core/SDK/三卷摘要 -> inspect 相等 [集成]
  + 运行租约/不安全路径/损坏数据库 -> 拒绝且旧版本保留 [测试]
  + 磁盘错误/中断 -> 无可选假成功版本 [注入测试]
schedule
  + 两次到期 -> 两个版本/保留数/重启计划恢复 [容器]
  + 子进程退出失败/停止信号/备份失败 -> 不假成功、不忙循环 [测试]
import/rollback
  + 完整空目标 -> 数据/来源/身份/配置核对 [隔离 NAS]
  + 旧版本+新治理+新撤销 -> 忘记不复活/旧凭证拒绝 [隔离 NAS]
  + 不兼容/损坏/中途失败 -> 拒绝或保持关闭/保护版本保留 [测试]
```

相关 pytest、上游快照回归和 `make check` 必须执行；最后使用镜像内安装代码与非空独立 NAS 卷验证两个自动版本、导出导入、历史回滚及故障恢复。定义和模拟测试不能算真机通过。

资料核对：[Docker 卷备份与恢复](https://docs.docker.com/engine/storage/volumes/)；[Debian cron 合同](https://manpages.debian.org/trixie/cron/crontab.5.en.html)。容器内协调是基于当前三卷写者和目标 NAS 权限的工程选择，并非 Docker 文档提供的应用一致性保证。

## 管理页面的有限备份 API

以下四个接口仅使用管理员身份，复用 Hub `require_admin`、有界 JSON 请求解析及既有
Origin／CSRF 边界。设备凭证不能调用。备份目录来自服务端 `CMH_BACKUP_DIR`，默认
`/backups`；请求不接受路径、命令、文件下载或恢复操作，不新增无鉴权访问能力。

| 方法与路径 | 请求 | 响应与语义 |
| --- | --- | --- |
| `GET /hub/v1/backups/status` | 无查询参数 | 200：复用 runtime.status 的计划、执行状态、下次时间与待处理请求 ID；`supervisor_running=not_checked` 不表示调度器在线 |
| `GET /hub/v1/backups/versions` | 无查询参数 | 200：`{"versions":[...]}`；有界读取清单摘要，仅返回版本 ID、`state=unverified`、创建时间、构建版本、声明文件数和声明总字节数；不表示当前文件完整或可恢复 |
| `PUT /hub/v1/backups/schedule` | 严格对象：`enabled` 为 bool，`interval_minutes` 为整数 1–525600，`keep` 为整数 1–365；拒绝额外字段 | 200：已保存计划；复用 runtime.configure，不立即触发备份 |
| `POST /hub/v1/backups/request` | 严格空对象 `{}` | 202：`status=queued`、请求 ID 与请求时间；仅调用 runtime.request_backup，不代表已启动或备份成功 |

所有同步控制文件、计划和清单摘要读取操作通过 `asyncio.to_thread` 执行，不阻塞 HTTP
事件循环。版本租约被占用时返回 503 `backup_storage_in_use`；已有未处理请求时返回 409
`backup_request_pending`，不覆盖该请求。非法请求沿用 422 `invalid_request`（请求体超限
为 413）；控制目录只读、磁盘故障或控制文件损坏返回 503 `backup_control_unavailable`，
其他版本读取故障返回 503 `backup_versions_unavailable`。响应不得带文件清单、源正文、
凭证、路径或原始异常。发生网络或落盘结果未知时客户端应重新读取状态核对，不能把
失败响应当作请求未写入的证明。

### 网页目录摘要的预算与校验边界

独立审查指出，在线程中执行全量文件摘要不能随 HTTP 取消而终止，可能持有备份租约超过
停服等待窗口。网页版本接口因此改为独立目录摘要，不调用 `store.list_backups` 全量校验。
继续复用原私有路径检查、清单格式及同一 `StorageLease`，最多读取 365 个候选版本、合计
64 MiB 清单，每份不超过既有 `MAX_MANIFEST_BYTES`；每个目录项和每 1 MiB 读取都检查
三秒协作预算，解析每份有大小上限的 JSON 前后也检查预算。单次系统调用和单次 JSON
解析不能硬中断，不将此预算描述为操作系统级绝对截止时间。错误或预算到限及时释放租约。

仅严格验证并投影 ID、带时区 UTC 时间、构建标识、非负数量和大小等清单元数据，不遍历
数据文件、不计算其摘要、不做 SQLite 或治理链验证。未知格式、重复键、损坏或变动清单
拒绝整次读取；预算到限、时间到限、非法清单分别返回 503 `backup_catalog_limit`、
`backup_catalog_timeout`、`backup_catalog_invalid`，不返回虚构空列表或逐项假定损坏。
网页显示“已生成，恢复前完整校验”，并注明列表未经重新校验。生成完成状态与当前文件
验证分开；CLI inspect、备份保留清理和恢复前的完整校验全部保持，不降低恢复安全边界。
