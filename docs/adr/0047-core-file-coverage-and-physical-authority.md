# ADR-0047：Core 文件覆盖与无请求物理授权

日期：2026-11-10。状态：四域分类、签名覆盖与停服激活已实现，本地/NAS 同镜像验收通过；无来源正文授权尚未启用。关联 FR-10、FR-11、ENG-01，接续 ADR-0046，不缩小完整运行、Docker 覆盖或客户端目标。

## 范围与复用审查

已存在两个签名执行存储、父子恢复图、精确 SDK 记录授权、只读扫描、全局预算、临时文件证明、原子替换、真实 Core 写者维护和本机完整审阅。固定上游提供真实 formatter/projector 与日志文件工厂，但没有 Hub 的治理父操作、文件授权或覆盖证据，不能直接提供本层合同。

继续使用同一文件执行器和 schema2 表结构。新增内容集中在 Core 纯分类/分帧、固定四域 profile、版本化持久证据、无请求授权和原入口接线。跨越八个既有模块是签名、扫描、恢复和确认边界必须一致的结果；不以复制第二套清理服务或省略持久兼容来缩小表面差异。当前不新增发行制品，沿已验证 Linux amd64 镜像、安装探针与 NAS 隔离流程验收。

## Core 字节分类与分帧

四个文件域为 `pipeline`、`sdk`、`core-log`、`core-diagnostic`。Core 域共享 `data/logs` 实际目录，白名单分别为 `core.log`、`diagnostic-core.jsonl` 及各自 `.1/.2/.3`；不能把同目录当成同一语义域，也不能遗漏未知文件或临时文件。

`core-log` 的完整严格 LF 行复用现有 `_strict_sdk` 闭集；`core-diagnostic` 严格 JSON 使用原 `project_core_diagnostic`，先验证时区时间戳，再做字段与类型敏感的完整等值检查，避免触发其当前时间兜底。重复键、额外字段、自由字符串、伪 marker、无效标识或不完整行不能算无正文。严格行只证明字节内容受限，不证明来源或真实日志事件边界。

纯 `CoreFramer` 仅以完整 byte-LF 严格行分隔：严格行原样保留，其余构成最大连续原字节块。输入分块方式不改变结果；所有帧串接必须逐字节还原输入。无 LF 尾部、CR、多行异常、伪时间戳及非法 UTF-8 不丢弃、不猜测事件归属；不可安全展示的正文在审阅边界拒绝。块称为物理片段，不能冒称完整逻辑事件。`details` 内嵌 JSON 保持所属物理字节，不拆成独立授权。

SDK 原有 2 MiB 单行上限不变。Core 原始块使用独立、最高 32 MiB 的预算，并受原 32 MiB 单文件／128 MiB 全局预算限制；原生 4 MiB 轮转文件不能因套用 SDK 行限制而天然不可审阅。超限拒绝整个扫描，不截断展示或拆小授权绕过限制。

## 覆盖版本与真实存储要求

- 旧 SDK `RecordGrant`、authority v1、manifest v1/v2、verification v1 的 canonical、摘要和签名保持原样；它们只证明 SDK 两域。
- manifest v3 与 verification v2显式保存固定四域 profile，禁止缺域、重复域和未知域。新 Core artifact 只能出现在四域 manifest 中；checkpoint 冻结 profile、贡献者和文件身份。
- 复用主治理日志的 capability MAC，显式绑定 `execution_file_coverage_v2=<execution store UUID>`，要求与 `execution_store_v2` 完全一致。普通读取和启动不补写。旧程序须因未知 capability 拒绝，不能忽略它后继续两域操作。
- `RecoverySnapshot` 从同一主链事务读取 required profile，Store、Binding、RecoveryGraph 共用覆盖满足判断。旧 `completed + verified` 在四域要求下仍待覆盖，不重签或重写原业务授权。
- 未来正式四域协调入口硬要求四域能力；旧备份缺项只能进入显式维护，不能自动降级。这项 capability 本身不被称作独立防回滚证书。

显式激活只提高存储要求，不能报告文件已清理。成功后旧两域回执仍可供观察，实际完成需新的全域扫描与证明。合法旧 stage 继续按旧贡献者和原保留前缀证明，不借新授权回溯扩权；全部实际 stage 证明后才能退休，随后开始新四域 pass。

`activate-file-coverage --writers-stopped` 是实际可达的停服入口。整个过程持有数据、配置和治理三个目录的租约，先只读核对主链、外部 witness、执行库绑定及恢复图，仅新增与实际执行库 UUID 绑定的覆盖 capability，再重新只读核对；不创建或迁移执行库、不补写 witness、不启动服务、不清理文件。响应只返回版本、所需 profile、执行库标识、待处理数和是否变更。合法旧库、缺执行绑定或无效证明均保持现场；后置验证失败时保留已提高要求，重试不回退或重复插入。

四域文件执行必须处于 Hub 实际组合维护窗口，不能只传 SDK 文件门闩或遗漏 Core 目录。门闩与当前线程、真实租约实例和已持有根目录绑定，在原生 Core 维护退出前撤销。空 Core 域及全严格元数据文件可完成四域覆盖；原 Core 字节保持不变。任何 Core 原始正文在完整扫描阶段返回 `diagnostic_core_authorization_required`，早于旧 stage 退休、进度写入和文件替换；不会借 SDK 授权删除 Core 正文。新 Core artifact 虽有格式定义，持久入口和恢复读取均拒绝缺少独立授权的使用。

## 无请求正文授权边界

Core 原生事件确实可以没有 SDK request ID。不能伪造请求身份，也不能用 `trace_id`、时间戳或没有发现其他项目标记来证明来源。保留独立 `PhysicalRecordGrant` 合同，不把 nullable request ID 塞入旧类型。

裸块摘要不足以授权：两个项目可分别输出相同的 `Error:\n`。物理选择必须绑定原完整文件上下文摘要/长度，以及块偏移、长度、摘要、域和真实父操作；审批视图绑定全部实际副本、实际文件身份及完整可读上下文。严格尾部追加或轮转的容许条件也必须来自该上下文，不能泛化成任意同文删除。

完整文件镜像逐字节相同仍不证明同源。已向用户询问：无来源证明的恢复副本应重新审阅，还是明确授权完整镜像的所有同字节副本。该决定只影响对应长期许可，不能借已确认的同项目内容防重导入规则推定答案。未获此授权前，无法证明来源的副本保留现场并阻止完整恢复成功；纯分类、覆盖版本与无正文路径继续实施。跨项目混合旧片段的批准同样保持原未确认边界。

## 数据流、失败与验证

```text
真实主链 + 执行库绑定 + required profile
        ↓
存储租约 / worker、SDK、Core 写者排空
        ↓
四域完整扫描 → 严格元数据保留 / 原字节候选与完整文件上下文
        ↓
完整审阅 + 明确父归属 → 新签名授权（未知范围不放行）
        ↓
原恢复图 + 全部旧 stage 证明 → 单次联合文件执行
        ↓
四域复核 + stage 缺席 + 字节守恒 → 文件覆盖回执
        ↓
另行满足业务与 Docker 覆盖后才可声明完整删除
```

验收图：

```text
原生 Core emitters
 ├─ strict text / strict Core JSON / formatter fallback → 原样保留
 ├─ 多行、嵌套JSON、伪marker、无LF、跨chunk → 原字节完整且边界稳定
 └─ 超限、自由字段、异上下文同短文 → 不误判安全、不泛化授权
签名和覆盖
 ├─ 旧canonical/旧SDK合同保持；真实四域空域与strict-only成功
 ├─ 旧verified、新cap、缺域/重复域/profile变化 → 保守pending/拒绝
 └─ 旧父+新repair、旧stage、新文件域、中断与恢复 → 无扩权、可重试
安装与实际入口
 └─ 固定源码镜像 / 旧制品拒绝新cap / 本地与NAS合成回归
```

测试使用真实 formatter、文件工厂、`DiagnosticLog.write/close`、SQLite、现有 HTTP 与文件执行流程。模块存在、内存实验或纯分类成功不能替代落盘、恢复、客户端或正式运行证据。每个新增写入路径覆盖失败前零变化、部分执行保留现场、重试和进程重启。

## 质量、性能与并行所有权

复用严格解析和文件安全原语；Core 纯分类不读配置、不调用模型、不取时钟。流式分帧只保留有界当前原始块，避免按每一输入片段重复拼接大块造成平方复杂度；文件上下文计算、回读和展示共用总预算，不设跨调用安全缓存。

分类/分帧及原生样例、存储 profile/持久兼容、审阅/授权反例分别交叉审查；协调者负责主能力与应用绑定、扫描/文件执行接线、文档和同镜像验收。接口先定再并行写，保留他人修改。未知来源的具体长期授权尚未定稿，其依赖实现不抢先启用；完整输出覆盖和可达成功路径仍是本次连续工作的目标。
