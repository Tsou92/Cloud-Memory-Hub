# ADR-0052：复用提炼流程接入 Anthropic Messages

日期：2026-11-10。状态：实现中，真实外部模型验收待完成。关联 FR-01、FR-02、FR-07、FR-14、ENG-01。

## 目的与复用证据

用户提供的生成服务仅兼容 Anthropic 协议。既有 SDK 的 `hy_memory/agent/llm_provider.py` 只实现 OpenAI 生成后端；Core 的 `model_probe.py` 已有 Messages 请求、认证头和响应文字解析，但探测入口、配置激活与网页选项尚未开放。因此仅更换地址或开放表单不能使真实提炼工作。

基于固定上游 `b7d9f0e` 及既有补丁，增加一个最小上游适配补丁。保留 HY 的提炼、JSON 解析、工具执行、限流与调用统计；在 LLMProvider 边界适配 Messages 请求和响应。复用 Core 的模型配置、加密凭证存储、探测和激活流程，以及现有管理网页；不新增代理服务、提炼引擎、队列或配置页面。向量默认继续采用镜像内置的本地 ONNX 模型。

协议依据为 [Messages API](https://platform.claude.com/docs/en/api/messages/create) 与 [API 概览](https://platform.claude.com/docs/en/api/overview)。这些文档说明标准协议，不能证明用户网关或指定模型已通过验证。

## 请求与兼容边界

`provider_kind=anthropic` 明确选择 Messages 后端，不能根据模型名猜测，也不回退到 OpenAI。生成端点使用配置根地址的 `/v1/messages`；标准认证头为 `x-api-key` 和固定兼容版本 `anthropic-version: 2023-06-01`。HTTPS、超时、禁止自动重定向与现有代理策略继续适用。个人接口地址、模型配置及凭证只保存在运行配置中，不进入源码。

SDK 统一调用合同保持不变：系统消息映射到顶层 system；普通消息、工具声明、工具调用与工具结果转换为 Anthropic 对应内容块。响应转换回原有文字、工具调用、停止原因和 token 用量合同。JSON 提炼继续沿用既有提示和解析，不向 Messages 发送 OpenAI 的 response_format 或其他专属字段。请求截断、非法工具参数、认证失败和非文本响应不能伪装成成功的提炼结果；超时及可重试错误沿既有有限重试机制处理。既有“关闭思考”选项映射为 `thinking.type=disabled`；未关闭时不主动启用思考，不发送固定 temperature。

同时修正既有生成入口 `max_retries=0` 时完全不调用模型的问题：现在表示至少执行一次，不额外重试。这一小修复同时适用于 OpenAI 后端，有独立旧协议回归覆盖。其余 OpenAI 路径保持原有行为。

模型探测复用既有能力记录，必须实际验证生成和本地向量能力才能激活。JSON 提示返回合法 JSON 不等于服务提供 schema 约束能力，能力标识须准确。保存配置不自动激活，也不绕过原有配置 revision 校验。凭证仍经 NAS 已有加密存储，接口与诊断不回显明文。

无数据库或 MCP/CLI 协议迁移；已有 OpenAI-compatible/Ollama 配置与行为保持兼容。新 Anthropic 配置回退到旧服务版本后应被明确拒绝激活，不能当作 OpenAI 执行。升级前备份现有 NAS 数据和配置，保留旧镜像；无需重置既有共享记录。

## 验收与运行边界

保留相关上游生成、模型配置、探测和网页回归，新增合成 HTTP 协议测试：文本/JSON、工具调用往返、用量、超时/限流/认证错误、密钥与错误正文不外泄，以及 OpenAI 旧合同。构建可安装镜像，在独立 NAS 临时实例验证配置与重启持久性，然后升级 MVP 实例。

真实验收须由用户在私有管理页面填写密钥，实际执行探测与激活，再从上传合成事件开始，确认提炼完成且第二台 Mac 搜索得到生成记忆。匿名请求返回认证错误只证明网络与端点可达；模拟协议通过不等于真实模型通过。

正式实例激活模型可能恢复已有等待提炼的记录；不得声称只发生一条模型调用。若需要严格单事件验收，应先使用空的独立实例。完整历史导入、其他客户端自动化和治理恢复仍按后续范围处理。

本次范围是记忆提炼与供 Agent 检索的记忆；管理网页中另一个直接生成问答的 `sdk_memory_qa` 路径尚未支持 Anthropic，不能把该入口算作已完成。
