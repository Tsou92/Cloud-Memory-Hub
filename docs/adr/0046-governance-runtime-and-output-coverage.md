# ADR-0046：正式恢复协调、可达维护与完整输出覆盖

日期：2026-11-10。状态：设计审查与分阶段实施中。关联 FR-10、FR-11、ENG-01；接续 ADR-0043/0044/0045。正式启用前须具备下列完整链路，不以某个组件通过替代产品验收。

## 范围审查与复用

复用现有两个 ExecutionStore、Authority/witness、SDK/worker 排空、SourceSuppression、Purger、主日志请求指纹、StorageLease、诊断分类/扫描/文件替换及已验证的恢复图。固定上游没有 Hub 的 signed repair、治理库 capability 或 Docker 宿主覆盖合同，不能直接由其普通治理入口补全这些语义。保留已有依赖、协议和业务删除算法，不新增数据库后端或并行删除服务。

完整路径涉及多个既有入口，不能靠仅移除 runtime_unsupported、给现有函数添加默认成功的 coverage 参数，或仅允许新空实例而取消旧恢复要求来完成。实现按所有权拆分并逐步提交；普通 schema2 运行门槛直到全部必要输出域及可达确认接通后才解除。发布设置、真实历史导入及六入口接续仍按原路线推进，不移出产品范围。

## 统一执行视图

增加薄的版本选择与验证视图，复用现有签名校验。Authority、应用抑制读取和 Executor 使用同一选择合同。无 capability 的 schema1 保持原格式；缺库且空主链保持惰性，不创建 schema2。已存在 capability 必须与真实 schema2 binding 精确匹配，缺库、错版本、错 UUID 不回退。schema2 迁移已提交而主 capability 未提交只允许显式维护续做，不放行业务启动。

每次视图读取均重新核验真实状态，不跨请求缓存已验证摘要。区分两种业务集合：抑制读取保留全部已验证普通计划，包括实际丢弃前的 orphan；恢复执行仅使用实际 committed 的业务操作。repair 不进入业务内容规则、旧任务业务证明或 Purger。原旧 purge 缺失的业务内容证明不能因为排除 repair 而被绕过。

pending 必须包含业务未完成、cleanup 未验证、orphan 和无计划主意图。结构读取不依赖临时运行故障，避免恢复自锁；领取、SDK 写许可及未经过逐记录抑制的 Core 输出继续沿 ADR-0044 阻断。健康例行核验不得抢 SDK 独占、阻断已有 worker 或反复使正常读取失败。

## 恢复与新执行的顺序

```text
真实 Authority + 统一执行视图
       ↓
worker 排空 → SDK 独占 → 诊断排空
       ↓
全业务 scope + 全部输出域覆盖前置
       ↓
单次同步 gate：全图 SDK 文件恢复 / Core 文件处理
       ↓
仅 committed 普通业务父：原业务重放/forget
       ↓
各操作真实 receipt + 各域终检 → complete
       ↓
全部资源成功退出 → 重核主链/计划/pending → 解除故障
```

新请求必须在 plan/append/取消前完成业务范围、物理确认与输出覆盖复核。业务 preview 和物理 review 分开绑定；新 grants 进入原签名 targets 与请求指纹，同 operation_id 改选择必须冲突。已提交重试按原不可变请求核验并重新扫描实际文件，不用删除后的文件状态与旧审阅视图比较。

所有 orphan 丢弃需要真实 artifact 缺席观察，不能用无 purge 时文件函数返回空 tuple 代替。修复操作只处理它的明确文件授权，不重删业务数据、不取消队列。多个主 completed 不等于本次恢复完成；任何失败、取消或资源退出失败保留故障并使重放缓存失效。

## 停服维护与审阅

在 create_hub/Uvicorn/Core lifespan 前分流状态、显式迁移、完整审阅/repair 提交及续做入口，持现有三目录 StorageLease。复用现有只读开库与迁移间隙核验，不另造签名算法；续做复用同一恢复协调器，不能要求被阻塞的普通服务先启动。

本机 TTY 可作为首个真实确认入口：安全转义、逐条完整分页，显示内容、长度、摘要、全部副本与父操作，明确整记录及同字节副本语义。正文不写诊断日志、持久审阅缓存或报告；输入结束、取消、未完成显示时不提交新授权。它是用户明确选择的载体，不声称机器证明了自由文本来源或人确实阅读。

审阅摘要绑定完整有界文件清单、文件摘要、副本数、真实父摘要、实例/ledger/store、策略、selectors 和选集；新提交在同一租约内重算。长期 RecordGrant 仍不绑定路径/inode/轮转名，已确认后同字节恢复可续做。HTTP 的孤立 body_reviewed 布尔值不构成确认，后续网页须具备实际完整展示与服务端绑定的审阅状态。

上次清理留下已登记临时文件时，审阅复用文件执行器的恢复证明：以所有真实已提交贡献者证明临时文件和正式文件的保留前缀，核对扫描未变，再展示新增候选。此步骤只读，不退休文件、不写进度、不补发授权；新候选不能追溯扩大旧临时文件权限。摘要额外绑定实际存在的临时文件身份、字节摘要与原 pass，未知文件、唯一剩余副本、冲突前缀或确认前变化均保留现场并拒绝。

repair 使用独立请求类型，复用签名 target 保存请求身份，不建第二请求表。actor 来自可信本机管理员身份；多父使用独立稳定 operation ID，全部新选择先预检再逐项 plan/append。中断留下的 orphan 不贡献文件授权。跨项目混合整记录批准仍待用户决定；已知混合或无法明确判断的记录不得借 request 相同、无关键词或一条布尔字段获得权限。这只阻塞该类批准，但同一受管日志域仍有无法覆盖正文时，也不得报告完整清理成功。

## Core 与 Docker 输出域

Core 历史文件包含 logs/core.log 与轮转、diagnostic-core.jsonl 与轮转。新 strict formatter/projector 只证明新输出策略，不能证明历史文件无正文。复用原后端及分类/文件安全算法；Core 的 RotatingFileHandler 与独立 queue/thread 需真实维护合同，不能套用只接受 SDK handler 类型的旧 gate。flush 只等待已排队任务，不等于阻止新入队；close/reset 失败必须保留现场。停服处理与在线处理分别证明真实写者边界。

Docker json-file 由 daemon 管理，应用不能直接改写其文件，也不能仅凭自己的环境变量或上传 JSON 声称宿主无残留；配置改变需要重建既有容器，见[官方驱动说明](https://docs.docker.com/engine/logging/drivers/json-file/)和[日志配置](https://docs.docker.com/engine/logging/configure/)。实际宿主维护需以明确容器 ID、daemon、挂载身份与保留日志为范围；删除旧容器日志必须先完整审阅及授权，只允许精确 stop/remove，不使用 force、prune 或删除业务卷。新运行策略和现有历史覆盖分开验证。

本轮 SSH 实测 NAS daemon 为 29.6.2，早期用户清单的 26.1.5 不代表当前宿主。已核对应 `docker-v29.6.2` 的[日志路径源码](https://github.com/moby/moby/blob/docker-v29.6.2/daemon/container/container.go#L429-L437)与[容器删除源码](https://github.com/moby/moby/blob/docker-v29.6.2/daemon/delete.go#L139-L165)：常规 json-file 位于容器根目录内，删除该目录失败会返回错误。这是宿主方案的版本证据，不是已经执行过日志清理的证明。

宿主证明必须来自真实 Docker 检查并绑定本次启动/维护的随机 challenge、实例与部署代际，旧票不能重放为新证据；宿主私有签名材料与独立记录不随 Hub 三卷备份回滚。应用不挂 Docker socket；具体宿主工具/签名接口与发行方法在实现前补充完整设计和实际 Docker 探针。此处明确的是必要信任边界，尚未实现，不能作为当前 purge 成功依据。

## 质量、测试与性能审查

已有签名、扫描、字节替换及业务删除复用；新增层只负责版本选择、操作分类与协调，避免把三个功能复制进 Authority、HTTP 和 CLI。真实测试必须覆盖：

```text
版本选择：v1 / v2 / 缺库 / 迁移间隙 / 错绑定
     ├─ 抑制：普通父仍生效、repair 不污染、orphan 保守保留
     ├─ 恢复：completed + pending、多父、多 repair、业务与文件恢复
     ├─ 失败：预检变化、取消、关闭失败、部分完成、无计划主意图
     ├─ 入口：被阻塞时停服 CLI 仍可审阅、提交与续做
     └─ 输出：真实 Core writer、实际 Docker 历史/重建/旧票拒绝
```

新增缺陷先用真实旧行为复现，再修复；使用已有合成 HTTP/SQLite/SDK/native handlers。保留旧格式读取、旧制品拒绝新能力、空启动惰性、正常读取和已许可 worker 收尾回归。正式解除门槛前运行完整 Hub、对应原生/Core 回归、工程门禁、同镜像安装和真实 NAS 隔离验证；未执行项单独记录。

视图读取一次完成 intent/records 分类，避免同一次规则检查混合多个快照；不设置跨调用安全缓存。文件扫描、正文展示和审阅清单沿既有总预算，超限无部分提交。耗时 I/O 在 joined worker 内，取消仍等待实际结束，避免持日志线程锁跨 await。

## 并行边界与失败处理

选库/业务视图及其测试、Core 输出维护及其测试、停服审阅/请求合同及其测试分别归属独立实现线；协调者负责 Executor/应用集成和设计、跨线验收。共享接口先固定，交叉审查后冻结，各线保留他人修改。

失配、未知内容、无法验证旧 artifact、宿主票过期或输出域遗漏均保留现场，不吞异常为成功。旧能力仍可使用原已验证路径；新格式的显式迁移不在普通启动时自动发生。整体目标及尚缺部件持续保留在路线图，不能把组件完成表述为 G1 完成。
