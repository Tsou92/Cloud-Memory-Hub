# 工程流程与质量门槛

状态：按用户要求建立的项目开发规范。大型项目的要求落实在可追踪变更、可复现检查与可恢复发布上；系统规模由实际负载决定。

## 1. 从需求到发布

```text
需求编号与验收场景
  -> 上游复用调查
  -> 架构／协议／数据变更评审
  -> 小步实现与相关测试
  -> CI 与差异审查
  -> 预发布环境和真实客户端验收
  -> 版本、制品、迁移与回滚演练
  -> GitHub 发布与运行验证
```

每次功能开发必须关联 [验证计划](verification.md) 中的需求编号。需求改动更新需求文档、测试计划和里程碑；不得在实现时悄悄缩减验收范围。

## 2. 复用门禁

新增模块前，必须说明：上游是否已解决同一问题、对应固定提交和源码路径、复用方式、保留的上游测试，以及新增代码的必要性。

优先顺序：直接使用已有能力 → 封装已有模块 → 最小适配补丁 → 有证据证明无法复用后重新实现。
数据模型、任务队列、权限、备份及 UI 也适用，不能只复用一个 SDK 名称却重写其余已存在能力。

与上游的差异单独维护。复制代码应保留 LICENSE、NOTICE、修改声明及版本来源，持续验证上游升级。

## 3. 开始实现的条件

- 验收行为、失败状态与范围已明确。
- 复用调查完成，并具备对应来源证据。
- 关键数据流、威胁边界和接口已记录。
- 需要迁移时提供迁移、旧数据验证及回滚策略。
- 高风险客户端能力已通过最小验证；若未通过，不能假设其可用。

普通实现选择可由开发者在已授权范围内决定；产品范围、不可逆的数据语义、许可证和公开发布设置的变化应单独记录并取得相应决定。

## 4. 变更完成的条件

- 代码、相关测试、文档和必要迁移一起提交。
- 质量检查通过；缺陷修复有回归证据，错误／重试／并发路径有相应验证。
- 安全与隐私检查通过，不提交真实用户数据。
- 产品功能需通过真实调用链；模拟测试不能替代需要真机验收的客户端行为。
- 审查记录指出完成项、未验证项、剩余风险和回滚办法。

## 5. Git 与审查

短期分支、小提交、PR 合并。合并前检查变更范围、需求映射、上游复用、测试、数据安全与兼容性。
大型改动尽量拆成可独立验证的 PR，但不通过隐藏必要配套改动来制造“小改动”。

远程仓库建立后配置：

- `main` 禁止强推和删除，要求 PR 与必需状态检查。
- 独立审查；有可用维护者时配置实际 CODEOWNERS 与审查人数。
- GitHub 私密漏洞报告、依赖更新与发布权限最小化。

这些远程设置目前尚未生效，不能由本地文件替代。初始化阶段的自审也不能标记成独立同行审查。

## 6. 测试层次

| 层次 | 目的 |
| --- | --- |
| 上游回归 | 证明复用或修改没有破坏既有合同 |
| 单元 | 纯转换、权限判断、幂等标识和冲突规则 |
| 契约 | 统一接入协议、客户端适配、格式版本与兼容性 |
| 集成 | 数据库、队列、模型适配、同步与恢复的真实组合 |
| 端到端／真机 | 六种实际入口、两台设备、已有对话更新及管理界面 |
| 质量评测 | 提炼准确性、来源可追溯性、冲突识别与错误记忆防护 |
| 性能／恢复 | 1 分钟目标、历史导入争用、断网、崩溃和备份回滚 |

覆盖率用于发现缺口，不能替代行为正确性。当前已包含工程工具、认证／凭证单元测试、真实 Core 启动集成和容器重启验证；完整产品测试随实现补齐。

## 7. 依赖与供应链

固定上游提交及依赖锁文件；CI 使用完整提交 SHA 固定第三方 Action。依赖升级独立审查，不使用浮动 `latest` 制品作为发布依据。
真实密钥从机器受控配置注入，示例配置只包含占位值。运行数据目录位于源码之外。

## 8. 发行与运维

目标制品：NAS Docker 镜像、Mac 本地连接组件及必要的 Agent 适配包。
NAS 首先验证 Linux amd64；Mac 的实际芯片架构在接入前确认，不能凭跨平台编译宣称已支持。

每个发行版本需要：版本说明、锁定依赖、许可证清单／SBOM、制品校验、安装与升级指南、健康检查、迁移前备份和回滚演练。
CI 构建与发布管线在相关制品实现阶段建立，上传 GitHub 前必须完成，不能只交付源码目录。

## 9. 当前与后续检查

当前 `make check` 验证仓库规范、脚本质量与凭证误提交。它不验证上游运行环境、Docker 制品、NAS、真实 Agent 或外部模型。
`make check-runtime` 验证固定上游和 Hub 集成；`make check-container` 构建 Linux amd64 并验证独立临时容器的认证、配置和重启持久性。运行时工作流还执行 67 项上游定向回归；这不是完整上游回归，已发现的失败项保留在[验证记录](reviews/2026-10-22-runtime.md)。

后续每一阶段在同一工作流中增加必要检查，并在 [里程碑](roadmap.md) 记录退出条件。
