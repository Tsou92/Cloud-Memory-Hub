## G1 优先顺序

2026-10-26 补充：治理运行时 `05eb169` 已停服备份后迁移到 NAS 常驻实验实例，并通过重启核验。真实 SDK 的关联探针确认默认读取会遗漏原文指针、旧版本和归档派生；现已按[范围规划设计](adr/0012-governance-scope-and-lineage.md) 接入管理员专用的[关联范围观察接口](governance-preview.md)，覆盖严格来源清单与方向性传播。它不执行删除，写入暂停协调、持久执行计划和选择性抑制仍待完成。

Claude Code 已完成[隔离原生入口与产品采集验证](reviews/2026-10-24-claude-native.md)以及[每轮在线召回](reviews/2026-10-25-claude-recall.md)，提供显式配置下的采集／读取。生成模型仍为本地替身，跨设备提炼与双向接续尚未完成。SDK 删除和恢复实测已形成[治理及离线同步方案](adr/0011-governance-authority-and-offline-sync.md)，独立治理记录及运行时绑定已通过[本地／NAS 隔离镜像验证](reviews/2026-10-25-governance-activation.md)；下一步完成关联范围、选择性抑制与执行器，G1 退出条件保持不变。

1. 在隔离环境检出已固定上游提交，使用上游要求的工具版本，运行涉及 Core、Host Bridge 和恢复流程的原有测试。
2. 证明可复用模块的实际边界，决定受控分叉／依赖方式，补全来源与许可证记录；不先复制再调查。
3. 用合成数据验证 Claude Code CLI 与 Codex 桌面已有对话的完整读写；随后补齐其他四入口的能力探针。Open Design 先核对本机产品的扩展合同。
4. 验证本地隐私过滤和多模态安全路径、历史导入队列行为、删除记录灾难恢复；原有机制能满足则直接沿用。
5. 核对 NAS 内存、CPU、磁盘和 Docker，以及两机到 NAS 的可达性；绿联转发、Tailscale、节点小宝是候选，不提前宣称任选都能支持后台服务。
6. 形成可审查的技术结论和补丁清单，再进入产品实现。

## 范围与依赖

G0 只建立工程基线；当前已按用户授权通过 SSH 在 NAS 的独立 Docker 项目中部署测试。仍不接管日常客户端设置、不导入真实私人历史、不激活收费模型或创建公开远程仓库；后续正式接入按已确认范围与具体配置推进，不因当前未执行而取消。

未来必须明确的信息：NAS 与另一台 Mac 的实际访问方式／运行环境、模型提供商和配置方式、GitHub 仓库归属／可见性及项目许可证。只有进入依赖这些信息的工作时才需要补充，不阻塞本地工程准备。

不纳入本产品：工作文件同步、跨 Agent 原生会话格式强制转换、自动第二站点备份、替用户修改原 Agent 历史或已自行保存的导出副本。
