## G1 优先顺序

1. 在隔离环境检出已固定上游提交，使用上游要求的工具版本，运行涉及 Core、Host Bridge 和恢复流程的原有测试。
2. 证明可复用模块的实际边界，决定受控分叉／依赖方式，补全来源与许可证记录；不先复制再调查。
3. 用合成数据验证 Claude Code CLI 与 Codex 桌面已有对话的完整读写；随后补齐其他四入口的能力探针。Open Design 先核对本机产品的扩展合同。
4. 验证本地隐私过滤和多模态安全路径、历史导入队列行为、删除记录灾难恢复；原有机制能满足则直接沿用。
5. 核对 NAS 内存、CPU、磁盘和 Docker，以及两机到 NAS 的可达性；绿联转发、Tailscale、节点小宝是候选，不提前宣称任选都能支持后台服务。
6. 形成可审查的技术结论和补丁清单，再进入产品实现。

## 范围与依赖

当前 G0 不接管用户客户端设置、不导入真实私人历史、不部署 NAS、不调用收费模型，也不创建公开远程仓库。后续这些工作仍属于产品交付流程，不因本阶段未执行而被取消。

未来必须明确的信息：NAS 与另一台 Mac 的实际访问方式／运行环境、模型提供商和配置方式、GitHub 仓库归属／可见性及项目许可证。只有进入依赖这些信息的工作时才需要补充，不阻塞本地工程准备。

不纳入本产品：工作文件同步、跨 Agent 原生会话格式强制转换、自动第二站点备份、替用户修改原 Agent 历史或已自行保存的导出副本。
