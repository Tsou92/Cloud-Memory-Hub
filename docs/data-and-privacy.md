# 数据会去到哪里

Cloud Memory Hub 是自托管服务。这份说明回答三个问题：数据存在哪、会自动离开 NAS 吗、以及哪些情况需要你主动操作。

## 存在你自己的 NAS 上

服务的持久数据位于 NAS 上的三个 Docker 卷，均由部署时创建的目录承载：

| 卷 | 内容 |
| --- | --- |
| `hub_data` | 记忆库、向量索引、接纳后的处理任务 |
| `hub_config` | 管理员密码、加密密钥、模型密钥（加密存储）、项目与设备授权、已接纳原文 |
| `hub_governance` | 忘记／彻底删除的意图与执行记录；不含业务正文 |

这些卷不会被上传到本项目或任何第三方。备份也留在你自己的 NAS 上，位置可配置；同一块磁盘上的副本不算异地备份。

## 什么时候内容会发给外部模型

只有在**你配置了模型服务**、并且有内容需要整理成长期记忆或你主动使用「问记忆」时，相关文本才会发送给**你填写的那个服务商**：

- 服务地址和 API Key 由你在「系统设置 → 模型」填写，密钥加密保存在 `hub_config`。
- 发送范围是本次需要整理或提问所涉及的记忆片段与原文，不包含管理员密码、设备凭证或加密密钥。
- 外部服务商的保留、日志与计费策略由其自身条款决定，本项目无法替你控制。
- 未配置模型时，Hub 仍可保存原文与任务交接，但不会自动整理长期记忆，也不会调用任何外部模型。

所有 Agent 自身的模型调用（例如 Claude Code、Codex 的对话）不受本服务影响，仍按各自原有配置发送。

## 凭证过滤

本地连接组件在上传前会过滤密码、密钥、令牌和登录 Cookie，并支持用私有文件补充已知凭证。过滤是尽力而为的规则匹配，**不能保证识别任意格式的秘密**。不要把密钥写进共享记忆。

## 谁可以读取

- 管理员：通过后台网页会话，可读写所有项目。
- 设备：只在你为它授予的项目范围内读写，权限分 `events:write`、`memory:read`、`history:read`。
- 撤销或轮换设备后，该设备的旧凭证立即失效；已注入到某个 Agent 会话里的历史上下文无法由本服务撤回。

## 忘记与彻底删除

- **忘记**：停止自动调用与再次自动提炼，原始历史仍可按记录 ID 主动查阅。
- **彻底删除**：在已有完整证明的范围内清除正文及相关副本；不受支持的记录类型会明确拒绝，而不是假装完成。

离线设备重新连接、历史重新导入或恢复旧备份，都不会让已忘记或已删除的内容自动重新生效。当前版本不提供离线读取缓存，断网时无法读取共享记忆。

## 备份与离开

- 备份包含上述三个卷，含密钥与设备配置，**必须私有保存**。
- 传输中的备份未加密；请放在只有你能访问的位置。
- 卸载前请先导出需要的备份，再删除 Docker 卷。删除卷不可逆，且会一并删除治理记录。

## 当前限制

- 未实现的功能包括：完整历史自动导入、离线读取缓存、多模态（图片／PDF／附件）解析、用量与费用统计。
- 含附件的记录目前会被明确拒绝采集，而不是丢弃附件正文后继续。
- 这是实验版本，不应作为唯一记忆存储。

具体部署、备份与恢复步骤见[运行指南](development-runtime.md)与[备份与恢复](backup-and-recovery.md)。
